## 七、还确认了、但没改的（都记了理由）

- 固件 RUN 分支 `DPH_TxApply(off)` 没被 `!ext_ctrl` 门控：加门控会让发射中的上行**完全没人
  补偿**（这个状态下 App 推的 TX 本来就写不到芯片），可能比现状更糟 → **存疑，需真机+功率计**。
- "EXT 跳过状态行守卫"：**判假**。守卫在 `doppler.c:1760`，EXT 分支在其后，agent 看反了顺序。
- 看门狗交还后备光常亮 / 键盘锁不还原：停在多普勒页就一直亮背光，人手动进来也一样，
  是既有页面行为 → **产品决策，不是 bug**。
- 在线档亚音无通路：正解是协议加字段（和 ppm 补偿同一档），不是把表里的 67.0 压掉。
- `Recorder` 线程自行退出后 `running` 不回落（麦克风一直被占、本次会话自动录音彻底废）。
- `clearStaleExt` 超时后那个迟到线程仍会发出 off，**撤销用户刚建立的接管**，而且没人发现。
- `MainScreen` 6 处 IO 线程写 Compose state，确切行号：`447 / 460 / 461 / 466 / 473 / 474`。
- `0x0768` 发完不读回包 + `drain()` 只有 1 ms + `ask` 不比对操作码 → 上一条应答会被当成
  这一条的（表现为状态行慢一帧）。
- 死页：`RadioPage`（约 1645 起）和 `DataPage`（约 1415 起）都无调用点。
- `versionName 0.1 / versionCode 1` —— 要发布就必须可追溯。
- 桥接失败后那句旧提示会一直挂在界面上（`lastMsg` 是"Activity 重建后还能显示"的设计），
  今晚"连不上电台"有一半是它造成的误判。
