## 2. 硬墙（改固件改不掉）

### 2.1 BK4819 没有 SSB

厂商特性页原文是 "half duplex TDD **FM** transceiver"，功能表只有 FM / FSK modem / CTCSS-DCS / DTMF / Selcall / VOX / 扰频，**无 SSB**
（[sunrisedigit BK4819N](http://www.sunrisedigit.com/product/70-cn.html)）。

固件里 `BK4819_AF_Type_t`（`App/driver/bk4819.h:25-43`）16 个 AF 模式里没有边带解调器：

```
BK4819_AF_FM = 1,  BK4819_AF_AM = 7,
BK4819_AF_BASEBAND2 = 5,  // 社区注释写 "USB"，实为双边带
```

无 BFO、无正交检波、无边带选择位、无载波抑制寄存器。社区实测（[HamCQ 1647](https://forum.hamcq.cn/d/1647)）：UV-K5 发出去的所谓 "SSB" 频谱是**关于载频对称的上下边带**，能被 SSB 电台解调但无载波抑制。

后果：

- **收 SSB** → 镜像边带同时进入，强信号可懂，弱信号不行；
- **发 SSB** → 变 DSB+C，带宽翻倍、功率利用率减半；
- 末级丙类谐振 PA 非线性，SSB 互调严重。

### 2.2 半双工 TDD

`REG_30` 的 `RX_DSP`(bit0) / `TX_DSP`(bit1) 互斥置位，RX/TX 经 GPIO0(`RX_ENABLE`) / GPIO1(`PA_ENABLE`) 切天线开关。**没有边收边发的模式。**

线性转发器操作**必须能听见自己的下行**（判断是否落进通带、有没有被更强信号压住），单前端做不到。

### 2.3 前端只到 ~470 MHz

芯片本身 18–660 MHz + 840–1300 MHz，但 K5 的滤波/PA 只做到 470 MHz，1260 MHz 无可用前端。

对线性星的实际影响：AO-7 Mode A（下行 29.4 MHz）理论能收不能发；**Mode B（70cm 上 / 2m 下）频段正落在能力范围内** —— 频段不是主要障碍。

参考：`BK4819_PickRXFilterPathBasedOnFrequency()` 在 28 MHz 处切 VHF/UHF LNA 路径。

## 3. 数学模型与精度要求

### 3.1 双向多普勒

符号：`u = ρ̇/c`（远离为正），`ρ̇` 斜距变化率，`B` 转发器搬移量。

非反相（`f_dn = f_up + B`，如 AO-7 Mode B）：

```
f_rx = [f_up(1-u) + B](1-u) ≈ f_dn - (f_up + f_dn)·u
```

反相（`f_dn = B - f_up`，如 FO-29 / RS-44）：

```
f_rx = [B - f_up(1-u)](1-u) ≈ f_dn - (f_dn - f_up)·u
```

一阶下 `Δ_i = f_i·u`，所以 `Δ_dn/Δ_up = f_dn/f_up` **严格成立**。
二阶项 `f·u²` 在 145.9 MHz 是 0.09 Hz、436 MHz 是 0.27 Hz，可忽略。

真正不能忽略的是**变化率** `ḟ = f·ρ̈/c`：过顶时 `ρ̈ ≈ 67 m/s²` → 32 Hz/s @145.9、**97 Hz/s @436**。

### 3.2 反相是 1:1 镜像

- 反相星：上行调 **+1 Hz** → 下行 **−1 Hz**（镜像）
- 非反相星：同向 1:1

SatPC32 的 `Doppler.SQF` 里 `REV` 参数就是这个标志位（作者 Erich Eichmann DK1TB，[AMSAT-BB 2020-12-02](https://mail.amsat.org/archives/pipermail/amsat-bb/2020-December/080435.html)）。

**不加 `inverting` 字段的后果不是差几十 Hz，是整个通带镜像。**

### 3.3 三种补偿策略的残余（800 km LEO，436.0 / 145.9）

| 策略 | 下行收听误差 | 通带内漂移 |
|---|---|---|
| 只补下行（FM 星做法） | 0 | **±9.8 kHz** |
| 只补上行 | ±3.3 kHz | 0 |
| **双向（本项目当前）** | 10–50 Hz | 10–50 Hz |

上行漂移 `D = f_up·ρ̇/c`，峰值 `±f_up·v_max/c`：436 MHz → **±9.8 kHz，占 100 kHz 通带的 9.8%（约 4 个 SSB 信道）**。
以 97 Hz/s 计，**10 秒 QSO 位置就移动近 1 kHz**。

这就是为什么线性星必须补上行，而 FM 星（SO-50）靠限幅 + AFC + 5 kHz 信道化，拨 3–4 次就行。

### 3.4 更新率

- 1 Hz 更新 → 每步约 100 Hz 跳变，SSB 可闻、CW 刺耳
- **10 Hz → 每步约 10 Hz，边缘可闻**
- ≥50 Hz 或加频率斜坡 → 听不出

平滑做法：`ρ̈` 前馈一阶外推、线性/样条插值、α-β 或 Kalman。现成软件多为零阶保持。

**本项目现在 5 Hz**（`MainScreen.kt` `delay(200)`），加上固件 `ext_prev_rx10` 斜率外推能缓解，但源头不够。

### 3.5 精度链条

AMSAT 判据：CW/SSB "**25 Hz or better**"
（WA4SCA, *Bringing the One True Rule of Doppler Tuning into the 21st Century*, AMSAT Journal Jul/Aug 2010, p.12，[PDF](https://www.amsat.org/wordpress/wp-content/uploads/2015/02/FDT-WA4SCA.pdf)）

折算时钟：

| 目标误差 | @145.9 MHz | @436 MHz |
|---|---|---|
| 25 Hz | 0.17 ppm | **0.057 ppm** |
| 5 Hz | 0.034 ppm | 0.011 ppm |

- 普通 TCXO 0.5 ppm → 73 / 218 Hz，**不达标**
- 0.1 ppm → 15 / 44 Hz，70 cm 勉强
- 实测 RS-44 需要 **8.8 kHz 校准**才能对上 → 本振没标定过

TLE 误差量级（Kelso, [CelesTrak TLE FAQ](https://celestrak.org/columns/v04n03/)）：新鲜 TLE 的 `ρ̇` 误差 1–3 m/s → 1.5–4.4 Hz @436；陈旧 3–5 天 → 15–45 Hz。

**判定**：只有 TLE + 本地时钟、无闭环测频时，最好约 **20–50 Hz** —— 够 SSB 边缘通联，70 cm 偏紧；**不标定本振则跳到 kHz 级，不可用**。

## 4. 需要改什么（分层）

### A. 硬件（改不了，只能换方案）

1. 无 SSB 调制/解调、无载波抑制、丙类 PA
2. 半双工 TDD 单前端，无法全双工
3. 前端只到 470 MHz

### B. 数据模型（可改，工作量中等）

`dph_entry_t` 现在（`App/app/doppler.h:106-118`）：

```
name[16] freq10(下行) data_off up10(上行) aos_min dur_s pts step_ms ctcss10 flags max_el
```

要加：

| 字段 | 用途 |
|---|---|
| `inverting`（1 bit，可塞进 `flags`） | 反相/非反相，决定调谐方向 |
| `bw_up10` / `bw_dn10` 或 `pass_lo`/`pass_hi` | 通带范围（AO-7 Mode B 上行 432.125–432.175） |
| `mode`（FM / SSB / CW / DSB） | 决定 UI 提示与是否需要 SSB |
| `bw_khz` | 转发器带宽（50 / 100 / 200 kHz） |

→ 表格式版本从 **v5 升到 v6**，固件 / PC / App 三端同步（`verify_layout.py` 有 23 项一致性检查会一并覆盖）。

### C. 算法与交互（可改）

1. **反相映射**：下行由上行的通带位置反推 `f_dn = B - f_up`，不能用两个独立标称点。
2. **推帧率 5 Hz → ≥10 Hz**，并加斜坡插值。
3. **通带内调谐界面**：FM 星是"选信道"，线性星是"进通带边听边微调"。
4. **本振标定**：目标 0.05 ppm 量级。前提是校准 ppm 能存住（CRC 14→12 字节 bug 已于 2026-10-30 修复）。

## 5. 三条路线

| 路线 | 内容 | 工程量 | 可用度 |
|---|---|---|---|
| **双机**（推荐） | UV-K1 只做发射端预补偿（`DPH_ExtTxApply` 已在跑），接收交 SDR / 第二台机，手机同时算两路 | 小（纯软件） | 高 |

| 换机 | IC-9700 / FT-847 / TS-2000 / SDR + 功放 | 采购 | 高 |

### 过渡方案：只收

`BASEBAND2` + IF 2.5/3.0 kHz 档 → DSB 接收，能听清强信号。可作为"先能听"的临时能力，但不要宣称支持 SSB。

### 8.3 三条对本机影响最大的推论

**1. 反相星存在一条硬规则：`f_up + f_down = 常数`。**
FO-29 是 581.800 MHz、RS-44 是 581.545 MHz。这条规则比"Δf_down = −Δf_up"更好用 —— 实现双向联动时直接守住这个和，两个 VFO 就不会分叉。

**2. 上行误差被约 3 倍放大到下行。**
435/145 ≈ 3。上行偏 +3 kHz，下行就偏 +9 kHz（JE9PEL 实测例）。所以"先补上行"不是可选项：**上行的精度要求比下行高**，和 FM 星的习惯正好相反。

**3. 表格里 8 颗 SSB 星，本项目只存了单点标称频率。**
比如 RS-44 存的是 `up=145.965 / down=435.610`，真实通带是 145.935–145.995（60 kHz）对 435.610–435.670。在通带里"往哪边站"这件事，现在表达不出来 —— 而这正是线性星操作的核心自由度。

### 8.4 既有实现都是双边补偿

- **CALSAT32 + DDE + SDR#**（JE9PEL 实测方案）：下行 `fs = −fd·(v/c)`，上行 `fs = +fu·(v/c)`，**符号相反自动处理反相**
- **SatPC32（DK1TB）+ CAT**：`Doppler.SQF` 存每星上下行基准频 + `REV` 反相标记
- **Gpredict + Hamlib**：按转发器定义分别算 up/down 并下发 CAT，支持反相标记与"仅补下行"

三者的刷新都受 CAT/串口节拍限制，实质约 1 s 级 —— 比本项目现在的 5 Hz 还粗，但它们的电台是 1 Hz 步进、且操作员手动微调兜底。
