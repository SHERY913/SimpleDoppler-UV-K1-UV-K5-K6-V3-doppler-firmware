# 第一部分 · 固件（P0 三条全部是 32 位整型溢出，已数值实证）

## F-P0-1　`DPH_TxOffset` 乘法溢出 → 435 MHz 上行的卫星发射频率固定偏 −9.8 kHz

`App/app/doppler.c:366`

```c
return (off_hz * up) / down;      /* int32 × int32，注释只验算了 145.99 MHz */
```

`up = cur.up10/100`（单位 kHz）。注释（358-360）声称"12000 × 145990 落在 int32（1.75e9 < 2.1e9）" —— 只算了 2 m 波段。阈值 = 2³¹ / up：

| 上行频率 | 溢出阈值 | off_hz 钳位 | 结论 |
|---|---|---|---|
| 145.99 MHz（145990） | 14709 Hz | ±12000 | 安全 |
| 435.15 MHz（435150） | **4935 Hz** | ±12000 | **过境中段必溢出** |
| 1260 MHz（L 波段） | **1704 Hz** | ±12000 | **全程溢出** |

实测（Python 精确复刻 int32 截断 + 向零除法）：

```
AO-73/AO-91/CAS-4（435 MHz 上行, 437.8 下行）
   off=+5000Hz   int32=-4840Hz   正确=+4969Hz   误差 -9809Hz  <== 溢出
   off=+10000Hz  int32=+129Hz    正确=+9939Hz   误差 -9810Hz  <== 溢出
   off=-12000Hz  int32=-2117Hz   正确=-11927Hz  误差 +9810Hz  <== 溢出
```

误差恒为 ∓9810 Hz，即**上行频率被整体拉歪近 10 kHz —— 对方一个字都收不到**，而发射功率、屏幕显示、亚音全对，现场无法归因。

修：

```c
return (int32_t)(((int64_t)off_hz * up) / down);
```

## F-P0-2　`DPH_ClockSec` 校准项溢出 → 开机 29.8 小时后走时校准反向

`doppler.c:262`

```c
adj = (int32_t)((int32_t)secs * clk_ppm / 1000000);
```

注释（234-236）写"先除后乘避免溢出"，**代码里并没有除**。`clk_ppm` 钳 ±20000，`secs` 自开机累计：

```
ppm=20000 (2%)
  secs=   86400  int32=   1728  正确=   1728   误差     0s
  secs=  107374  int32=   2147  正确=   2147   误差     0s   ← 临界点 29.8 h
  secs=  200000  int32=   -294  正确=   4000   误差 -4294s
  secs=  864000  int32=    100  正确=  17280   误差-17180s
```

过 29.8 小时后，校准从"补 +4000 s"变成"再减 294 s" —— 误差放大 4300 倍，且方向和大小都随秒数跳变。

修：

```c
adj = (int32_t)(((int64_t)secs * clk_ppm) / 1000000);
```

## F-P0-3　`q = (t_ms * 1000u) / cur.step_ms` 四处溢出 → 过境超 71.6 分钟全曲线崩

`doppler.c:762 / 778 / 785 / 799`（`DPH_AngleAt` / `DPH_RangeAt` / `DPH_RateAt` / `DPH_OffsetAt`）

`t_ms = elapsed * 10`，`dur_s` 上限 7200 → `t_ms` 上限 7.2e6，×1000 = 7.2e9 溢出 uint32（阈值 4 294 967 ms ≈ 71.6 min）。

```
过境  71 分钟  q=-174836     正确=21300000
过境  72 分钟  q= 125163     正确=21600000
```

即**任何长于 71.6 分钟的过境（ISS 高仰角、以及所有 dur_s>4295 的表项），后半程的仰角/距离/多普勒全是垃圾**。修：

```c
q = (t_ms / cur.step_ms) * 1000u + ((t_ms % cur.step_ms) * 1000u) / cur.step_ms;
```

## F-P1-4　ExtPush 接收侧无节流，与发射侧 1 Hz 节流不对称

`doppler.c:2878-2903` 每帧只要 `ext_rx10` 变化就 `BK4819_SetFrequency()`；注释（2873-2877）明说"5 Hz 怼芯片会怎样"，但只给发射侧（2929）加了 1 Hz 节流。App 2 Hz 推帧 + 手机在算，值每帧都在变 → PLL 每 500 ms 重锁一次，弱信号下听感是"持续沙沙声跟着数字跳"。修：接收侧同样加 `if (now - ext_tune_tick < 10u) return;`（≥100 ms）或变化 <50 Hz 不写。

## F-P1-5　`DPH_Tune`/`ExtPush` 写 `gRxVfo`，交还时只恢复 `saved_vfo` → 悄悄改掉操作员另一条信道

`doppler.c:858`、`:2892` 都写 `gRxVfo->pRX->Frequency`，而 `DPH_AudioRestore()`（911）只恢复 `saved_vfo`。双守在过境期间切换过 VFO，另一个 VFO 被写脏且永不恢复。修：两处统一写 `saved_vfo->pRX->Frequency`（`radio_saved` 为假时才用 `gRxVfo`），或污染时把指针记进集合。

## F-P1-6　不在过境页时 10 ms tick 强制 `DPH_Leave()` → 踢掉菜单、取消自动过境

`doppler.c:1410-1413`：`gScreenToDisplay != DISPLAY_DOPPLER` 且非 RUN/EXT 且无 tx_hold 时直接 `DPH_Leave()`，其内部无条件 `GUI_SelectNextDisplay(DISPLAY_MAIN)`（`ui/ui.c:114` 直接赋值 `gScreenToDisplay`）。后果：
- 用户在多普勒 READY 页按侧键进菜单看设置 → 下一拍被踢回主界面，`gIsInSubMenu`、`gInputBoxIndex` 一起被清（ui.c:100-112）；
- `phase` 被打成 `DPH_OFF`，武装中的自动过境整段作废。

修：READY 且 `auto_armed` 时应"记账不退出"（置 `ext_shown_until` 类似机制），或 `DPH_Leave` 里加 `if (gScreenToDisplay == DISPLAY_MAIN)` 才切页。

## F-P1-7　`DPH_Tune(cur.freq10)` 全程无频率范围校验（清单待办 #3 仍未修）

调用点 `doppler.c:1187 / 1216 / 1785 / 3087`；`DPH_LoadEntry`（634-641）只校验 pts/step_ms/dur_s/data_off，**不校验 `freq10`**。坏表项 → `BK4819_SetFrequency(0)` 或越界 → 芯片行为未定义。修：`DPH_LoadEntry` 加 `if (freq10 < 1000000u || freq10 > 1300000000u) return false;`（29–1300 MHz）。

## F-P1-8　ExtPush 名称帧长边界：8 字符名被砍成 7 字符

`doppler.c:2867`：`if ((uint8_t)(21u + nameLen) > len) nameLen = (uint8_t)(len - 21u);` —— App/PC 侧 `21 + 8 = 29`，而固件侧最小可接受 `len = 28`，此时 `nameLen` 被压到 7，名字末字丢失且不报错。修：把最小长度判据提到 29，或按 `nameLen = min(nameLen, len - 21)` 且允许 nameLen 上限 8。

## F-P1-9　未对时的机器整页没有倒计时

`doppler.c:294-326` 无 RTC 时 `clk_days` 恒 0，`DPH_AosLeft`（478）要求 `clk_days != 0` → 显示 `--:--`。表头 `hdr.date` 可以兜底：`clk_days == 0` 时用 `hdr.date` 推当日序号。修：加 fallback 分支。

## F-P1-10　EXT 看门狗在发射中强断载波

`doppler.c:1339-1355`：`silent > 500`（5 s）且 `FUNCTION_TRANSMIT` → `DPH_ExtStopTx()`。App 在发射瞬间 USB 与 BK4819 SPI 抢总线导致两次推帧超时即触发，"一按 PTT 就掉载波"。需与 App 节拍对齐（App 侧 `RadioLink.ask` 3 s 超时 + 重试），或发射中把门限放宽到 15 s。

## F-P1-11　`DPH_EditClock` 年份取自表头 → 空表时按键对时把日期设成 2000 年（清单待办 #5 仍在）

`doppler.c:1006` 用 `(hdr.date >> 9) & 0x7F` 取当前年份，但 `hdr` 只在写过表之后才有意义：全新机器/擦过表的机器该字段为 0 → 用户在时钟页按键对时，日期被设成 **2000-xx-xx**，`clk_days` 差 26 年，`DPH_FindNext` 排出来的过境全部落在 26 年后。`doppler.c:999` 才查 `edit_len`，此时脏值已经读进输入框；`:1010` 附近只校验 `dd <= 31`，接受 `02-31`。

**实测路径**：擦表 → 重启 → 进时钟页 → 按 MENU → 输入合法 HHMMSS → 保存 → `DPH_DayNow()` 返回 2000 年对应的日数。

修：年份从 `DPH_DayNow()` 反推（`DPH_Days` 的逆运算），并加当月天数表（含闰年）校验；`hdr` 未加载时把年份字段当"未知"处理。

## F-P1-12　ppm 保存侧不钳位（清单待办 #1 的另一半）

`doppler.c:341` `DPH_SaveCal` 直接 `clk_ppm = ppm`，钳位只在使用侧（`:257-260` 钳 ±20000）。校准页能存进 ±99999，之后 `DPH_ClockSec` 的乘法更容易溢出（见 F-P0-2）。修：保存时同钳 `±20000`，并把乘法改 `int64_t` —— 两处都要改，只改一边仍会溢出。

4. **固件校准会话放弃后残留 `cal_run`**（U-F-15/U-F-16）—— 隔几小时误按两个键就能把错误 ppm 写进 flash。
5. **安卓「手机接管」跳到详情页且那页没有停止控频**（U-A-16）—— 用户进了接管却找不到出口。

# 第八部分 · 两套逻辑的频率 / 节拍 / 显示一致性对照

第一套 = 机上手按 M 进过境页、固件自己按过境表算多普勒。
第二套 = 手机接管（0x0768 + 0x076E），固件只听手机推来的帧。

## A. 节拍对照（这一节全是实测/实读）

| 项目 | 第一套（固件自算） | 第二套（手机推帧） |
|---|---|---|
| 多普勒重算 | 每 10 ms 一次（`doppler.c:1548`） | 手机每 **200 ms** 一次（`MainScreen.kt:439` 的 `delay(200)`） |
| 落 PLL 的频率 | 每 10 ms 试写，`DPH_Tune` 的去重使它变成"每变化 10 Hz 写一次"（437 MHz 上多普勒率峰值约 75 Hz/s、均值约 34 Hz/s → 峰值约 0.13 s 写一次，均值约 0.3 s 一次） | **每帧都写**（`doppler.c:2894`，只要值变了），5 Hz 推帧 → 约每 200 ms 一次 PLL 重锁 |

| 频率量化 | 10 Hz（`off/10` 整米除） | 10 Hz（App 端 `Math.round(/10)`，`MainScreen.kt:395`） |
| 显示来源 | 固件插值表 | 手机算好整帧推来 |

## D. 性能浪费（按"能省多少 SPI/CPU"排序）

| 编号 | 浪费点 | 量化 | 建议 |
|---|---|---|---|
| P-1 | RUN 页 20 Hz 全屏重画，12 项里只有 `$D`（RSSI）需要 >2 Hz；`$S/$N/$T/$W/$U/$B/$M` 七项**整个过境是常量**却每帧重算重画 | 每帧 12 次 `vsnprintf` + 字模逐像素写 + 1024 B framebuffer + 逐行 `memcmp`；20 Hz → 每秒 240 次格式化 | 页内做"上次值缓存"，常量项跳过；整页降到 5 Hz，RSSI 单独 5 Hz |
| P-2 | `ui_div` 一套变量服务三种节拍（5/50/100） | 模式切换时残留值让首帧最多晚 1 s | 三个独立计数器 |
| P-3 | 同一帧内 `DPH_*At(elapsed*10)` 被调 4 次（`$E/$G/$H/$O`），每次重做 `t_ms*1000/step_ms` 软件除法（M0 无硬件除法） | 20 Hz × 4 = 80 次/s | 每帧算一次 `q`，四个函数复用 |
| P-4 | ~~第二套接收路径每帧写 PLL~~ **实测非瓶颈** | 单次写频率只是几个 SPI 寄存器，微秒级；5 Hz 下 CPU 占用可忽略 | 与 T-3 一起更正：不需要改 |
| P-5 | App 侧每帧 `new Thread` 去抢 `@Synchronized` 的 `ask` | 5 Hz × 每次一个线程对象 + `join` | 单线程执行器 + 只保留最新帧（已在前文 P1） |

## E. 这两套里做对了的地方（不必再动）

- 第一套 `$F` 取的是 `gRxVfo->pRX->Frequency`（`doppler.c:2256-2257`），**报的永远是芯片真实站住的频点**，不是计算值。
- 第二套由**固件自己**写 `BK4819_SetFrequency(ext_rx10)`（`:2902`），App 不再直接怼 REG_38/39，芯片状态机不被绕过。
- `last_freq` 在三条写入路径（`DPH_Tune` / ExtPush 接收 / ExtPush 发射）之间**同步**（`:2901`、`:2933`），交还时不会被缓存骗过。
- 发射中 `$F` 固定显示接收频率，不跟着跳到上行（`:2248-2255` 的注释与实现一致）。
- 第二套只在内容真的变化时才重画（`:2943`），心跳帧不刷屏。
- 两套的上行修正都锁在 1 s 节流上，避免 PLL 相位扰动变成对方的"咔哒"声。

# 第十部分 · 真机联调实测（2026-10-27 凌晨，MuMu + COM7 桥接）

## 10.1 链路是怎么打通的

MuMu 12 没有 Android USB host 透传（`dumpsys usb` 恒为 `num_connects=0`，容器内无 `/dev/ttyUSB*`），
App 的「USB 连接」在模拟器里永远拿不到设备。真正可用的是作者已经写好的另一条路：

```
电台 USB → 宿主机 COM7 → 多普勒工具/serial_bridge.py --port COM7 --listen 7878
         → adb reverse tcp:7878 tcp:7878 → 模拟器内 App 的「网络桥」
```

`adb reverse` 把模拟器里的 `127.0.0.1:7878` 转到宿主机，App 走 `RadioSession.connectNet()`，
协议层与 USB 完全一致，只是传输换成 TCP。实测延迟 1~3 ms，不影响 5 Hz 推帧。

> 结论：**Windows 上的模拟器（MuMu/雷电/BlueStacks/WSA）都做不到 USB 直连**，
> 能做的只有 Linux 主机 + AVD、Genymotion 商业版。本项目不需要——桥接这条路本来就在设计里。

## 10.2 实测结果（全部真机，非仿真）

| # | 项目 | 结果 |
|---|---|---|
| 1 | 桥接连通 | 「网络已连通 127.0.0.1:7878（固件有回包）」 |
| 2 | 固件自检 `0x076A` | `proto 6 · 表已加载（phase 1）` |
| 3 | 过境表读取 `0x0764` | `表 v5 · 2 条过境`（写前） |
| 4 | **写表** `0x0760`+`0x0762`+读回 | **49116 B / 12 扇区 / 35.6 s**，写完读回 `表 v5 · 21 条过境` |
| 5 | 接管控频 `0x0768`+`0x076C` | `手机控频 · 电台受控`，收 145.80283 MHz（+2825 Hz），界面每秒刷新 |

## 10.3 本轮实测中发现并已修掉的问题

### A-新1（已修）状态行残留上一次的掉线文案

# 第十一部分 · 致命 BUG：多普勒与主信道互相踩（2026-10-27 修复）

## 11.1 现象与根因

你报的现象：**开始多普勒后，页面上的接收频率变成主界面的主信道频率，而且主信道的频率真被改了。**

这不是一处 bug，是三条独立路径共享了同一份 VFO 状态。任何一条都能单独把电台搞乱，三条同时存在所以必现。

### 路径 1：多普勒直接写主信道的 VFO 结构体

`doppler.c` 的 `DPH_SaveRadio()` 里 `saved_vfo = gRxVfo`，而 `gRxVfo` 就是
`&gEeprom.VfoInfo[gEeprom.RX_VFO]`（`radio.c:781`）—— **指向操作员主信道那个结构体本身，不是副本**。
`DPH_Tune()` 又写 `saved_vfo->pRX->Frequency = freq`（旧 `doppler.c:895`）。

于是：多普勒调谐 = 改主信道。页面 `$F` 读的也是 `gRxVfo->pRX->Frequency`，
所以"显示成主信道频率"和"主信道被改"其实是同一件事的两面——两边是同一个变量。

### 路径 2：固件定时把指针拉回主信道，并把多普勒频率冲掉

`app.c:2846-2872`（`APP_TimeSlice10ms`）在 `gVfoConfigureMode != NONE` 或
`gFlagReconfigureVfos` 时做三件事：

1. `RADIO_ConfigureChannel(0/1,…)` —— 按信道数据**重填** `pRX->Frequency`；
2. `RADIO_SelectVfos()` —— 把 `gRxVfo` 重新指回 `gEeprom.VfoInfo[RX_VFO]`；
3. `RADIO_SetupRegisters(true)` —— `radio.c:855` 拿主信道频点去点芯片。

而 `DPH_Tune()` 有 `if (freq == last_freq) return;` 缓存，`last_freq` 里还记着
卫星频点 —— 芯片被点到主信道之后，多普勒**再也不会**把它改回来（判定"频率没变"）。
这就是"忽然跳回主信道而且再也回不来"的完整机制。

### 路径 3：省电与双守会在多普勒页换台

- `HandlePowerSave()`（`app.c:1625`）每 500 ms 走 `DualwatchAlternate()`
  （`app.c:1099-1106`、`app.c:1687`），`FullWatchAlternate()` 直接写
  `gRxVfo = &gEeprom.VfoInfo[...]` 或 `gFullWatchBackgroundVfo[]`；同一段里还有
  `BK4819_Sleep()` 把芯片睡掉。三件事都不判断"当前是不是多普勒页"。
- `APP_StartListening()` → `FullWatchPromoteCurrentBackground()`（`app.c:1054`）
  在**每收到一次信号**时把 `gRxVfo` 换成另一个 VFO。

**这就是你说的"主信道突然有人说话，多普勒就出问题"**——不是"有人说话"这件事本身，
而是"收到信号"会触发一次全双守提权，把 VFO 指针从卫星那边拽走。

## 11.2 修法：借副本，不借主信道

| # | 改动 | 位置 | 作用 |
|---|---|---|---|
| 1 | 新增私有 `VFO_Info_t dph_vfo`，`DPH_SaveRadio()` 时整份拷贝并**重指 pRX/pTX 到副本内部**，再把 `gRxVfo/gTxVfo/gCurrentVfo` 全指到副本 | `doppler.c:117-122`、`doppler.c:928-948` | 主信道 `gEeprom.VfoInfo[]` 从头到尾一个字节都不再被写 |
| 2 | `DPH_Tune()` 改写 `dph_vfo.pRX->Frequency` | `doppler.c:893-899` | 调谐只动副本 |
| 3 | 新增 `DPH_GuardVfo()`，每个 10 ms tick 开头调用 | `doppler.c:951-970`、`doppler.c:1400` | 任何人把指针抢走，下一拍抢回来并强制重写芯片、清 `last_freq` |
| 4 | `DPH_AudioRestore()` 先把 `gRxVfo/gTxVfo/gCurrentVfo` 还原成原指针，再谈频率 | `doppler.c:993-1000` | 交还时干净收场；`orig_*` 的还原变成幂等保险 |
| 5 | `HandlePowerSave()` 开头判 `DOPPLER_IsActive()` 直接跳过省电/双守/睡眠 | `app.c:1625-1637` | 多普勒页不再被换台、不再被 `BK4819_Sleep()` 睡掉 |
| 6 | `FullWatchPromoteCurrentBackground()` 判 `DOPPLER_IsActive()` | `app.c:1054-1070` | "收到信号就提权换 VFO"这条路对多普勒页关闭 |
| 7 | `DualwatchAlternate()` 调用点判 `!DOPPLER_IsActive()` | `app.c:1556-1578` | 双守换台另一条入口同样封掉 |

修完之后的语义：**多普勒从"借用主信道"变成"借一份副本"**。主界面显示它自己的信道，
多普勒页显示它自己的卫星频点，两个互不可见、互不可写；退出时把指针一还，主信道毫发无损。
