## 六、本轮（22:00–22:47）改了什么

### App 0.5 —— 控频期间进程不被冻
`KeepAlive.kt`：接管时 `startForegroundService` + `PARTIAL_WAKE_LOCK`（10 分钟上限），
通知渠道 `doppler_ctrl` / id 1001 / `foregroundServiceType="specialUse"`；
服务自带 3 s 看门狗（`CtrlState.takeover` 为假即 `stopSelf()`），
`KeepAlive.stop()` 同时发 `ACTION_STOP` 与 `stopService`。
证据：`isForeground=true foregroundId=1001 types=0x40000000`、`WAKE_LOCK 'doppler:ctrl' ACQ`，
熄屏 60 s 后仍"接管中"且频点在走。**A/B 在 MuMu 上无效**（仿真器不进 Doze）。

### App 0.6 —— 过境表的时间轴
结论先说：**表算法一直是对的（≤6 Hz），错的是"表说的第几秒"**。
`PassCalc.kt` 三处：AOS 由"向下取整"改四舍五入到偶数秒、采样起点跟着表头一起挪、
`Pass.aosMs = baseAos`。表格没动，固件不用改。

| 项 | 145.8 MHz | 435.8 MHz |
|---|---|---|
| 旧（AOS 向下取整、采样从真 AOS 起） | 中位 −45.4 Hz、max 52.1 | 中位 −146.4 Hz、max 152.2 |
| 0.6（四舍五入、采样同原点） | 中位 −0.2、max 6.0 | 中位 −1.2、max 7.2 |
| 电台时钟慢 1 s / 15 s | 40 / 531 Hz | 109 / 1579 Hz |

同时加**自动对时**：链路一就绪 `0x0766`（假电台抓到实证：连上后第 4 条命令就是它），
之后每 5 分钟一次，不再指望用户记得点按钮。

### App 0.7 —— 追踪页崩溃的真凶 + 撤掉强制横屏
用户实机栈（V1936A / Android 11）：
```
java.lang.IllegalStateException: Offset is unspecified
  at AndroidCanvas.drawLine
  at com.f4hwn.doppler.SkyViewKt.SkyView$lambda$15$lambda$14(SkyView.kt:175)
```
`SkyView` 第 175 行画"卫星方位那条红短线"，坐标是 NaN。来源：`satAz ← live.az ←
Geo.look ← SGP4`。SGP4 在偏心轨道退化 / TLE 外推太远时会给出 NaN，NaN 进 `Offset`
后 Compose **在绘制阶段**抛异常 —— 所以仿真器（数据正常）永远复现不出来。

两头都堵：
- 源头 `MainScreen` tick：方位/仰角/距离/变化率任一非有限 → 不更新 `live`，
  改标 `ok=false` + "轨道解算失败（TLE 外推太远？）"；
- 绘制 `SkyView`：入口 `isFinite` 兜底四个入参、`R<=0` 直接 `return@Canvas`、
  过境轨迹逐点跳过非法值。

**0.6 里那个"锁横屏"是我判断错了**（用户直接问"为啥 APP 是横屏"）：0.7 删掉
`android:screenOrientation`，竖屏下详情页"收 x / 发 y"改成可压缩权重 + 最多两行右对齐。
竖屏 1080x1920 逐页实拍：列表 / 详情 / 追踪都正常。

### 固件（`819a3ad`，未烧进用户手上的电台）
- `uart.c` 新增 `case 0x0770` → 回 `0x0771 { uint32 Rx10 }`（当前接收频率，10 Hz 单位）。
  **故意不往 `0x076B` 里加字段**：老 App 的 `fwInfo` 是 `expect=7`，加长会让它判
  "回包长度不合理"，而版本号只在那条里、对不上没退路。
- `doppler.c` 断帧斜率外推（抄星来 `:556-601`，闸门更严）：`gap∈[30,200]` 拍、
  `span∈[10,500]` 拍、`|Δ|>100 kHz` 判换星不推、发射中不动、节流 100 ms。

## 八、踩过的坑（省下一次重来时的时间）

**环境**
- `adb` 用 MuMu 自带的 `/c/Program Files/Netease/MuMu/nx_main/adb.exe`，且必须
  `-s 127.0.0.1:16384`；`tc/sdk/platform-tools/adb.exe` 起不来 server。
- Git Bash 里 `taskkill //PID` 会失败（只回用法）；杀进程用
  `powershell -NoProfile -Command "Stop-Process -Id N -Force"`。
- `netstat | grep :7878 | head -2` 会先命中 TIME_WAIT，要 `grep -i listen`。
- MuMu 的 `uiautomator` 会 SIGSEGV，抓 UI 一律 `screencap`；`input tap` 坐标 =
  **实际截图坐标**，聊天里看到的预览是缩放过的（1708x961 ↔ 1920x1080，**×1.124**）。

**构建**
- 同源码增量构建 APK 会抖 200+ KB（D8 分包）；交付前必 `clean`。
- `AndroidManifest.xml` 里注释**不能写在属性中间**（我这么干过，报
  `ManifestMerger2$MergeFailureException: Error parsing ...`）。
- 提交信息别用 `-m "…$变量…"`，会被 bash 先展开；写文件 + `-F`。

**固件/协议**
- `0x07xx` 回包 `body[0..1]` 恒等于 `cmd+1`（回显），App 现在会校验，错了就抛
  "回包串了"。所以别在固件里"顺手"改回显字节。
- `0x0768` 裸发会被 `doppler.c:1747` 那段"接管了却没开页"的防呆在下一拍收回 ——
  **必须先 `0x076E=1` 再 `0x0768=1`**（探针实测：只发 `0x0768` 时 state 立刻回 0，
  先开页则稳定 15）。
- `0x0769/0x076D/0x076F` 三条同为 5 B、只差回显，从前 App 不校验 → 稳态永久 −1 帧。
- 别给高频数据帧加"每帧应答"：星来用 `0x05F7` 不应答省一半流量，我们 `0x076C`
  每帧回 `0x076D` 是 5 Hz × 双份。

**App/UI**
- Compose 的 `drawLine/drawPath` 收到 NaN 的 `Offset` 会在**绘制阶段**抛
  `IllegalStateException: Offset is unspecified` —— 任何来自数值计算（SGP4/传感器/
  JSON）的浮点值，进 Canvas 前都要 `isFinite` 兜底。
- 长在最里面的 `RadioPage()` 死页曾"承接"了自动重连、USB 插入自动连、诊断区三块能力，
  删它的时候一定要把这三块搬出来（已搬：会话级 `LaunchedEffect` + 设置页诊断区）。
- `RadioSession.lastMsg` 这类"最近一条状态"必须带时间戳再上屏，否则用户看到的
  "接管中"可能是两分钟前的。
