## 一、为什么改：上一版的产品是"死的"

先说结论，因为这一轮的动因是它：

- `多普勒/PC工具/多普勒工具/doppler_core.py:73` 原来写
  `FLASH_VOICE_PACK = (0x102000, 0x095000)`（= `0x102000..0x197000`）。
- 表区在 `0x162000`，**正落在这个"别人的地盘"里**。
- `guard()`（`doppler_core.py:828`）对三块禁区一律判"不许重叠"，于是表区自己的
  每个地址都被自己拒掉：`guard(0x162000, 4096)` 抛
  `拒绝写入：与固件/APP/语音包区 0x102000 重叠`。
- 调用点 `doppler_tool.py:1538-1542` 在"确定现在写入吗"弹窗**之前**、且**不在
  try 里** → `ValueError` 抛进 Tk 回调 → 窗口程序里没有地方印 traceback →
  现场表现就是**"点写入电台，毫无反应，一个字节没写"**。
- 而九层回归全绿，因为 `verify_table_fit.py:309-318` 只测了"guard 拦得住禁区"，
  **从来没测"guard 放得行表区"**。只测拦截不测放行，这条回归永远抓不到它。

修法（本轮已做）：
1. 禁区拆成表区两侧两段：`FLASH_VOICE_HEAD`（`0x102000..0x162000`）+
   `FLASH_VOICE_TAIL`（`0x172000..0x197000`），表区本身不属于任何禁区。
2. 补正向用例：`verify_table_fit.py` 现在逐个断言 **表区 16 个扇区全部过
   `guard()`**，并断言 `erase_plan()` 的每个扇区也过。
3. `write_radio()` 里 guard 那几行包进 try，万一以后再有人把禁区写歪，
   至少能看见一句话而不是静默。

## 二、占地事实（本轮用真镜像复核，不再引用文档口径）

| 地址 | 原厂镜像（`全满.bin` / `无多系统.bin`） | 汉化包（`汉化-02-external-flash.bin`） |
|---|---|---|
| `0x102000..0x11C000` | 13 个 FAP1 应用 | 40 个 FAP1 应用（到 `0x151A5C`） |
| `0x11C000..0x162000` | 存活语音 280 KiB | 汉化应用尾 + 空白 |
| **`0x162000..0x172000`** | **A-law 语音包中段（熵 7.89，无文件头）** | **全 0xFF（0/65,536 非 FF）** |
| `0x172000..0x180000` | A-law 语音包 | **全 0xFF（0/57,344 非 FF）** |
| `0x180000..0x1D6300` | 语音尾 + 空白 | 16×16 字库 / 8×8 字库 / 拼音表 |
| `0x1DE000` 起 | 空白 | 空白（Sonic 4K 互操作保留区） |

- `0x162000` 为什么不是魔数：`App/apps/app_overlay.h:65-70` 的
  `APP_REGION_BASE 0x102000` + `APP_SLOT_STRIDE 0x2000` × `APP_SLOT_COUNT 48`
  → `APP_SLOT_BASE(48) = 0x162000`。表区起点正好是**最后一个 app 槽
  （slot 47 = `0x160000..0x162000`）的结束地址**，不压任何槽。
- **原厂机器上这块地被语音包占着**。用户决定：那段语音放弃（表区密度优先）。
  代价是"第一次在原厂机上装表会被固件的防呆拦住"，所以本轮加了 0x0776。
- 上一版文档里"`0x16A000..0x180000` 88 KiB 实测空白"是**错的**：原厂镜像是语音，
  汉化包才空白。现在只敢写实测数字。

| `DPH_UNLOCK_CREDITS` | — | **64** | 同上 |

| `DPH_STEP_MS_MIN` | `10000` | **`5000`** | `doppler_core.py:45` |

| `PassCalc.STEP_MS_MIN` | `10000` | **`5000`** | 同上 |

容量算式（三端同一个 +1 修正）：

```
16（表头）+ 30 ×（40 + floor(1500/5)+1 = 301 × 6）
= 16 + 30 × 1,846 = 55,396 B
+ 4,096（DPH_SAMPLE_OFF）= 59,492 B ≤ 65,536 B，余 6,044 B
```

**`+1` 是这一轮修的第二个真 bug**：样点数是 `floor(dur/step)+1`
（0, 5, …, 1500 是 301 个点），旧算式少算一个点。两边一起少算 180 B，
所以"断言成立、回归全绿"，但真实余量比以为的少。现在
`doppler.c` 的 `_Static_assert`、`doppler_core._CAP`、
`verify_table_fit.check_capacity`、`check_firmware` 四处都带 `+1u`。

精度（`verify_table_fit` 实跑 ISS 单向过境）：

| 栅格 | 最大插值偏差 | 对比 |
|---|---|---|
| 1 s（真值） | 0.5 Hz | — |
| 5 s | 1.2 Hz | 比 76 ppm 失谐（33 kHz）小 26,948 倍 |
| 10 s（默认） | 1.2 Hz | 比 NFM 2.5 kHz 信道小 2,000 倍 |

所以"5 s 下限"不是为了精度，是为了**让 64 KiB 有密度可换**；默认仍 10 s。

## 四、新增 VCP 命令：`0x0776` → `0x0777`（受控清地）

原厂机器上表区是语音包，固件 `DPH_TableErase` 判 `DPH_SECTOR_FOREIGN` →
返回 `DPH_TBL_OCCUPIED`(4)。这是**设计**（保住别人的数据）。但"主人决定在这里
装表"固件无从推断，必须由人宣告一次。

```
PC → 电台  0x0776  Token(u32) = 0x31555044 ("DPU1" 小端)
电台 → PC  0x0777  Token(u32) 原样回显 + Credits(u8) 剩余额度
```

- 令牌对 → 借出 64 次擦除额度；令牌错 / 长度不足 → 回显收到的令牌 + `Credits=0`。
- **额度只在 RAM 里，掉电清零**：每次上电都要重新解锁，不搞"开一次永久畅通"。
- 额度按次扣，`FOREIGN` 判定照样逐扇区做；扣到 0 就回到"一律拒绝"。
- 它不是安全边界（能发 VCP 帧的人本来就能擦 flash），挡的是误帧、串口噪声和
  "忘了自己发过什么"的旧工具。

实现：`doppler.c` 的 `dph_unlock_credits` / `DPH_UnlockRegion()` /
`DPH_UnlockCredits()`，擦除闸门里只在判 `foreign` 时扣一次；
`uart.c` 的 `case 0x0776`。

### PC 侧怎么用

1. **写表按钮左边多了一个勾选框「允许清空被占的表区」**（默认不勾）。
2. 先探测表区归属（512 B 一帧读满 64 KiB，128 次往返，16 秒上下）：
   - 表头是 `DPT1` → 自己的旧表，直接写；
   - 全 FF → 新片，直接写；
   - 别人占着 + 没勾 → **一个字节不动地退出**，提示勾上或先跑 `clear_table.py --yes`；
   - 别人占着 + 勾了 → 发 `0x0776` 借额度，借不到就退出（老固件不支持）。
3. `clear_table.py` 的 `--yes` 现在也先发 `0x0776`：借不到就明说"先刷新固件"，
   不再让人对着 `code=4` 猜。

App 侧暂时没有 0x0776 的入口，所以**手机上首次给原厂机器装表会被拒** ——
先用 PC 工具清一次即可（这条已写进 `PassCalc.kt` 的注释）。

## 七、烧机流程（这一版）

1. 刷 `交付/f4hwn.sstv.doppler.bin`（104,288 B，md5 `b48ffb57…`）。
2. **原厂机器/表头不是 DPT1 的机器**：两种走法，任选其一
   - PC 工具勾上「允许清空被占的表区」→ 点写入电台 → 确认；
   - 或 `python 多普勒/PC工具/多普勒工具/clear_table.py COM7 --yes`（会先 0x0776 解锁）。
3. 采样间隔填 **10.0**（下限 5 s 已放开，但默认口径仍是 10 s）。
4. 写完电台当场会 `DOPPLER_ReloadTable()`，不用退页重进。
5. **刷完新固件不重写表 = READY 页没有内容**：旧表的 `step_ms=1000` 会被
   `DPH_LoadEntry` 整条拒收（`step_ms < DPH_STEP_MS_MIN`）。这是预期，别误判成
   固件坏了 —— 旧表在真机上就是 `step=1000ms`（`config.json` 里存着 `step: 1.0`）。

1. **没上真机**：本轮所有改动只在编译 + 假电台 + 离线镜像上验过。

   `交付/F4HWN-Doppler.apk` 仍是 1.5/15（32 KiB、64 趟上限）。用户决定 APP 先不动。
   App 侧也没有 0x0776 入口，原厂机器首次装表必须借 PC。
3. **flashmap app 没编译**：本轮跟着改了它的地图常量（`0x162000..0x171FFF` /
   `0x172000..0x1D9FFF`），但那个 app 不在默认 93 TU 里。
4. **老表自动失效**：真机上现存的 `step=1000ms` 表刷完新固件就废了，
   需要重写一次。若用户想保留那张表，先别刷。
5. **三仓都未 commit**：固件仓 4 M、App 仓 1 M、PC 仓若干；按用户习惯不主动 commit。
