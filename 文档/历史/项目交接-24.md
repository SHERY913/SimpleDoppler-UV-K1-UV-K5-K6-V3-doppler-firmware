## 二、BUG-1：预听/尾音页没有 `$Z`

**证据**：`doppler_layout.h` 的 page 7/8 共 20 格，没有亚音那一格；排版器
`layout_editor.html:342/357` 也只在 page 0/1 放了 `$Z`。而
`多普勒使用说明.md`（按 1 那一行、发射那一节）都写"屏幕上 `$Z` 跟着变"，
`交接-23 §七 第 8 行` 的判据更是直接写"右上角 `$Z` 逐个换音"——按那张表的顺序
（第 7 行在尾音页按 PTT、第 8 行接着按 1），做到第 8 行时人正停在尾音页：
**按了听不见、看了没数字**。

**改法**：两页各补一格，收在底行 `EXIT` 左边（y=47、右对齐到 x=106）：

```
    { 7, 0, 2, 106, 47, "$Z" },      doppler_layout.h:102
    { 8, 0, 2, 106, 47, "$Z" },      doppler_layout.h:117
```

横向量过：最坏串 `T254.0` 6 格 24 px → 82..105；左边离 `M RUN  1 TONE` 的末尾
53 还空 29 px，右边离 `EXIT` 的起点 110 还空 5 px。排版器 `defaultModel()` 同步补了
同样两条（`layout_editor.html` page 7/8）。

**配套改的一处行为**（`doppler.c:1078`）：`DPH_CycleTone()` 新增
`if (!ext_ctrl && cur.up10 == 0u)` 拒绝（双响）。原因是版面自己有一条规则
——`DPH_DrawPage` 在 `cur.up10 == 0` 时把 `$Y`/`$Z` 整格跳过，所以纯接收星的
预听/尾音页**画不出这一格**；不改的话就是"按了一声响、屏幕上什么都没说"。
手机接管期间不拦：那一路的上行在手机帧里（`ext_tx10`），与表里的 `up10` 无关，
而且 EXT 页上 `$Z` 是显示的。

## 三、BUG-2：发射中换亚音，芯片不跟

**证据链**（三段都在源码里，不靠推断）：

1. `DPH_SetTone()`（`doppler.c:968`）只写 `FREQ_Config_t` 的 `CodeType/Code`；
2. 真正落到 BK4819 的是 `RADIO_SetTxParametersEx()`（`radio.c:1194-1209`），
   而它只在 **key-up** 那一刻跑一次；
3. 同文件的 `DPH_CyclePower()` 早就知道要补一句
   `if (gCurrentFunction == FUNCTION_TRANSMIT) RADIO_SetTxParameters();`
   （`doppler.c:2077`）——说明这个坑本身是已知的，只是换功率补了、换亚音没补。

后果正是本项目反复在杀的形状：`$Z` 读配置（当场变）、0x0775 的
`DOPPLER_TONE_ST_APPLIED` 位也按"已写进发射配置"报 APPLIED，而空中还是旧音。
proto 7 当初被发明出来就是为了 `0x0775` 不再谎报亚音，这条等于把同一种谎留在
一个更窄的角落。代码注释（`doppler.c:3185` 那一带）自己写着"要临时换音的时机
恰恰是已经听到了但对方要求换一个 sub-audible 的时候"——那个时机通常正在发射。

**改法**：`DPH_SetTone()` 末尾统一补一对寄存器写，发射中生效：

```c
    if (gCurrentFunction == FUNCTION_TRANSMIT)
    {
        if (applied != 0u) BK4819_SetCTCSSFrequency(applied);
        else               BK4819_ExitSubAu();
    }
```

**故意不照抄功率那一行**：`RADIO_SetTxParameters()` 是带 `SYSTEM_DelayMs`、
`AUDIO_AudioPathOff()`、PA 重开的整套流程，载波中间调它等于自己打断自己。
只补 `REG_51`（`SetCTCSSFrequency` 自带 Enable TxCTCSS）+ `REG_07` 频率字，
或 `ExitSubAu()` 清 `REG_51`，不碰 `REG_30`（AF DAC）、不切音频通路。
这一对函数的实现已逐个读过（`bk4829.c:546/1259`），确认只动这两个寄存器。

**残留一条窄的**（记着不修，进 §九）：`DPH_DONE`（73! 页）在手机接管那条路上
还活着，那 3 秒窗口里 `ext_ctrl` 为真、`$Z` 所在的 page 2 又没这一格，
按 `1` 会改配置但屏幕上没有读数。要不要留着 DONE 页本来就是 `交接-23 §八.1` 的
待定项，等那条定了一起收。

## 四、BUG-3：`$Y` 的注释在给不存在的补偿背书

**证据**：`doppler.c` 的 `case 'Y'` 注释写着 "uplink, compensated exactly like the
real TX path"，实现却是 `else if (phase == DPH_RUN)` 才补偿。READY/PRE/POST 三页
屏上印的是**标称上行**，而按下 PTT 出去的是补偿后的（READY 用 AOS 当刻样点，
预听/尾音用 `hold_off`，见 PTT 按下那一支）。

**改法**：把"此刻该补多少"收成一个入口 `DPH_TxOffsetNow(elapsed)`
（`doppler.c:1539`），PTT 按下那一支（`:3105`）和 `$Y`（`:4163`）都调它：

```c
static int32_t DPH_TxOffsetNow(uint32_t elapsed_10ms)
{
    if (phase == DPH_PRE || phase == DPH_POST)
        return hold_off;
    return DPH_OffsetAt(elapsed_10ms * 10u);
}
```

`$Y` 的含义因此统一成"现在按下去会发在哪个频点上"，与 `$O`/`$F`/真发出去的上行
同源。这一条**有可证伪的上机判据**（§八 的 B 行）：原来在就绪页按下 PTT 的瞬间
`$Y` 会从标称跳到补偿后，现在不该再跳。

## 五、BUG-4：满容表被 PC 自己的地址自检拒写

`doppler_tool.py` 写表前的自检原来是：

```python
for i in range(len(table) // core.DPH_SECTOR + 1):     # "商加一"
```

表长 = `0x1000 + 6×总样点数`，所以它真的可能是 4 KiB 的整数倍；`fit_keep()` 用的是
"超过才丢"，等号放行，于是**总样点正好 10240 的那张表 = 整 64 KiB**。此时
`//4096 + 1` 多数出一个扇区 → `guard(0x172000)` 判越界 → 弹
"地址自检没通过，一个字节都没写"，看不出是表"太满"还是"常量写歪了"。

改成向上取整 `(len + DPH_SECTOR - 1) // DPH_SECTOR`。用 `core.guard()` 直接跑过四种长度：

```
表长  16384 B  修前 5 扇区 / 修后 4 扇区
表长  61440 B  修前 16 / 修后 15
表长  65535 B  修前 16 / 修后 16
表长  65536 B  修前 拒：拒绝写入：0x172000+4096 超出表格区 0x162000..0x172000
               修后 放行 16 扇区，末尾 0x171000
```

（少查的那几个扇区不影响覆盖面：`erase_plan()` 恒返 16 个扇区，同一段前面已经
逐个 `guard()` 过一遍。）

## 九、要你定的

1. **预听里手动拧的频率，按 M 进跟踪时整份丢掉**（不是本轮改出来的，是这版的设计）。
   `DPH_BeginRun()` 不继承 `hold_off`，而 RUN 页的 ▲▼ 只挪时间、没有"给整条曲线
   加偏置"的入口。操作员拧频率的唯一动机就是提前找到了折射信号，这一跳把那份劳动
   清零。要做成"手动 delta 当偏置带进 RUN"是三四行的改动，但会改掉"进跟踪=完全按表"
   这条语义，所以留给你拍，没动。

   换的话要走一遍老流程：`交付/` 覆盖 + 旧份进 `交付/历史-20261101/` + `交付/README.md`
