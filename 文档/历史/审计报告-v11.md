## 1. 固件：已修（本次 21 处）

### 1.1 最重的一条：第二套逻辑（手机推帧）的频率整体小 10 倍

`doppler.c` 里 VFO 与 BK4819 的 REG_38/39 用的是**同一个单位：10 Hz**
（证据链：`frequencies.c:51` `NoaaFrequencyTable = {16255000, ...}` 对应 162.55 MHz；`app.c:953` `pRX->Frequency = 43300000` 对应 433 MHz；`radio.c:855` `BK4819_SetFrequency(gRxVfo->pRX->Frequency)` 无任何换算；安卓 `RadioLink.kt:189` `setRxHz` 也是 `hz/10` 后直写 REG_38/39）。

而手机帧的 `rx10/tx10` 按协议也是 10 Hz 单位（`MainScreen.kt:378` `((rxHz + dop) / 10.0)`、`test_ext.py` `push(int(hz/10), 14_599_000, ...)`）。

旧代码在 11 处写成 `ext_rx10 * 10u` / `ext_tx10 * 10u`，等于把 10 Hz 的数当 Hz 用，**PLL 落在十倍频上**（145.98750 MHz → 1459.875 MHz）。屏幕上每个数字都来自手机那一帧，所以**屏显全对、硬件全错**：收不到、发不出去，而且现场只会怀疑表错、天线坏、中继关了。

- 修法：11 处全部去掉 `* 10u`；新增 `DPH_ExtFreq10()` 做输入校验（29–1300 MHz 之外整帧按坏帧丢弃，`ext_rx10/ext_tx10` 置 0 让下游 `!= 0` 判断挡住）。
- 位置：`doppler.c` 的 `DPH_ExtFreq10`（新增）、`DPH_ExtTxApply`、`DOPPLER_ExtPush` 两个分支、PTT 松手回频。

### 1.2 判据分裂：屏显「TX ----」却双响拒发 / 屏显「RX ONLY」却真发射

PTT 闸门用 `ext_tx10 == 0`，屏幕 `$V/$Y` 用 `ext_flags & 0x04`。统一成宏 `DPH_EXT_RXONLY()`（`doppler.c:96`），四处替换。

### 1.3 显示与实际不一致（三处）

| 症状 | 根因 | 修法 |
|---|---|---|
| 开双守时，EXT 模式频率被周期性抢回，屏幕数字不变 | `ExtPush` 只写芯片和 `last_freq`，**从不写 `gRxVfo->pRX->Frequency`**；而 `radio.c:851-855` 的 `RADIO_SetupRegisters()` 会照 `pRX->Frequency` 重新点频，它被 `app.c:1115`（双守换台）、改音量、进菜单等一堆路径调用 | 接收分支补写 `gRxVfo->pRX->Frequency`（只写 gRxVfo，不动操作员另一个 VFO） |
| 交还控制权时芯片被调到 **0 Hz** | `SetExtControl` 的 `else { DPH_Tune(cur.freq10); }`，没有过境表时 `cur` 从未被 `DPH_LoadEntry` 填过 → `freq10 == 0` | 只在 `phase == DPH_READY && cur.freq10 != 0` 时才回表频点 |
| 交还后被踢到刚结束那趟的频点（屏上不显示频率，看不见） | 同上那条 `else` 分支对 DONE 也生效 | 同上 |

### 1.4 手机推来的多普勒**根本没有任何显示入口**

`DPH_Expand` 的 EXT 分支被 `*tpl != 'D'` 挡死，里面的 `case 'D'`（算多普勒）是死代码；公共分支的 `$O` 在 EXT 下恒为 `+0`。于是「手机算了多普勒、固件也在收」但屏幕上永远看不到。
- 修法：EXT 分支里那段死代码改成 `case 'O'` 输出带符号的 `ext_dopp`；布局表 page1 新增一格 `{ 1, 0, 2, 127, 33, "$O Hz" }`（3×5 小字，避开 dB 与墙钟）。顺带离线 RUN 页也开始显示实时偏移——以前第一套逻辑从不显示这个数。

### 1.5 接管真的把载波放掉

三个看门狗（5 s 帧静默 / 6 s 串口掉线 / 15 s 总超时）里写的是 `gFlagEndTransmission = true; /* carrier down */`，但全工程只有 `APP_HandleEndTransmission()` 读这个标志，而它只在**按键松开**时跑。10 ms tick 里没人轮询 → 所谓「强制停发」从来不执行，载波一直按到操作员自己松手或 TOT。
- 修法：`DPH_ExtStopTx()` = `APP_EndTransmission()` + `APP_HandleEndTransmission()`，两处超时改调它。

### 1.6 接管时不清编辑态（会在过境途中擦写 flash）

READY 页按 8 / 9 进 CALIBRATE / SET CLOCK 子页，`UI_DisplayDoppler()` 先判 `sub`，所以手机接管后屏幕停在编辑页、EXT 页永不出现；更糟的是数字键还能输入、MENU 还能提交 `DPH_EditCommit()` → 过境中擦写外置 flash 并锁发射 6 s。
- 修法：`DPH_ExtSessionReset()` 里清 `sub / edit_mode / edit_len`（三条接管路径都会调到它）。

### 1.7 其它

- **`$V` 没有实现**：page1 的 `{1,0,0,7,12,"$V $Y"}` 里 `$V` 只在 EXT 分支有 case，离线 RUN 页原样印出 `$V 145.98868`（v9 改模板时的回归）。公共 switch 补 `case 'V'`（按 `FUNCTION_TRANSMIT` 输出 TX/RX）。
- **发射中三角标整条消失**（v9 回归）：`DPH_TriAuto()` 按首两字符 `"TX"/"RX"` 匹配，模板是 `"$V $Y"` → 匹配不到。改为认 `$V` 前缀。
- **`ext_done_until` 是死变量**：注释承诺「73! 页停 3 s 自己退出」，但从没被赋过值，每次过境结束都得手动 EXIT。`DPH_FinishRun()` 里补 `+ 300 ticks`。
- **`DPH_Leave()` 不清 `ext_ctrl`**：页面退掉后 `DOPPLER_ExtActive()` 仍成立，下一拍自动抢页又拉回来 → 「按 EXIT 退不出去」。补 `ext_ctrl = false`（保留 App 的 `ext_page_on` 偏好）。
- **RUN 的 pTX 同步没加 `!ext_ctrl` 门**：App 只接管控频、不接管页面时（0x076E=0），这段每拍把 `pTX` 覆盖成表里的上行，和 `ExtPush` 写的手机上行打架。
- **0x076A 的「过境中」位在接管时恒 0**：`DOPPLER_ExtState()` 只看 `phase == DPH_RUN`，App 整段过境都读到「不在过境」。改成也在 `phase == DPH_EXT && ext_flags & 0x02` 时置位。
- **表项健壮性**：`DPH_LoadEntry` 增加 `dur_s <= 7200` 上限（`t_ms * 1000` 的 32 位乘会溢出）；`span_hz` 改用 32 位相减再夹 30 kHz（`-32768` 取负会原地溢出）。
- **`FindNext` 兜底**：表里全是被听过的过境时 `best` 停在 0 → 打开昨天第一条。改成取离现在最近的一趟。
- **空表页给原因**：`DPH_LoadHeader` 现在记录 `dph_tbl_err`（1 没写过 / 2 版本不认 / 3 hdr 坏 / 4 count 坏），EMPTY 页用新占位符 `$@` 显示 `NO TABLE` / `VER n ONLY` / `BAD HDR` / `BAD COUNT`。
- **LOCKED 闪字与百分比叠字**：page1 的 `$P%`（右对齐 111）与 `$J`（右对齐 127）在同一行 y=46，闪那 2 s 两个都读不出。闪字期间跳过 `$P%`。
- **`case 'Y'` 里上一版留下的恒真三元**（`DPH_EXT_RXONLY() ? "ONLY" : ...`）清掉。

## 3. 安卓 App：审计结论（未改代码）

P0 四条，按「最伤人」排序：

1. **`RadioSession.kt:49/78-83/585-595` `verified` 只在 `markLost` 里清**。点「断开」再连一台不回包的设备（旧固件/线错/没开机）→ `isReady` 立刻为真 → `MainScreen.kt:840-846` 弹「电台已连接」。**假连接被 UI 盖章**，后面所有操作都建立在假状态上。一行修：`markAlive()` 里 `verified = false`。
2. **`MainScreen.kt:419-425` `finally { setExtPage(false); releaseControl() }` 无代次保护**，而 effect 以 `idx` 为 key。控频中换星/连点两次 → 旧协程的 finally 晚于新协程的 `takeControl()` → 接管被关掉，界面还是「停止控频」，多普勒静默失效。这是最难定位的一类失效。
3. **`RadioLink.kt:112` 回包尾部 crc16 与 `DC BA` 收下不校验，`n` 不限长**。坏帧当好帧 → 垃圾频率被 `writeReg` 推到 PLL；`n` 偏大还会吞掉后续帧。
4. **`RadioSession.kt:426-435` `takeControl()` `join(400)` 而 USB 写超时 3000 ms**，`ok` 又非 volatile → 恒返回 false，界面永远「接管失败：固件没回话」。改用 0x0769 回包判定。

P1 七条：`ask()` 无互斥（写表与推帧互踩 CRC）· 每 200 ms 新建线程（长过境几千线程）· 授权 15 s 超时不回调 → `busy` 永久 true → 全页按钮哑 · `tryReconnect()` 从不重新请求权限 → 永久「正在自动重连」· `connectNet()` 不先 `disconnect()` 泄漏 socket · **接管弹窗显示 437.800/145.990，实际按模式推 145.800/144.490**（用户对着错的数字按 PTT）· `flags` 把「接管(0x01)」和「过境中(0x02)」焊成同一位。

P2/P3 十二条在子报告里（坐标压叠、模式按钮文案是当前模式却点一下换一个、弹窗两个按钮落点相同、无前台服务导致后台录音静音、星历计算跑在主线程、`toLong()` 截断导致恒定 −5 Hz 偏低等）。

**等你确认后再动的一件关键事**：App 的 `MainScreen.kt:378` 送的是 `rxHz/10`（10 Hz 单位），固件现在按 10 Hz 单位正确处理了。**两边都不许再改单位**——要改就同时改，否则又回到这次的十倍频问题。

## 4. PC 工具：审计结论（未改代码）

P0 两条：

1. **`doppler_core.py:623` 表头 count 是 u8，上限却写成 256** → 选满 256 条时 `struct.error: 'B' format requires 0 <= number <= 255`；`doppler_tool.py:1229` 只 catch `ValueError`，异常冒进 Tk 回调 → 按钮点了没反应、一个字节没写。修：上限改 255（或 `min(len,255)`）+ 兜底 `except Exception`。
2. **`doppler_tool.py:1290` 从偏移 0 顺序写** → 表头先落盘、样点最后。40 KB 中途掉线就留下「magic/ver/count 全合法 + 样点垃圾」的半表，电台按 count 读垃圾样点乱调频。修：样点先写、16 B 表头最后写，写完回读校验，失败把 count 置 0。

P1 八条：三套时区混用（`TZ=8` 硬编码 / 系统时区 / `datetime.now()`）→ 非 UTC+8 机器整表差 1 h · 队列非空时无视本次勾选 · TLE 解析失败不清右栏（A 的 AOS 配 B 的频率）· 勾选存 `id(p)`（recalc 后 id 复用）· 工作线程直接操作 Tk 控件 · 写表无二次确认、不备份、不可取消 · TLE 60 天都算「新」且 `tle_age` 从不赋值 · 串口列表不按 VID 36B7 过滤（装 MuMu 时混排）· 进度条 total 与实际 tick 数不一致。

**正面结论**：SGP4/多普勒符号/TLE epoch/站点 ECEF/`struct.calcsize`（16/40/6 无 padding）全部正确，`coarse=20 s` 两天窗口 11 趟无漏无切分。工具的核心物理是对的，问题全在外围工程（错误处理、状态一致性、UI 线程）。

### 仍需真机过一遍的两点
1. `RadioLink.ask()` 新加的回包 CRC 校验：若所有命令突然全部超时/CRC 不对，就是这里（固件 `uart.c` 的 CRC 覆盖范围与 `len` 字段是否含补齐字节），把 `回包 CRC 不对` 那两行注释掉即可回到旧行为，尾部 `DC BA` 校验可保留。
2. `takeControl()` 的 3200 ms 等待：USB 写超时 3000 ms 是库默认值，若固件对 0x0768 回包更慢，接管仍会判失败。

### 未动的（说明理由，不是漏）
- App 的 UI 布局问题（`UiLayout` 百分比 offset + 固定 padding 无宽度约束、按钮无 disabled 态、树状列表无横向滚动条）要重排布局，属于改版不是修 bug。
- `AndroidManifest.xml` 缺前台服务：后台录音/长过境提醒在 Android 11+ 会被掐，需要新增 service 组件 + 通知渠道，改动面大，单独做。
- `Recorder.kt` 主线程 `join(1500)`、星历计算跑在 Main 调度器：都是"卡一下"的量级，先记着。
- PC 工具的 Tk 线程安全、勾选状态用 `id(p)`、时区三套、TLE 缓存 60 天：都是 P1，逻辑改动牵一发动全身，建议下一轮单独做并配一次真机写表验证。
