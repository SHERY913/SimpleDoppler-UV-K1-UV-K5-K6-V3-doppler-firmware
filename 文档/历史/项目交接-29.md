## 二、E5 先定性：不是键码映射，也不是"时间轴到头"

交接-28 留的两种假设都不成立，第三条才是真的。三句话交代清楚：

**① 键码表没串位。** `App/driver/keyboard.c:142-180` 的 `keyboard[5][4]` 是
`col1={MENU,1,4,7}`、`col2={UP,2,5,8}`、`col3={DOWN,3,6,9}`、`col4={EXIT,*,0,F}`，
而扫描循环 `keyboard.c:209-274` 的列序用 `PIN_COL(n)=GPIO_MAKE_PIN(GPIOB, 1u << (6 - (n)))`，
`PIN_MASK_COLS` 只含 PB6/5/4/3 —— **列序与表一一对应，没有镜像**。
（顺带纠正交接-28：`KEY_UP=11 / KEY_DOWN=12 / KEY_EXIT=13`，不是 36/37/38；
全树 grep `KEY_LEFT|KEY_RIGHT` 零命中 —— 这台机器**没有左右键**，交接-28 说的"左右键"就是 ▲▼。）

**② 派发没被吃掉。** `app.c:2805-2817` 只把 `KEY_SIDE1/KEY_SIDE2` 从表格派发里排除，
RUN 页里 ▲▼ 一定到 `DOPPLER_ProcessKeys`，并落到 `doppler.c:3779-3821` 的
`case KEY_UP: case KEY_DOWN:` → `DPH_StepKey`。

**③ 真因在这里**（`doppler.c:2676-2692`，改之前）：

```c
el = (int32_t)(SCHEDULER_GetTick10ms() - t0_10ms) + dir * step;
if ((uint32_t)el >= total) el = (int32_t)total - 1;   /* ← 错在这一行 */
if (el < -(int32_t)total)  el = -(int32_t)total;
t0_10ms = SCHEDULER_GetTick10ms() - (uint32_t)el;
```

`el` 为负是**合法**的（注释自己写着"下界允许负"，负 el 表示原点被推到未来；
`DPH_BeginRun` 的"提前开始"分支 `doppler.c:2566` 就靠它把 AOS 之前的进度记成负数）。
可上界判据把 `el` 强转成 `uint32_t`：负 el 一转就是 4.29e9 级，**恒 ≥ total**，
于是被钳成 `total - 1`；10 ms 后 tick 里 `doppler.c:3196`
`if (elapsed >= (uint32_t)cur.dur_s * 100u) { DPH_FinishRun(); return; }` 成立 →
`DPH_PostListen()` → 就是"一按 ▼ 直接进尾音页"。
同一段注释上一行还写着"上界留最后一格（一按就跳进尾音页太奇怪）"——
**注释说它做了 ≠ 代码真做了**，这条又是范例。

**改法**：判据改成有符号比较，一行。

```c
if (el >= (int32_t)total)   /* doppler.c:2684 */
    el = (int32_t)total - 1;
```

正向越界仍然钳在末样点（LOS 前 10 ms，"跳到末尾"语义不变），负向完全不受影响。

**上机验证**：进 RUN 页后立刻按一下 ▼ —— 屏幕应停在跟踪页、频率停在首样点（不回跳、
不跳页）；再按 ▲ 同样。再在整趟末尾按 ▲ 应钳在末样点、页面不变。

## 三、E1　侧键一只换亚音、不起发：`ptt_down` 永远停在 true

**代码里有证据（三处，缺一不可）**：

1. `app.c:2731` 的 `if (gCurrentFunction == FUNCTION_TRANSMIT) {` 块里，
   `app.c:2754` 那句 `if (Key == KEY_PTT) { GENERIC_Key_PTT(bKeyPressed); goto Skip; }`
   —— **发射中（含抬起那一刻）`KEY_PTT` 一律走这里**，`ProcessKeysFunctions[...]` 根本轮不到，
   也就是 `DOPPLER_ProcessKeys → DPH_PttEvent(false)` 在真机上**从来没被调用过**。
2. `doppler.c` 里 `ptt_down` 的置位点只有 `DPH_PttEvent` 的准入块
   （`tx_hold = bKeyPressed; ptt_down = bKeyPressed;`），而 `DPH_Enter()` 清了一堆状态
   **唯独不清 `ptt_down`**。
3. `DOPPLER_KeySide1()` 起发那句是 `doppler.c:3527` 的
   `if (!ptt_down) DPH_PttEvent(true);` —— `ptt_down` 残留 `true`，它就只换亚音。

于是链条闭合：真按一次 PTT → 正常发射 → 松手时屏幕回不来（同上）、`ptt_down` 留在 `true`
→ 之后每次按侧键一：亚音确实换成 74.4（**这就是"链路是通的"那一半**）→ `if (!ptt_down)` 为假
→ 不起载波；松手走 `DPH_So50Release()`，那里看到 `ptt_down` 为真就只调
`RADIO_SetTxParameters()`、**不调 `DPH_PttEvent(false)`** → 循环永久成立。

**改法（两处，最小）**：

```c
/* app.c:2747-2751，放在 GENERIC_Key_PTT(bKeyPressed) 之前 */
if (!bKeyPressed && Key == KEY_PTT
    && (gScreenToDisplay == DISPLAY_DOPPLER || DOPPLER_IsActive())) {
    DOPPLER_ProcessKeys(Key, bKeyPressed, bKeyHeld);
    goto Skip;
}
```

只拦**抬起**：按下沿仍走 `GENERIC_Key_PTT`，否则同一拍里会再 `PrepareTX` 一次。

```c
/* doppler.c:3353-3367：准入失败时的松手也要收摊 */
else if (!bKeyPressed)
{
    GENERIC_Key_PTT(false);   /* 载波得有人关 */
    ptt_down = false;         /* 侧键一的准入判据要复位，不只是准入块里那一条路 */
}
```

`GENERIC_Key_PTT(false)` 的松手分支只在 `gCurrentFunction == FUNCTION_TRANSMIT` 时动手
（`generic.c:99-110`），所以补这一句不会误伤接收态。

**上机验证**：真按 PTT 说一句 → 松手 → 直接按侧键一 —— 应当**立刻起载波**（不用再按 PTT），
屏幕仍是多普勒页（`gRequestDisplayScreen = DISPLAY_DOPPLER` 把 `GENERIC` 的"回主界面"抢回来）；
松手回到本页频点、亚音回到原值。

> 顺带一个结论：交接-26 的第②条（松手分支补 READY 的 `DPH_Tune`）在真机上原来是**死代码**
> —— 松手根本进不了 `DPH_PttEvent`。这一轮之后它才第一次真正被执行。

## 四、E2　侧键二：一条必然、一条时序

**必然那条**（`doppler.c:1103` 起 `DPH_CycleTone`）：原来第一件事是

```c
if (!ext_ctrl && cur.up10 == 0u) { gBeepToPlay = 双响; return; }
```

纯接收星（`up10 == 0`）**必然**只双响，跟概率无关；同一次过境换到有上行的条目又突然能用，
操作员分不出是键坏了还是这颗星本来就没有。更糟的是配套的 `DPH_DrawPage` 把含 `$Z` 的整条
一起跳过 → **按键之后屏上什么都不说**。
两条一起改：早退删掉（`radio_saved` 那道闸仍在，空表页不会碰操作员的信道），
`doppler.c:4896` 的跳过条件收窄成只跳 `$Y`。

**时序那条**：`app.c:2726` 原来只认 `gScreenToDisplay == DISPLAY_DOPPLER`；
而 `GENERIC_Key_PTT` 起发那一刻会把屏请求到 `DISPLAY_MAIN`（`generic.c:210`），
抢回多普勒页要等下一拍 —— 这一拍里侧键二落到 `app.c:2743` 的
`if (Key == KEY_SIDE2) Code = 0xFE;` → **误发 1750 Hz 单音**。
改成与侧键一、与 tick 闸门同源：`(gScreenToDisplay == DISPLAY_DOPPLER || DOPPLER_IsActive())`。

**上机验证**：找一个纯接收星（表里没有上行）→ 进预听页 → 按侧键二 —— 应当听到"嘀"（不是双响），
且 `$Z` 那格从 `T--` 变成 `T67.0`；发射中按侧键二 —— 应换亚音，**不应听到 1750 Hz 单音**。

## 五、E3 / E4　两处版面（只动坐标，别的一样没碰）

`doppler_layout.h` 是 `layout_editor.html` 导出的，**两边必须一致**（`verify_layout.py` 第 10 段
逐条比对 86 条）。所以两处都同时改了 `.h` 与 `defaultModel()`。

- **E3**（`doppler_layout.h:65-66`）：`{1,0,0,39,18,"STEP $*s"}` + `{1,0,0,74,18,"BW $-"}`
  （原来 `S$*s` 在 39、`BW $-` 在 58，中间 19 px；最坏串 "STEP 10s" 8 字 = 32 px → 39..70，
  "BW 12k" 6 字 = 24 px → 74..97，右边 `$Z` 最坏 24 px 右对齐 127 → 103..126，都留了缝）。
- **E4**（`doppler_layout.h:131` / `:162`）：page 7 与 page 8 各补一条 `{7,0,0,2,24,"TX $Y"}` /
  `{8,0,0,2,24,"TX $Y"}`。**为什么是 24**：big 字走 `UI_PrintString(..., line=it->y, ...)`，
  `it->y` 是**行号**、8x16 实占像素 `line*8 .. line*8+15`（y=1 → 8..23），所以第一排内容从 24 起。
  原来把 `TX $Y` 放在 y=18 是错的（会压进大字里），已废弃。
  这两页原来的行是 25/32/39/47（page 7）与 25/32/39/47（page 8），一并按 24 起重排。

**重叠检查**：仓里原来**根本没有**版面重叠检查（`grep 重叠|overlap` 只有表区那一条），
这一轮补了 `tests/sim/check_layout_overlap.py`：按固件真算法复算字宽（tiny 4 px/字、
bold 7 px/字、big 13 px/字且 y 是行号），worst-case 展开占位符，像素级判重叠/出屏，
另外加**内容要求**（重叠检查发现不了"这一格干脆没有"）：

```
结果：OK（86 格 / 9 页，最坏串下无重叠、无出屏）   + 2 处已知贴边
```

两处"已知"都写清了为什么不算缺陷（page 1 `RX $F` 与 `$L` 只在 1.2 GHz 十位串下相碰；
page 1 `$P%` 与 `$J` 互斥，见 `doppler.c:4883` 的 `$P%` 跳过分支）——
**不写成"已知"就等于给自己留了个会翻车的口子，所以每条都指了代码位置。**

## 六、仿真与阳性对照


## 八、覆盖损失（必须知道）与下一步

**这一轮没法覆盖的（别当成"已验证"）**：

1. **E1 在 `app.c` 的那一半只能静态守**。`tests/sim` 只编 `doppler.c`，`app.c` 进不来；
   `check_dispatch.py` 抓的是结构，抓不到"写在 `goto Skip;` 之后"这种**编译得过、永不执行**
   的写法 —— 那只有真跑 `app.c` 才看得见。
2. **仿真里的 `GENERIC_Key_PTT` 是桩**（`sim_hw.c:381-393`），没有 `gFlagPrepareTX` 语义，
   所以 `RADIO_PrepareTX` 那串拒发闸门（`TX_LOCK` / `BUSY_CHANNEL_LOCK` / 电池 / 非 FM /
   忙扫描）一条都没被走过。E1 修好后**在真机上会不会被其中一道挡住**，仿真答不了。
3. **亚音只能语义观测**。`DPH_TxCfgs` 在 `radio_saved` 之后返回的是 `doppler.c` 内部静态
   `dph_vfo.pTX`，`sim_main.c` 拿不到指针，只能用 `DOPPLER_ExtToneGet()`（与 `0x0775` 同源）
   看"软件里记的亚音变了"，**看不到 BK4819 寄存器里 CTCSS 是否随载波真发出去**。
4. **版面只保证几何**。仿真字模是实心块（刻意不抄真字模），所以 `check_layout_overlap.py`
   保证的是"不重叠、不出屏"，不保证"3x5 字体下 `S` 和 `5`、`T--` 和 `T67.0` 好不好读"。
   E3 的 `STEP`/`BW` 在实际 128 px 屏上挤不挤，只能上机看。
5. **按键层组合没覆盖**：`gSetting_set_ptt_session`（PTT 会话模式）、按键重复回调
   （`DOPPLER_KeySide1` 是同步直接调的，绕过 `app.c` 的重复派发）、长按侧键一时
   `so50_prev_*` 被覆盖后还原不回 —— 三条都还是**已知未修**，这一轮没碰。
6. **8/9 的三份实机 flash 镜像仍缺**（`全满.bin` / `无多系统.bin` / `汉化-02-external-flash.bin`），
   guard()/erase_plan 只剩 7 条合成用例。
