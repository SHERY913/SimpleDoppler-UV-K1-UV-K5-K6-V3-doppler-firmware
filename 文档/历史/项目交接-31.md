## 二、E6：READY 页两条发射后门，一个闸门管住

### 2.1 为什么侧键一修好了、PTT 还能发

`app.c` 的 PTT 派发只拦**抬起**（`app.c:2747` 起，注释原文「只拦抬起，按下沿仍走 GENERIC」）：
按下那一刻 `gCurrentFunction` 还不是 `FUNCTION_TRANSMIT`，走的是普通接收分支 →
`ProcessKeysFunctions[DISPLAY_DOPPLER]` → `DOPPLER_ProcessKeys` → `DPH_PttEvent(true)`。
也就是说按下**确实**送到了这一页，能不能发只取决于 `DPH_PttEvent` 里的准入判据 ——
而那里面 `DPH_READY` 一直写着。

### 2.2 改法（两处，缺一不可）

```c
/* doppler.c:3317 —— 新增闸门，放在 haveUp 之前 */
if (bKeyPressed && phase == DPH_READY)
{
    if (!tx_refused)
    {
        tx_refused  = true;
        tx_hold     = false;
        ext_dirty   = true;
        gBeepToPlay = BEEP_500HZ_60MS_DOUBLE_BEEP_OPTIONAL;
    }
    return;
}
```

```c
/* doppler.c:3347 —— 准入相位里删掉 DPH_READY */
if ((phase == DPH_RUN || phase == DPH_EXT
     || phase == DPH_PRE || phase == DPH_POST) && haveUp)
```

- 反馈沿用 EXT 那条"没有上行就双响"的既有做法（同一个 `tx_refused` 去重），**不上屏** ——
  操作员自己做 UI，屏上不许多出任何东西。
- 松手不用特殊处理：`!bKeyPressed` 时闸门不拦，准入也不成立，落到已有的
  `else if (!bKeyPressed) { GENERIC_Key_PTT(false); ptt_down = false; }` 兜底。
- 侧键一走的是 `DOPPLER_KeySide1()` → `DPH_PttEvent(true)`，**同一个闸门**，所以两条路天然一致；
  这也是为什么 `negctl` 的 case 12 必须同时拆掉闸门才跑得出红 —— 只把 READY 塞回侧键一准入会被闸门先挡掉。

## 三、E7：方向、范围

### 3.1 方向只翻 RUN 的时间轴

```c
/* doppler.c:2673 */
int32_t dir = (Key == KEY_UP) ? -1 : 1;   /* ▼ 往前、▲ 往后 */
```

操作员先选"两处一起反"（RUN 时间轴 + READY 选星），随即发截图纠正「这个说错了，只有 run 反」。
所以 READY 的 ▲▼（`doppler.c:3829` 那条 `if (sub == 0u && phase == DPH_READY && hdr.count > 1u)`）
一个字没动，仍然是 `KEY_UP → sel=(sel+count-1)%count`、`KEY_DOWN → sel=(sel+1)%count`。

方向的口径是屏上那行 `$L`：它印的是**距 LOS 还剩多少**，往右按就该把这行数字吃掉。

### 3.2 范围钳成 `[0, total-1]`

```c
/* doppler.c:2706 */
if (el >= (int32_t)total)
    el = (int32_t)total - 1;
if (el < 0)
    el = 0;
```

- 上一版允许负 `el`（"AOS 之前手动开始那段，t0 落在未来"），代价是能一路拧到 -100000 s、
  `$L` 印成 `-10:02` 这种比整趟还大的数。现在过界**停住**：到 0 再按 ▲ 什么也不做，到末样点按 ▼ 也一样。
- **已知代价（操作员明确接受）**：提前开始那几秒的提前量，一按 ▼ 就归零。
- 必须保留 `(int32_t)` 比较：`(uint32_t)el` 在负值时是 40 亿级，恒 `>= total`，
  会被上界钳成 `total-1`，下一拍 tick 立刻判到点 → "按一下就跳进尾音页"（E5 的老症状）。
