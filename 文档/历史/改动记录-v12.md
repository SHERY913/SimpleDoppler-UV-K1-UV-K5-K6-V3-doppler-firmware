## 一、固件：发射时上方那格不再变成发射频率

### 现象
PTT 按下后，RUN 页上方那格（原设计是"接收频率"）跳到发射频率；下面 `$Y` 那行本来
就是发射频率，于是两行显示同一个数字，而左侧三角标已经翻到上行行。用户看到的是
"主频率跟着发射频率变了"，屏上一半信息消失。

### 根因
`App/app/doppler.c` 公共 `DPH_Expand` 的 `case 'F'`：

```c
if (gCurrentFunction == FUNCTION_TRANSMIT && cur.up10 != 0u)
    f = gRxVfo->pTX->Frequency;        // ← 发射时改指上行
else if (phase == DPH_RUN)
    f = gRxVfo->pRX->Frequency;
else
    f = cur.freq10;
```

### 修改
删掉发射分支，这一格永远只报"现在在收什么"：

```c
if (phase == DPH_RUN) f = gRxVfo->pRX->Frequency;
else                  f = cur.freq10;
```

发射频率由 `$Y` 那行负责，三角标也指向那一行，两者不再重复。

### 验证
93/93 TU，link rc 0，`size` 99,240 B（v11 是 99,296 B，少了一条分支）。
RAM 12,768 / 16,384 B（77.93%），FLASH 98,408 / 118,784 B（81.44%）。

## 四、真机联调记录（COM7）

电台在 PC 上枚举为 `COM7`，VID/PID = `36B7:FFFF`。模拟器没有 USB Host，所以走
`serial_bridge.py` 桥：

```
python 多普勒工具/serial_bridge.py --port COM7 --listen 7878 --log
adb -s emulator-5554 reverse tcp:7878 tcp:7878
```

App「设置 → 网络调试」连 `127.0.0.1:7878`，实测通了，链路日志：

| 动作 | 发出的命令 | 回包 |
| --- | --- | --- |
| 连接后自动对时 | `0x0766` | `0x0767` |
| 固件自检 | `0x076A` → `proto 6 · 未接管 · 表已加载（phase 0）` | `0x076B` |
| 手机接管频率 | `0x0768` + `0x076E`（开 EXT 页） | `0x0769` / `0x076F` |
| 持续推帧 | `0x076C` 每 ~200 ms | `0x076D` |
| 停止控频 | `0x076E`（关页）+ 交还 | `0x076F` |

### 一条协议事实（本轮实测，之前 App 里写错了）

固件回包的 `crc` 字段**恒为 `0xFFFF`**（不计算），尾部 `DC BA` 是**不参与掩码的明文**，
且回包 `msg` 不补零（可以是奇数长度）。App 原先按"发送侧规则"校验回包 CRC，会把
所有正常回包判成坏帧 —— 已改成：`crc == 0xFFFF` 放行，尾部按明文比对。

# v14（2026-10-26 01:56）"电台没有响应"排查

## 一、真正的原因：7878 上有个假电台

这台机器上一直挂着我早期做协议验证用的 `.gtmp/dec.py`（假电台，只认 `0x076A`，
其它命令一律不回）。它占着 `0.0.0.0:7878`；`serial_bridge.py` 用的是
`SO_REUSEADDR`，**在 Windows 上这不是"TIME_WAIT 复用"，而是允许抢占同一端口**，
于是桥接也 bind 成功，两个进程抢同一个端口。App 连上后请求被谁接走看运气：

- 假电台接走 → `0x0766` 对时 / `0x0764` 读表 没有回包 → 界面「没有响应」
- 真桥接接走 → 一切正常

所以出现"有时能连、点对时又没反应"这种玄学。已处理：

1. 杀掉假电台进程（`python .gtmp/dec.py`），并确认 `7878` 无人监听。
2. `serial_bridge.py` 改成 Windows 下用 `SO_EXCLUSIVEADDRUSE`：端口被占就
   **立刻报错退出（rc=2）**并打印"先关掉占它的程序"，不再静默抢占。已实测。

## 二、顺带修掉的三个"点了没反应"

| 现象 | 原因 | 改法 |
| --- | --- | --- |
| 「更新电台时间」灰着点不动 | `clickable(enabled = ready)`，链路没就绪时按钮直接禁用，没有任何解释 | 按钮永远可点；没链路时直接显示「未连接：先点上面『USB 连接』或『网络桥』」 |

# v15（2026-10-26 02:02）连真机.cmd 编码事故

## 现象

双击 `多普勒工具/连真机.cmd`，控制台满屏 `'ge.py" --port --listen 7878' 不是内部或外部命令`，中文全是乱码。

## 根因

第一版用 UTF-8 保存（还带了 `chcp 65001`）。cmd.exe 读 .cmd 是按系统 ANSI 代码页（简中 = GBK/936）解析字节的，UTF-8 的中文在 GBK 下成了乱码字节，乱码里恰好出现 `>`、`|`、引号，命令行被从中间拆断，于是出现半截命令报错。

## 改法

1. 整份文件用 **GBK** 写回（CRLF，`chcp 936 >nul`）。
2. 顺手去掉两个脆弱点：`timeout /t 3`（在 MSYS/Git 环境会解析成 GNU timeout）改成 `ping -n 4 127.0.0.1 >nul`；`find_port.py` 输出带装饰不能直接喂 `for /f`，改成一行式 `python -c` 只打印 device。
3. 新增 `连真机.cmd dry` 自检模式：只查串口与 adb 设备，不起桥接、不做 reverse。

## 端到端复测（02:01）

# v16（2026-10-26 02:35）写表提速、追踪页重排、亚音/水印、免开 CMD

## 1. 写表为什么慢（三个独立缺陷，全部修掉）

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | `RadioLink.putChunk` 用 `r[6]` 当状态码 | 0x0763 回包是 `cmd(2)+len(2)+payload`，真状态码在 `r[10]`。按 `r[6]`（addr 低字节 0x16）判断，每一块都"失败" → 3 次重试 + `sleep(8)`，实测 150~180 ms/块 | 改判 `r[10]==0 && r[8..9]==want` |
| 2 | 每写一块就回读一块校验 | 命令数翻倍（372 块 → 744 次往返） | 先去写、再整段回读一次，只重写对不上的块（最多两轮） |
| 3 | 日志串 `.format("%.6X", …)` | `%X` 不接受精度 → `IllegalFormatPrecisionException: 6`，整次写表直接中止、一块没写 | 去掉 `%.6X`，改字符串插值 |

实测（MuMu + COM7 桥接，20 趟 / 47624 B / 372 块）：修复前 40 s 以上且最终失败；修复后 2 趟 / 16152 B / 8 扇区 **10.0 s**（界面右下角直接显示耗时）。
延迟拆解：`drain 3 ms + write 0 ms + 等回包 44 ms`。同一块表用 PC 直连 COM7 只要 **1.7 ms/块** —— 这 44 ms 是 MuMu 虚拟机 ↔ 宿主的 TCP 中转开销（`adb reverse` 隧道和 `10.0.2.2` 直连都测过，都是 44 ms；ping 只要 0.37 ms）。换成真手机 OTG 直连，整表应在 1 秒内。

## 2. 覆盖，不找空位

每次写表固定流程：`0x0766` 对时 → 从 `0x00162000` 起逐扇区 `0x0760` 擦除（4 KiB × 8 扇区起）→ 先写样点与条目（`table[16..]`）→ 最后写 16 B 表头 → 回读表头校验 `DPT1`。旧表一定被抹掉，不做空闲区搜索。

## 3. 界面

- 详情页（过境规划器）：阶段文字「擦除 i/8 → 写 done/total p% → 写表头 → 校验」，进度条 0.72 宽 4 dp，完成后显示「已写入 N 趟 / B / 扇区 / 秒」。
- 追踪页：顶栏 `收 %.5f MHz   多普勒 %+.0f Hz`；罗盘与数据块上下分区，数据块常驻（未接管也显示下行/上行/亚音/仰角/方位/距离/多普勒/变化率/剩余）；盘面上只保留"手机朝向差多少"，其余数字不再重复叠印。
- `BG0FPJ`：顶栏右上角常驻 + 开发者信息首行 + 版本块末尾。
- 术语统一为**亚音**（CTCSS），不再是"哑音"。

## 4. 不用再开 CMD

- `多普勒工具/连真机-静默.vbs`：双击即后台起桥接 + 做 `adb reverse` + 拉起 App，无黑窗口；失败弹框并贴出 `bridge.log` 尾部。
- `多普勒工具/断开桥接.cmd`：双击收工（关桥接、撤 reverse）。
- 两个文件都必须存成 **GBK**（UTF-8 会让 cmd/cscript 把中文当乱码拆命令行，就是上一版满屏 `不是内部或外部命令` 的原因）。

## 5. 桥接顺手优化

`serial_bridge.py`：`pump` 改按 `in_waiting` 直读（原来 `read(4096)` 每次等满 50 ms 超时）、`timeout=0.01`、`TCP_NODELAY`。App 侧 `connectNet` 先试 `10.0.2.2`（模拟器网关）再退 `127.0.0.1`。
