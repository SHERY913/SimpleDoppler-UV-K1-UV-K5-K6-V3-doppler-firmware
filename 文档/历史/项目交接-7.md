## 1. 删掉手调（App 侧）

**改法**：把"手动改频率"的整条交互链从 App 里拿掉——步进旋钮、步长选择、`0x0771` 读回重设基准，
一个都不剩。现在频率只有一个来源：解算器算出来、追踪循环写下去。

**证据**：`grep -rn "0x0771\|手调\|readback\|rebase" 安卓App/.../doppler/*.kt` 无命中（本轮实测）。

**故意没动的**：固件里的 `0x0771` 处理分支还在（`uart.c` 的 `case 0x0771`）。留着的原因：
它是后台命令，老 PC 工具还在用；App 不发它就等于不存在，删分支反而要改 PC 工具。
**副作用要记住**：电台上的物理旋钮现在拧了也会被 App 下一帧写回，用户看到的是"旋钮没反应"——
这是需求 1 的直接后果，不是 bug。

## 2. 晶振（ppm）——把"存 200 用 76"这条缝焊死

### 之前的三个数

| 环节 | 旧行为 | 后果 |
|---|---|---|
| 保存 `DPH_SaveCal` | 钳 ±20000 | flash 里能写进 20000 |
| 施加 `DPH_ApplyXtalTrim` | 只钳 ±400 **步**（= ±76.9 ppm） | 实际按 76 走 |
| 页面显示 | 读 `clk_ppm`（20000） | 显示 20000，射频修 76 |

三条路各不相同，于是"校准页报的数"和"真正生效的数"对不上，而且谁也说不清哪个是真的。

### 现在

- `App/app/doppler.h:52` `#define DPH_PPM_MAX 76`，推导写在 :35（400 步 ÷ 5.2005 = 76.9… 向下取整）。
- `DPH_SaveCal()` 返回**实际生效值**（`int32_t`），钳到 ±76 后写 flash、立刻落 PLL。
- `DPH_ApplyXtalTrim()` 先用同一个常量钳 `ppm` 再算步数，`±400` 留作最后一道物理兜底
  （注释里写明"永远进不来，防的是有人把 MAX 调大"）。
- `DPH_ClockSec()` 的 ±20000 钳位降级为纯防御，注释说明"正常进不来"。
- **回读**：新命令 `0x0772` 回 `{Ver[8], Ppm, PpmMax, Proto, Phase}`（`uart.c:1493`，回包 ID `0x0773`，16 B 帧）。
  App 侧 `RadioLink.kt:381 readFwTag()`、`Model.kt:249 FwTag`，设置页/信息页用它显示
  "固件 DPH-… · 校准 +12 ppm（上限 76）"。`|Ppm| == PpmMax` 就是"被钳过，按范围重填"的判据。

### 顺手关掉的后门

`CMD_0602_WriteBK4819Reg` 现在**拒写 `BK4819_REG_3B`**（`uart.c:740` 起）：
那正是晶振刻度寄存器，App 随手写一次就能让校准静默失效而页面照旧显示。拒绝时仍然
`DOPPLER_ExtHeartbeat()`，"不写寄存器"不能被 App 的拔线看门狗误判成串口死了。
旁路清单（EEPROM 的 `BK4819_XTAL_FREQ_LOW`、旧固件写下的 v1 记录）写在 `DPH_SaveCal` 的注释里，
两条都只能"少修"，不能越界。

**没证实的事**：76 ppm 是不是这颗 26 MHz 晶振的真实可修范围，只有实测频谱能答。
代码这侧只保证"报的数就是写进寄存器的数"。

## 3. 罗盘重做（这一项返工过一次，记录清楚）

### 根因（不是画得难看）

旧实现直接吃 `SensorManager.getOrientation()` 的 `ori[0]` / `ori[1]`，把 `ori[1]` 取负当仰角，
再用它画天穹图。`ori[1]` 是"设备平面从水平面转了多少"，它的零点是**平放**；
而"指向"的零点是**竖直**（举起手机指地平线）。两套零点差 90°，所以：
平放桌面 → 显示"指向天顶"，举到正上方 → 显示"指向地面"。**显示和实际差整整 90°，而且方向是反的。**
叠加 `NaN` 没有兜底（矩阵退化时 `atan2(0,0)`），偶尔整块图消失。

### 现在的口径（写死在 `SkyView.kt:38-50` 的类注释里，改之前先读它）

- 取 **设备 +Y 轴（顶边）** 在世界系 `(east, north, up)` 的分量 → 方位 `atan2(east, north)`、仰角 `asin(up)`。
- 平放桌面 = 仰角 0（顶边指地平线）；竖直举起 = 仰角 90（顶边指天顶）；仰角钳到 `[0,90]`。
- 顶边接近垂直时水平投影退化，方位保持上一次的值，不输出 `NaN`。
- 与 **Look4Sat 完全同口径**（`参考-Look4Sat罗盘实现.md` 里逆向出来的 `max(0,-pitch)` 就是同一个意思）。
  中间那一版按"手机背面法线（-Z）"做的，物理上也自洽，但和 Look4Sat 差 90°，用户会二次投诉，已废弃。

### 传感器链

| 项 | 实现 | 位置 |
|---|---|---|
| 主传感器 | `TYPE_ROTATION_VECTOR`（融合陀螺仪，跟手不抖） | `SkyView.kt:109,208` |
| 兜底 | 加速度计 + 磁力计组矩阵（只在没有 rotvec 时注册） | `SkyView.kt:210-216` |
| 采样 | `SENSOR_DELAY_GAME`（约 50 Hz） | 同上 |
| 解矩阵 | `getRotationMatrixFromVector`，`values.size < 4` 直接返回（有些机型给 3 个会抛） | `SkyView.kt:165-176` |
| 平滑 | 方位环形低通（差折到 ±180 再加，0/360 不跳），仰角线性低通；首帧直接落值不爬坡 | `SkyView.kt:147-160` |
| 自适应增益 | 单帧跳变 >18° 用 0.75（转身跟手）、>6° 用 0.42、否则 0.20 | `SkyView.kt:158-160` |
| 自证 | `OrientationState.source` = `rotvec` / `accel+mag` / `无`，追踪页直接显示 | `SkyView.kt:53` |

### 对准指引（说人话）

`pointGuide()`（`SkyView.kt:77`）把两轴偏差合成一个 `dist`，`<= ALIGN_TOL_DEG` 判对准；
`ui/TrackScreen.kt:241-290` 负责翻译成"右转 23° / 抬头 8° / 对准"。
顶边朝下（仰角被钳到 0）且卫星在天上时，额外一句"抬高手机顶边"——只说动作，不讲原理。

### 没证实的事

传感器在真机上是否"正确调用"= 代码层已保证（谁在出数、出的什么数都可读）；
但磁场环境（地铁、车内、变电站旁）的漂移只能真机跑，`source` 字段就是给这件事留的观察口。
MuMu 模拟器没有磁力计，`verify_display.py` 验的是"给定姿态下 App 算的和 Python 算的一致"，
不验"姿态本身准不准"。

## 5. TLE 多源与刷新耗时

### 做了什么

- 新增 `PC工具/多普勒工具/tle_sources.py`，把"源"抽象成可枚举的 provider；
  `refresh_tle.py` 依次试、按 `tle1` 历元裁决新旧。
- **SatNOGS 批量源**：`https://db.satnogs.org/api/tle/?format=json` → 实测 **200 / 1735 条（1700 条可用）/ 537 KB / 40~119 s**。
  字段是 `tle0`（带 `"0 "` 前导）/`tle1`/`tle2`/`tle_source`/`sat_id`/`norad_cat_id`/`updated`。
- **`updated` 不是历元**（是入库时间），新旧一律从 `tle1` 解——这条踩过坑，写进 `TLE数据源说明.md`。
- **默认只补缓存里已有的 NORAD**（`keep` 过滤）：1700 条里 1605 条是非业余星，
  全量并入会把界面 96 → 1701。命中 **95/96**。
- **`--stale`**：只刷超龄星。实测把 `40931 IO-86` 从 101 天 → 11 天；`71922 LILIUM-4` 两个接口都没有（如实报，exit 2）。
- **防回退规则（本轮修的真 bug）**：`--stale` 补好的星，会被下一次默认 AMSAT 刷新用**三个月前的历元**打回去。
  现在"源给的比缓存旧就保留缓存"，并打印"保留旧缓存 N 颗"。反向案例也证实了必要性：
  SatNOGS 的 ISS 记录停在 2023-01-06，若盲信"新源优先"会把 ISS 打回三年前。
- **耗时**：从 166.7 s → **13.0~19.9 s**。手段是每个 host 先做一次 5 s TCP 预探
  （连不上立刻判死，同主机后续源 0.0 s 跳过）+ `curl --connect-timeout 5`。
  `--skip=celestrak_*` 13.3 s；`--extra`（含 SatNOGS）106~119 s，只在兜底/单星查询时用。

### 现状与不做的事

- `verify_data.py` 现在跳过 `_` 开头的顶层键（元数据键曾被当成卫星条目计数，制造假告警）。
  当前 **rc=2，P1 仅 1 条**（LILIUM-4 211 天）+ P2 1 条（IO-86 11 天）。
- celestrak 全线不通（网络侧），不修。
- `--extra-all` 能把 96 → 1701 颗，**故意没执行**：频率表只覆盖 97 颗，多出来的会变成"无频率"行，
  是负资产。要用就显式加参数。

## 6. 固件信息页（`sub == 3`，layout page 6）

- 新增第 4 个页面 `sub = 3`（`doppler.c:179` 的 `sub` 注释同步），布局在 `doppler_layout.h`（+12 行）。
- 内容：固件 tag、`Proto`/`Phase`、实际 ppm、上限、时钟/校准状态。
- **节流**：`static uint8_t info_sec`（`doppler.c:57`）+ `doppler.c:3409-3430`——
  每秒最多重绘一次。理由写在 :3410 的注释里：LCD 与 BK4819 共用 SPI，信息页每秒都有数字在变，
  不节流会按 100~200 ms 的节奏抢总线。判据只看低 8 位（"这一秒画过没有"），256 s 回绕最多让某帧提前/推迟 1 s。
- 进页那一下不节流：`DOPPLER_ProcessKeys` 会把 `info_sec` 推后一秒，保证按 5 立刻见到画面（`doppler.c:3420`）。
- `DPH_FwTag()` / `DPH_PpmGet()` 暴露给 `0x0772`（`doppler.c:3506,3511`，声明在 `doppler.h:161,162`）。
