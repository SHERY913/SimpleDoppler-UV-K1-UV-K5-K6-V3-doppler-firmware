## 一、一句话

`doppler.c` 里三处「改了芯片却没同步缓存 / 漏了一个松手分支 / 改功率抢在借用副本之前」，
每一处都能在电台上一按就试出来，且都是**屏幕显示正确、硬件行为错误**那一类。

| 编号 | 缺陷 | 严重度 | 复现率 |
|---|---|---|---|
| D1 | 预听页 / 尾音页按 PTT 松手，接收机停在上行频点 | P0 | 100% |
| D2 | 就绪页按 PTT 松手，同样不回（这支根本不存在） | P0 | 100% |
| D3 | 进过境页把操作员信道的功率改成 5 W，退页不还原 | P1 | 100% |

---

## 二、D1　`DPH_TxApply` 少了 `last_freq = up;`

**现象**：预听页（长按 M）或尾音页按一下 PTT、松手，电台接着"听"，但听的是自己刚发出去的
**上行**频点。屏幕 `$F` 仍写着正确的下行数字 —— 屏对、芯片错。只有按一下 M 或 EXIT 才回来。

**根因**（`App/app/doppler.c`）：`last_freq` 是"芯片现在停在哪"的唯一缓存，`DPH_Tune()` 一开头
就拿它做早退：

```c
if (freq == last_freq)
    return;
```

链条是三步：

1. 进预听：`DPH_PreListen()` 里 `DPH_TuneSafe(DPH_Rx10WithOff(hold_off))` → 走 `DPH_Tune()`，
   `last_freq` 被设成"下行 + AOS 偏移"；
2. 发射：`DPH_TxApply()` 写芯片到上行，**却没有更新 `last_freq`**（对照
   `DPH_ExtTxApply()`，人家一直有这一行，注释还专门解释了为什么）；
3. 松手：`DPH_PttEvent()` 的松手分支调 `DPH_Tune(DPH_Rx10WithOff(hold_off))` —— 传进去的
   正是第 1 步那个值，于是被第 2 步遗留的旧缓存判成"没变化"，整段恢复被吞掉。

非 RUN 相位在 tick 里没有兜底（只有重画），`DPH_GuardVfo()` 在正常态直接早退，
`FUNCTION_Select()` 只写 `gCurrentFunction` 不重写频合 —— 没有任何别的东西替我们补。

**改法**：`DPH_TxApply()` 末尾补 `last_freq = up;`，与 `DPH_ExtTxApply()` 完全对齐。

**真机验证**：F+0 进页 → 长按 M 进预听 → 按 PTT 说一句 → 松手 → 卫星信号应当还在（修复前没了）。

## 三、D2　松手分支漏了 READY

**现象**：就绪页直接按 PTT 喊一句、松手，接收机停在上行频点上。

**根因**：`DPH_PttEvent()` 的松手分支只有两条出口（`DPH_EXT`、`DPH_PRE`/`DPH_POST`），
`DPH_READY` 一个分支都没有；而 `DPH_PttEvent()` 的准入相位里明明包含 READY。
READY 相位在 tick 里同样没有补频路径。

**改法**：补一支，回**标称频率**：

```c
else if (phase == DPH_READY && !ext_ctrl)
    DPH_Tune(cur.freq10);
```

为什么是 `cur.freq10` 而不是 AOS 偏移：与 `DPH_BeginRun()` / `DPH_BackToReady()` 两处进跟踪、
以及 `$F` 在 READY 的显示口径保持一致 —— 屏幕上的数字就是芯片上的数字。

**真机验证**：F+0 → 停在就绪页 → 按 PTT 松手 → 卫星仍在。

> **D1 与 D2 必须同版**：D1 单独修，就绪页松手还是不调 `DPH_Tune()`，症状不变。

## 四、D3　拨 5 W 抢在「借用副本」之前

**现象**：把某个信道设成 1 W → F+0 进多普勒页 → EXIT 回主界面 → 功率档变 5 W；
在这个信道上发射真的就是 5 W（存信道则落盘）。

**根因**：`DOPPLER_Start()` 里那两行 `gRxVfo->OUTPUT_POWER = OUTPUT_POWER_HIGH;` 跑在
`DPH_Enter()` **之前**，而 `DPH_Enter()` 内部的 `DPH_SaveRadio()` 才把 `gRxVfo/gTxVfo`
指到借来的 `dph_vfo` 上。所以改的是操作员自己那份 `gEeprom.VfoInfo[]`；
`DPH_SaveRadio()` 的 `orig_*` 里**没有** `OUTPUT_POWER` 这一项，
`DPH_AudioRestore()` 也就无从还原（它最后调 `RADIO_ConfigureSquelchAndOutputPower(gRxVfo)`，
`App/radio.c:766` 读的就是 `pInfo->OUTPUT_POWER`）。

原来那句注释（"这一改只落在借来的 `dph_vfo` 上…不动他存着的信道功率"）描述的正是
**改好之后**的行为，代码只是执行早了。

**改法**：把赋值挪到 `DPH_Enter()` 之后，并且加 `radio_saved` 守卫：

```c
    DPH_Enter();

    if (fresh_entry && radio_saved)
    {
        gRxVfo->OUTPUT_POWER = OUTPUT_POWER_HIGH;
        if (gTxVfo != NULL)
            gTxVfo->OUTPUT_POWER = OUTPUT_POWER_HIGH;
    }
```

- `fresh_entry` = `(phase == DPH_OFF)`，在 `DPH_Enter()` 之前定格（它会把 phase 改成
  READY/EMPTY）。顺手把上面那个 `if (phase == DPH_OFF)` 块收成一句 `if (fresh_entry)`。
- `radio_saved` 判断不能省：表无效时 `DPH_Enter()` 不会调 `DPH_SaveRadio()`，指针还指着
  操作员的信道，那时候写功率又漏回去了。

**真机验证**：1 W 的信道 → F+0 → EXIT → 功率档应当还是 1 W；再进页应当变成 5 W（页内该是最高档），
退页回 1 W。

## 五、回归网：写频合必须同步 `last_freq`

`PC工具/多普勒工具/verify_layout.py` 末尾新增一条静态检查（不需要编译器、不需要电台）：

- 把 `doppler.c` 按"顶格 `}`"切成函数块（内层 `if/for` 的右括号都有缩进，不会误切）；
- 凡是块里出现真调用 `BK4819_SetFrequency(` 的，块内必须有一条真赋值 `last_freq =`
  （同步、清零、先存原值都算）；
- **注释不算** —— 一段解释这份缓存的注释不能让检查常绿（第一版就是这么写的，实测抓不到）。

**证明它有用**：把 `last_freq = up;` 那行删掉再跑，报

```

一致 35 · 告警 0 · 漂移 1        结果：FAIL
```

放回去立刻 `结果：OK`（现在共 9 处调用点全部覆盖）。

## 六、没修的（已识别，按本轮口径不进这一版）

### 风险（未验证的假设）

1. `DPH_TuneSafe()` 只认 `gCurrentFunction == FUNCTION_TRANSMIT`，PTT 按下到标志置位之间有一个
   时间窗，落在窗里的相位切换仍会走 `DPH_Tune` 把载波挪走。**验法**：按下 PTT 的同时按 ▲▼ 换星。
2. 侧键一长按是否重复回调。`DOPPLER_KeySide1(true)` 在按下时存 `so50_prev_type/code`，
   若按键层重复回调，第二遍把"原始值"覆盖成 74.4，松手还原不回。
3. `sub != 0` 时武装倒计时整块被挂起（tick 里的 `sub == 0u`）。AOS 正好在操作员停在校时页时
   过去，退出后 `left < 0` → `auto_armed = false`，**静默丢武装，不跟踪也不提示**。

### 已知不一致

4. 跟踪中松手依赖"下一拍偏移变了"。过境最高点附近多普勒变化率≈0，可能几十毫秒到几秒
   维持同一格 —— D1 修完之后这条已经不会僵住（`last_freq` 已是上行值），保留观察。
5. 手机交还控制权后停在 AOS 偏移（`DOPPLER_SetExtControl()` 末尾用
   `DPH_TxOffsetNow(DPH_RunElapsed())`），而 `$F` 在 READY 显标称频率 → 屏与芯片差几百 Hz～几 kHz。
   本轮未动（用户裁定：只修 P0 + 功率）。

### 债

6. `doppler_layout.h:92` 注释写「按 5 进入信息页」，代码是 `KEY_0 → sub=3`（改它要重编固件）。
7. `hold_off` 名不副实：存的是 Hz 偏移，不是标志位。
8. `DPH_PostListen()` 与 3 s DONE 窗口在无手机路径上永远走不到。
