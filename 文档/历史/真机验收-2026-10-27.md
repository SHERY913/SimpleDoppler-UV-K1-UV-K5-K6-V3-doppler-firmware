# 真机验收 · 2026-10-27 深夜（COM7 / 新固件 102,308 B）

对象：用户已刷入的固件 `f4hwn.sstv.doppler.bin`（102,308 B，md5 `0cf5e137d2812fb988ee3c22fc101fdb`），
串口 COM7 @ 38400，脚本在 `.gtmp/`（`hw_test.py` / `hw_t4.py` / `hw_t5.py` / `hw_soak.py` / `hw_failsafe.py`）。

先说一句现场事实：`find_port.py` 把 COM7 判成"MuMu 虚拟串口"（VID 36B7），但实测这条口
能收到电台回包、能改频率、能触发防呆，**就是电台本身**，那个 VID 判据不可信，已列入待修。

## 三处"你以为有、其实没有"的坑

1. **`0x0601` 的回包 ID 是 `0x0601`，不是 `0x0602`。**（`uart.c:717` `reply.header.ID = 0x0601;`）
   按"命令+1"等回包的脚本一律超时——我第一次测守卫就栽在这。
2. **`0x0602` 写完没有任何回包**，别等。
3. **`0x0770` 的单位是 100 Hz**（`Frequency/10`，Frequency 是 10 Hz 单位），而推帧 `0x076C` 里是
   10 Hz 单位。同一个数差 10 倍：推 `14580000` → 读回 `1458000`。App 侧已不再使用这条命令，
   所以不影响使用，但谁以后拿它做"手调检测"会立刻踩坑。

## 我自己写错的两次（如实记）

- 第一次推帧只有 24 B，固件 `DOPPLER_ExtPush` 有 `len < 28` 直接 return 的门槛，整帧被丢掉；
  回包里 `state=0` 就是这个原因，**不是固件不认接管**。补齐到 36 B 后一次通过。
- 第二次用 `parse_replies()` 时把返回的 list 当单个对象用，脚本自己抛异常。

## 结论

固件这版在真机上**核心链路全通**：认得出新命令、守得住 REG_3B、接管能生效、推频点能落地、
拔线能自己退回操作员信道。剩下两项（ppm 是否真进 PLL、磁场环境罗盘稳不稳）只能人上机听/看，
串口给不出答案。

## 上面那三处已经改掉（2026-10-28 00:0x，等下一版固件刷入后复验）

| 原来 | 现在 | 位置 |
|---|---|---|
| `0x0770` 回 `Frequency/10`（100 Hz 单位），与推帧的 10 Hz 差 10 倍 | 直接回 `Frequency`（10 Hz），推 `14580000` 就该读回 `14580000` | `uart.c` `case 0x0770` |
| `0x0601` 回包 ID 写成 `0x0601`（等于请求 ID），按约定等 `0x0602` 的主机一律超时 | 回包 ID 改成 `0x0602`（**原厂 PC 工具若按 0x0601 匹配需同步改一行**；App 不用这条） | `uart.c:CMD_0601_ReadBK4819Reg` |
| `DOPPLER_ExtPush` 要求 `len >= 28`，短名星（"ISS" = 24 字节）整帧静默丢弃 | 门槛改成真实布局下限 `21`，名字长度按实际 `len` 收紧；App 仍补零到 28（兼容旧固件） | `doppler.c` ExtPush 入口 |

配套改的检查：`verify_layout.py` 原来硬比"固件 28 == App 28"，现在比"App 补零后长度 ≥ 固件下限"，
并改用 `|| len <` 定位固件那句（旧正则会把注释里的 "len < 28" 当成代码读，白绿一次）。

另外顺手改了：`find_port.py` 不再拿 VID 36B7 当"虚拟口"降权 —— 改成**发 0x076A 探针**看有没有
`0x076B` 回包，实测这条判据才拦得住"看着像串口、其实不转发"的情况。
