## 二、E6 侧键一在就绪页也发射，而且关不掉

### 2.1 三条独立的事实，各自有代码证据

**(a) READY 本来就在准入里 —— 交接-29 没动它。**

`App/app/doppler.c` `DOPPLER_KeySide1()`（改动前）：

```
if (!(phase == DPH_RUN || phase == DPH_READY || phase == DPH_EXT
      || phase == DPH_PRE || phase == DPH_POST)
    || !haveUp || (phase == DPH_EXT && DPH_EXT_RXONLY()))
```

交接-28 报的是"侧键一在跟踪页切了频点却不起发"，所以当时只查了"为什么不起发"，
准入相位一个字没动 —— 就绪页能发射是**一直如此**，只是以前 `ptt_down` 残留成
`true`（E1），侧键一根本走不到发射那一步，这个洞被挡在后面。

**(b) 载波收不掉：`DPH_So50Release()` 的判据被自己写脏。**

改动前：

```
if (ptt_down) { if (gCurrentFunction == FUNCTION_TRANSMIT) RADIO_SetTxParameters(); }
else          { DPH_PttEvent(false); }
```

而 `ptt_down` 是在 `DPH_PttEvent()` 的准入块里写的：

```
tx_hold  = bKeyPressed;
ptt_down = bKeyPressed;      /* 按下侧键一时这里被写成 true */
...
GENERIC_Key_PTT(bKeyPressed);
```

链条：按侧键一 → `so50_tx=true` → `if (!ptt_down) DPH_PttEvent(true)` → 准入块把
`ptt_down` 置 `true` → 松手 → `DPH_So50Release()` 看到 `ptt_down == true` →
判成"PTT 还按着，只把亚音换回来" → **没有任何人调 `GENERIC_Key_PTT(false)`**。
`ptt_down` 本来的语义是"**物理 PTT** 还按着"，此刻按着的是侧键一，两件事被同一个
变量表达了。

**(c) DTMF 键音是 (b) 的后果（推测，非直接证据）。**
载波还在出，主固件的按键处理在发射态下会回 DTMF（`App/app/app.c` 发射分支里
`KEY_SIDE2 → Code = 0xFE` 那条同源）。所以"关不掉 + 按键听见 DTMF"是**同一个**
故障的两个表现，不是两个 bug。

### 2.2 本轮改动（已落盘，未编译）

- `doppler.c` 准入相位去掉 `DPH_READY`（只留 RUN / PRE / POST / EXT）：
  就绪页按侧键一 → 双响拒绝。EXT（手机接管）保留 —— 那条链路上侧键一是唯一的
  发射手，用户这轮没提，不擅自关掉。
- 新增 `static bool so50_own;`（`doppler.c:164`），按下侧键一且 `!ptt_down` 时置真
  （`doppler.c:3566`），`DPH_So50Release()` 开头取出后立刻清零（`doppler.c:3443-3445`），
  收尾分支改成 `if (ptt_down && !own) {…只换亚音…} else { if (own) ptt_down = false; DPH_PttEvent(false); }`。

## 三、E7 跟踪页 ▲▼ 改了原点，但屏上什么都不变

### 3.1 证据

`App/app/doppler.c` `DPH_RunElapsed()`（`:1635-1646`）把负值钳成 0：

```
if (el < 0) return 0u;
```

`DPH_DrawPage()` 里 `elapsed = DPH_RunElapsed()`，`$L`/`$P` 都拿它算（改动前）：

```
case 'L': { uint32_t secs = elapsed / 100u; uint32_t left = (total > secs) ? (total - secs) : 0u; … }
```

于是"提前开始"（`DPH_BeginRun()` 的 `t0_10ms += d * 100u` 让 el 为负）那一整段里，
`elapsed` 恒为 0，`$L` 恒等于**整趟长度**（真机照片上的 `-10:40`），`$P` 恒 0，
频率恒停在第 0 个样点。`DPH_StepKey()` 确实改了 `t0_10ms`，但**屏幕上没有任何一格
读 t0**，所以按 ▲ 往前挪 1 s、按 ▼ 往后挪 1 s，画面一个像素都不动。

**"没跳页"= 交接-29 的 E5 修复成立**（`(uint32_t)el >= total` 改有符号比较），
这条新报是 E5 修好之后才看得见的**下一层**：页面稳住了，才发现进度是死的。

### 3.2 本轮改动

`$L` 在 `phase == DPH_RUN` 时不用 `elapsed`，直接算带符号的 `el`：

```
int32_t  el = (int32_t)(SCHEDULER_GetTick10ms() - t0_10ms);
left = (el >= (int32_t)total10) ? 0u : (uint32_t)((int32_t)total10 - el) / 100u;
```

el 为负时 `left > 整趟长度`，语义正好是"距 LOS 还有多久"（提前量 + 整趟），
按 ▲ 就减 1 s、按 ▼ 就加 1 s —— **屏上会动了**。`$P`（进度百分比）保持钳在 0：
AOS 之前进度确实是 0，这一格不该为了"看起来在动"而说谎。

## 四、E8 侧键二在"表值恰为 67.0"的星上是死键

### 4.1 证据

`App/app/doppler.c` `DPH_CycleTone()`（改动前）：

```
cur_tone = (a->CodeType == CODE_TYPE_CONTINUOUS_TONE && a->Code < 50u) ? CTCSS_Options[a->Code] : 0u;

if (cur_tone == cur.ctcss10 && cur_tone != 0u)
    next = tone_ring[0];                 /* "表值 -> 67.0" */
else { next = tone_ring[0]; for (…) if (tone_ring[i] == cur_tone) { next = tone_ring[(i+1)%4]; break; } }
```

`tone_ring[4] = {670, 744, 1413, 0}`。当**表里的亚音本来就是 67.0** 时：
`cur_tone == cur.ctcss10 == 670` → 走特例 → `next = 670` → 写回同一个值 →
按一次不换、按十次也不换。真机照片上 `$Z` 印的正是 `T67.0`，与这条完全吻合。

交接-29 只删了 `up10 == 0` 那道早退，音环本身没查 —— 于是"纯接收星"那一半修好了
（s6 覆盖），"表值 = 67.0"这一半仍然是死键。

### 4.2 本轮改动

删掉那条特例，只留环查找（表值在环里就往下走一颗，不在环里落到环首 67.0）：

```
cur_tone = …;
next = tone_ring[0];
for (i = 0u; i < 4u; i++) if (tone_ring[i] == cur_tone) { next = tone_ring[(i + 1u) % 4u]; break; }
```

一圈仍是 670 → 744 → 1413 →（`next == 0` 且 `cur_tone == 1413` 那条规矩）→ 回到表值。

## 五、E9 版面：频偏贴信号表、`STEP`/`BW` 常驻

### 5.1 约束是硬的（重叠检查算出来的）

- `$O Hz` 右对齐到 127，最坏 9 格 36 px → **91..126**；
- `$C` 右对齐到 95，占 **63..94**；
- 两者在 91..94 上真会碰 → `$O` 只能待在 **32..37** 这 6 条线里；
- 上面粗体 `$D`+`dB` 在 y=25 时占 **25..31** → 与 `$O`(32) **0 空行**，这就是
  "稍微重叠"的全部来源。

所以"把频偏再往下"物理上做不到（下面就是 `$C`），只能两头一起动：

| 项 | 改前 | 改后 |
|---|---|---|
| `$O Hz` | y=32 | y=33（33..38） |
| `$C` | y=38 | y=39（39..44） |
| `$D` / `dB` | y=25（25..31） | y=24（24..30） |
| 结果 | 0 空行 | 31、32 两条空线 |

`$D` 不能再往上一行：y=23 会压在 y=18 的 `$Z`/`STEP`/`BW`（18..23）上，重叠检查
当场报红（试过，已回退到 24）。

### 5.2 `STEP` / `BW`：不是间距问题，是"该不该常驻"

真机原话是"虽然不挤，但在这里太丑"。这两格是**一年改一次**的量，却占着最显眼的
一行。改法：

- 位置改成右对齐一栏，与 `$Z` 同一条右轨：`STEP $*s` 右端 75（最坏 `STEP 10s`
  43..75）、`BW $-` 右端 103（79..103）、`$Z` 右端 127（107..127），各留 4 px；
- **平时不画**：新增 `static uint32_t hud_until;`（`doppler.c:149`），`DPH_StepKey()`
  与数字键 1（换步进）各写一次 `hud_until = now + 300u`（`doppler.c:2691`、`:3743`），
  `DPH_DrawPage()` 里对含 `$*` / `$-` 的条目加一条 `continue`（`doppler.c:4973-4977`）。
  拧完露 3 秒，之后让位。

### 5.3 两侧一致性

`doppler_layout.h` 是 `layout_editor.html` 导出的，两边必须逐条相同：

```
cd 多普勒/PC工具/多普勒工具 && python verify_layout.py
  → 一致 36 · 告警 0 · 漂移 0（含"排版器 defaultModel 与固件排版表逐条一致（86 条 / 9 页）"）
cd 多普勒/tests/sim && python check_layout_overlap.py
  → 结果：OK（86 格 / 9 页，最坏串下无重叠、无出屏）+ 2 处已知贴边
```

这两条**是这轮唯一真跑过的东西**。
