## 二、D4　长按 M 进不了预听页

**现象**：按住 M 不放，屏幕上没有任何变化，直接就是跟踪页 —— 交接-25 里那个
"提前一分钟开静噪听折射尾巴 + 武装到 AOS 自动开跑"的主功能，在真机上一次都进不去。

**根因**（两条，缺一不可）：

1. `App/app/app.c:1869` 去抖完成那一拍就派发**短按** `ProcessKey(Key, true, false)`，
   而长按的 `(Key, true, true)` 要等到 `app.c:1884` 的 `key_repeat_delay_10ms` 之后；
2. `doppler.c` 的短按分支原样是 `DPH_BeginRun()` —— 当场开跑，`phase` 立刻变 RUN；
   等 held 到达时，长按块里的 `(phase == DPH_READY || phase == DPH_PRE)` 已经不成立，
   `auto_armed` 那行永远跑不到。

**改法**：短按不执行，只挂起。

```c
static bool menu_tap_pending;        /* doppler.c 静态区 */

/* DOPPLER_ProcessKeys() 松手分支（在 KEY_LOCK 判定之后、KEY_F 之前） */
if (Key == KEY_MENU && !bKeyPressed && menu_tap_pending)
{
    menu_tap_pending = false;
    DPH_BeginRun();
}
```

- 长按块一进来就 `menu_tap_pending = false;`（已经长按了，短按语义作废）；
- 短按 MENU 原 `DPH_BeginRun()` 改成 `menu_tap_pending = true;`；
- `DPH_Leave()` 与 `DOPPLER_Start()`（`fresh_entry` 分支）各清一次，挂起标记不带出页面。

**真机验证**：F+0 → 按住 M 两秒 → 屏幕应停在 `PRE-LISTEN` 页（不是跟踪页）；
按 EXIT 回就绪页；再轻按一下 M → 立刻进跟踪页。

## 三、D5　过境尾段回放一格

**现象**：整趟跟踪到末尾时，频率不是停在 LOS 那个偏移上，而是**往回跳一格**再走完最后一小段；
换句话说最后几十秒听到的是已经走过的时间点。屏幕上的数字同样会回跳一次。

**根因**：`DPH_OffsetAt()` / `DPH_AngleAt()` 里

```c
if (idx >= (uint32_t)(cur.pts - 1u))
    idx = (uint32_t)(cur.pts - 2u);      /* frac 没管 */
```

越界之后 `idx` 被钳到倒数第二点，`frac` 却照旧取模 —— 于是 `frac` 从 0 重新爬到 999，
在那一段里把最后一个样点区间**又插值了一遍**。写表方用
`n = max(2, int(total/step)+1)`（覆盖率 `(n-1)*step ≤ 过境时长`），只要时长不是步长的整数倍，
尾段就有一小截越界，所以这不是偶发。顺带：`frac == 0` 时取的是 `pts-2`，真正的 LOS 点从来没被精确显示过。

**改法**：越过末样点就钉住，不再插值：

```c
if (q >= (uint32_t)(cur.pts - 1u) * 1000u)
    return DPH_Sample((uint16_t)(cur.pts - 1u));      /* AngleAt 里是 DPH_SampleEl */
```

**真机验证**：跟一趟整的，在 LOS 前最后半分钟盯住屏幕：数字应当只单调收窄，
不再出现"往回走"的一次；末条频点应等于表里最后一个样点。

- 编译器 `zig cc`；`-D` 取自 `.gfw.py` 产出的 `.defs_full.txt`；只 shim 4 个头
  （`scheduler.h`/`driver/gpio.h`/`apps/app_overlay.h`/`audio.h`），其余用上游真头。
- 场景：`s1` 预听页松手、`s2` 就绪页松手、`s3` 功率还原、`s4` 整趟 600 s、`s1h` 长按 M 进预听。
- **阳性对照 5 条**（破坏修复 → 场景必须红）：① `doppler.c:904` 的 `last_freq = up;`
  ② `:3358` 的 READY 松手分支 ③ `:2777` 的功率块位置 ④ 尾段钉住 ⑤ 短按 M 改回当场开跑。
  对照在副本上打补丁，**固件源码零改动**。

**这套 harness 抓不到什么**（别指望它）：真实射频时序与 PLL 锁定时延；BK4819 寄存器物理含义
（桩只记语义量）；按键层的重复回调（`DOPPLER_KeySide1` 是直接调的，绕过了 app.c 的重复派发）；
