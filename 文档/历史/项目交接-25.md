## 二、修掉的三条真缺陷（新功能自己身上的）

上一轮我审交接-24 时列了 D1/D2/D3 三条，本轮全部落地。

### D1 发射中触到 `DPH_Tune` → 载波被改到接收频点

- **触发**：按着 PTT 等到 LOS（`doppler.c` 的 tick 里 `elapsed >= dur*100` 直接
  `DPH_FinishRun()` → `DPH_PostListen()` → `DPH_Tune(下行)`），或者按着 PTT 在就绪页
  连按 ▲▼ 换条目。
- **为什么是事故**：PLL 收发共用 `REG_38/39`，一写就把正在发的载波挪走，而且回不来。
- **改法**：新增
  ```c
  static void DPH_TuneSafe(uint32_t freq10)
  {
      if (gCurrentFunction == FUNCTION_TRANSMIT)
          DPH_RxShow(freq10);   /* 只改显示与 pRX，不碰 PLL */
      else
          DPH_Tune(freq10);
  }
  ```
  把 `DPH_BeginRun` / `DPH_PreListen` / `DPH_PostListen` / 就绪页换条目 四处
  `DPH_Tune` 全换成它。发射中只更新数字，真正的 PLL 回落在 PTT 松手那一拍
  （`DPH_PttEvent` 的松手分支）由 `radio.c` 的 `RADIO_SetupRegisters()` 完成。

### D2 手机交还控制权后，写频落进操作员自己的信道

- **链路**：`DOPPLER_SetExtControl(false)` 的 `released` 分支只在
  `table_ok && phase == DPH_READY` 时重新借 VFO。如果接管时没开推送页
  （`ext_page_on == 0`，这是明确支持的状态），相位一直停在 RUN/PRE/POST →
  不会重新借，而 `DPH_AudioRestore()` 已经把 `radio_saved` 置假 →
  RUN 分支的 `DPH_Tune` / `DPH_TxStore` 走的是**真正的 `gRxVfo`**，
  卫星频点被写进 `gEeprom.VfoInfo[]`，退页时 `DPH_AudioRestore` 又因
  `!radio_saved` 直接 return，操作员信道**永久被改**。
- **改法**：① 条件放宽成
  `table_ok && (phase == DPH_READY || phase == DPH_RUN || phase == DPH_PRE || phase == DPH_POST)`；
  ② 重新借 VFO 时按相位落频：`DPH_TuneSafe(DPH_Rx10WithOff(DPH_TxOffsetNow(DPH_RunElapsed())))`；
  ③ 另外补一条：`!was_ext_page && phase == DPH_DONE` → 也打回 READY/EMPTY
  （DONE 的 3 秒自动退页窗口在 tick 里要求 `ext_ctrl`，交还后永不到来，
  屏幕会冻在完成页）。

### D3 手动提前开始 → 整条曲线提前、整趟提前收摊

- **现象**：AOS 之前长按 M 进预听、再短按 M 开跑，会从数组第 0 点起跑；
  真正的 AOS 到来时已经跑到第 d 秒，LOS 时提前 d 秒结束。
- **为什么以前"只补一半"**：`DPH_BeginRun` 里只有
  `if (d < 0 && -d < dur) t0 -= -d*100;`（开始晚了才补），
  `d > 0`（AOS 还没到）完全没补；而 tick 里 `elapsed` 是 uint32，
  负值时回绕成一亿多。
- **改法**：① `DPH_BeginRun` 补
  `else if (d > 0 && d <= dur) t0_10ms += d*100;`（原点推到未来）；
  ② 新增
  ```c
  static uint32_t DPH_RunElapsed(void)   /* 有符号算，负的钳 0，超的钳 dur */
  ```
  替换 tick、`DPH_Progress`、`DPH_DrawPage`、PTT 按下、EXT 交还 五处
  `SCHEDULER_GetTick10ms() - t0_10ms`。

## 三、新增功能

### 3.1 步进可调（1 键）

`static uint8_t nudge_s`（0 视为 1），`DPH_NudgeTicks()` 返回 `nudge_s * 100` 个 10 ms 拍。
`DPH_StepKey` 的 RUN 分支改成按这个步长挪 `t0_10ms`，上界钳到 `total-1`，**下界允许负**
（模运算下负 el 等于把原点推到未来，不会回绕），所以往前挪过 t=0 之后
`DPH_RunElapsed()` 返 0、屏幕停在第一个样点，等真时刻追上来。
`DOPPLER_Start()` 里 `if (phase == DPH_OFF) nudge_s = 1u;` —— 每次进页回出厂值。
屏上 `$*` 在跟踪页显示 `S1s / S2s / S5s / S10s`。

### 3.2 SO-50 侧键一（74.4 Hz 按住发射）

- 74.4 Hz = `CTCSS_Options[3]` = 744（表在 `App/dcs.c:22`）。
- 把原来塞在 `DOPPLER_ProcessKeys` 里的整段 PTT 逻辑抽成 `DPH_PttEvent(bool)`，
  PTT 与侧键一共用 —— 这是关键，否则两条路径的"松手拉回"必然分叉。
- `DPH_So50Release()` 用**直写结构体**的方式还原（`pair[i]->CodeType/Code = so50_prev_*`），
  不走 `DPH_SetTone` —— 因为 DCS 无法用 CTCSS 表还原。
- 两键**可交叉**：`DPH_PttEvent` 里 `if (!bKeyPressed && so50_tx) { ptt_down = false; return; }`
  —— 先松 PTT 而侧键还按着，载波不停；反之亦然（`so50_tx` 抬起时才真正收）。
- 只在本页生效（`app.c` 用 `gScreenToDisplay == DISPLAY_DOPPLER || DOPPLER_Side1Held()` 拦截），
  `F + 侧键一` 组合键不受影响。
- 不做 5 分钟计时（用户明确：只发亚音）。

### 3.3 侧键二换亚音（四站环）

`tone_ring = {670, 744, 1413, 0}`，当前音等于写表那颗时下一站是 67.0，
一圈走完回写表那颗（`if (next == 0u && cur.ctcss10 != 0u && cur_tone == 1413u) next = cur.ctcss10;`）。
无上行（`cur.up10 == 0`）且没接管时双响拒绝。

### 3.4 3 键带宽

`DPH_CycleBandwidth()`：`BANDWIDTH_WIDE ⇄ BANDWIDTH_NARROW`，写
**`gRxVfo->CHANNEL_BANDWIDTH` / `gTxVfo->CHANNEL_BANDWIDTH`** ——
`FREQ_Config_t` 上没有这个成员，写 `pair[0]->CHANNEL_BANDWIDTH` 编译就报
`error: 'FREQ_Config_t' has no member named 'CHANNEL_BANDWIDTH'`（踩过）。
发射中用 `RADIO_SetTxParameters()` 重下滤波器+PA，否则 `BK4819_SetFilterBandwidth()`。
屏上 `$-` 印 `25k`/`12k`。

### 3.5 M 键语义重写

- 短按（READY 或 PRE）→ `DPH_BeginRun()`。
- 长按（READY 或 PRE）→ `DPH_PreListen()`，若 `phase == DPH_PRE && DPH_AosLeft() >= 0`
  再置 `auto_armed / auto_prepped / auto_alert = 0`。
  用 `DPH_AosLeft()` 判"时钟可信"是因为它在 `!clk_valid || clk_days == 0` 时返 -1，
  不必另找标志；`DPH_PreListen()` 在 `!table_ok` 时早退，此时相位仍是 READY，
  不会误武装。
- 武装的**时间门槛从来不是 60 秒**：`left <= 60` 只控制"提前开音频"那一跳。
- `$!` 变成相位感知：`ARMED` / `M RUN  HOLD:PRE` / `M RUN`。

### 3.6 F 长按键盘锁 + 小钥匙

- `DOPPLER_ProcessKeys` 开头 `if (gEeprom.KEY_LOCK && Key != KEY_F && Key != KEY_PTT) return;`
  —— app.c 的键盘锁闸门在**发射中整体放行**（给 DTMF 留的口），按着 PTT 时手指最容易
  误碰数字键，这一页自己再挡一道。
- `KEY_F && bKeyPressed && bKeyHeld` → `COMMON_KeypadLockToggle()` + `DPH_StatusRule()`
  + `ST7565_BlitStatusLine()` + 同步 `dph_prev_status`（差分刷新，不同步会漏画）。
- 钥匙图标必须自己补：主界面由 `ui/status.c:328` 画，多普勒页 `DPH_StatusRule()`
  把状态行换成一条横线且关了 `gUpdateStatus`，所以
  `if (gEeprom.KEY_LOCK) memcpy(&gStatusLine[LCD_WIDTH - sizeof(gFontKeyLock)], gFontKeyLock, sizeof(gFontKeyLock));`
  （`gFontKeyLock[9]`，`App/bitmaps.c:51`，贴 119..127）。
- **锁上之后连 EXIT 也不响应**，只有长按 F 能解开（app.c 闸门的既有行为，未改）。

## 八、已知未解决 / 下一轮可以接着做的

1. **手机 APK 写表不通**（样点区 0x3000 vs 固件 0x1000）。用户已明确"手机完全不管"，
   但这是**功能缺口**，不是可选项 —— 重新打包时必须一起改。
2. ~~74.4 Hz 下限风险~~ **已核查，不存在**：`BK4819_SetCTCSSFrequency()`
   （`App/driver/bk4829.c:546`）算 `控制字 = Hz×10 × 206488 / 100000`，74.4 Hz →
   `744×206488/100000 ≈ 1536`，写进 `REG_07 <12:0>`（13 bit，上限 8191），余量充足；
   函数里唯一的特殊值是 2625（=1050/4 Hz 检测模式），与 74.4 无关。
   **真正要注意的是用途分工**：AMSAT 的口径是 —— 74.4 Hz 只给星上 10 分钟定时器"开门"，
   窗口内通联要用 **67.0 Hz**（转发器的 PL），窗口里再发一次 74.4 续期。
   所以正确流程是「点一下侧键一唤醒 → 侧键二切 67.0 → PTT 通联 → 快到期再点侧键一」，
   **不是**"按住侧键一 74.4 一直说话"。使用说明 §3.3 已按这个顺序写清。
3. **侧键一长按连发（`bKeyHeld`）时按下/抬起是否成对**：app.c 的重复档只对 ▲▼ 派发
   快重复，所以理论上只派一次，但 app.c 的键盘锁闸门会先吃一遍，值得真机确认。
