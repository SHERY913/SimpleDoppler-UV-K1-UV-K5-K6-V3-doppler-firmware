## 1. 【高】信息页电池电压差 10 倍：8.28 V 印成 "82.8V"

`固件源码/uvk1-v6.3.0/App/app/doppler.c:3252-3256`

```c
case '=':   /* 电池电压。gBatteryVoltageAverage 的单位是 10 mV */
    n = DPH_Put(out, n, cap, "%u.%uV",
                (unsigned)(gBatteryVoltageAverage / 10u),
                (unsigned)(gBatteryVoltageAverage % 10u));
    break;
```

- `gBatteryVoltageAverage` 的单位由 `App/helper/battery.c:146-148` 定死：
  ```c
  gBatteryVoltageAverage = (Voltage * 760) / gBatteryCalibration[3];
  ```
  满电 ≈ `828`（= 8.28 V，10 mV/LSB）。
- 注释自己写着"单位是 10 mV"，但格式化用的是 `/10` 与 `%10`，等于按 **100 mV** 当整数位、**10 mV** 当小数位 → `828` 打成 `82.8V`。
- 对照状态栏 `App/ui/status.c:80-84` 同一份数据打 `%u.%02u`（`voltage/100` 与 `voltage%100`）→ `8.28`。**同一个电池，两个页面差 10 倍。**
- 布局位置：`App/app/doppler_layout.h:71` `{ 6, 0, 0, 2, 33, "PH $? $= $J" }`（INFO 页第 3 行）。

**严重度：高**（一眼可见的硬错，且容易被当成"电池坏了/固件乱码"去查硬件）。

**验证**：进 INFO 页（page6，按 5 进入），与状态栏右上角电压文字对比；或串口读 `0x0529` 原始 ADC/`gBatteryVoltageAverage`，屏幕值应为其 1/10。

## 2. 【高】`0x0774 → 0x0775` 回显"请求值"而不是"实际装进去的值"

`固件源码/uvk1-v6.3.0/App/app/uart.c:1545-1568`

```c
uint16_t tone10 = 0u;
if (pUART_Command->Header.Size >= 2u) {
    tone10  = (uint16_t)pUART_Command->Data[0];
    tone10 |= (uint16_t)((uint16_t)pUART_Command->Data[1] << 8);
}
DOPPLER_ExtSetTone(tone10);
{
    ...
    uint16_t Tone10;   /* 回显真正装进去的值，App 可对账 */
    uint8_t  State;
} Reply;
...
Reply.Tone10      = tone10;          /* ← 这里写的是请求值 */
Reply.State       = DOPPLER_ExtState();
```

而 `App/app/doppler.c:602-637`（`DPH_SetTone`）只认 `CTCSS_Options[]` 里的 50 个标准亚音：

```c
pTX->CodeType = CODE_TYPE_OFF;  /* 先清 */
for (i = 0; i < 50; i++)
    if (CTCSS_Options[i] == tone10) { CodeType = CODE_TYPE_CONTINUOUS_TONE; Code = i; }
/* 不命中：静默留 OFF，无任何回报 */
```

- 后果一：`tone10` 不在表内（例如 `2540` = 254.0 Hz、或手机按 0.1 Hz 精度发来 `670` 之外的边带值）→ 实际是**裸载波**，回包却说"已设 254.0 Hz"。
- 后果二：`DOPPLER_ExtSetTone()`（`doppler.c:639-651`）在 `radio_saved == false` 时**只记 `ext_tone_set/ext_tone10`、不立即写配置**，但 `0x0775` 照样把 `State` 与 `Tone10` 立即回出，App 认为"已生效"。
- 对照同一屏 `$Z`（`doppler.c:3154-3188`，已修）读的是 `DPH_TxCfgs()` 的真实 `CodeType/Code`，非法值显示 `T--` → **同一台机器上，屏幕说没有亚音、协议说已设亚音**。
- 文档与实际不一致：`文档/项目交接-8.md:30` 写"回显真正装进去的值，App 可对账"；`安卓App/.../RadioLink.kt:353-360` 也据此返回值判断成功。
- 加重情节：SO-50 / AO-27 这类必须亚音才开门的星，"以为设了 67.0 Hz、实际没开门"是**功能性失败**，不是显示瑕疵。

**严重度：高**（协议层谎报 + 卫星上行打不进去）。

**验证**：`0x0774` 发 `tone10=2540` → 回包仍是 `2540`，同时看屏幕 `$Z`；再按 PTT，用另一台电台解调看有没有亚音。

## 3. 【高】`pVfo->Band` 不随频率更新 → `$D` / S 表用错频段修正（已修例 1 的同类复发）

三处事实：

**(a) 多普勒侧只写频率，从不写 Band** —— `App/app/doppler.c:1090-1096`（`DPH_RxStore`）、`:1140-1157`（`DPH_Tune`）、`:1200`（`DPH_RxShow`）全部只动 `pRX->Frequency`；全文件 `grep` 无任何 `Band =` 赋值。

**(b) 显示侧用 `gRxVfo->Band` 查表** —— `App/app/doppler.c:2943`

```c
dbm = (int16_t)(BK4819_GetRSSI_dBm() + dBmCorrTable[gRxVfo->Band]);
```
`App/ui/main.c:1078-1081` 主界面同式，`App/misc.c:153`：
```c
int8_t dBmCorrTable[7] = {-15,-16,-10,-4,-7,-6,-1};
```

**(c) 但真正生效的静噪/功率用的是"现算的 band"** —— `App/radio.c:551`
```c
FREQUENCY_Band_t Band = FREQUENCY_GetBand(pInfo->pRX->Frequency);
```
（功率侧 `radio.c:617` 同）。而 `RADIO_ConfigureSquelchAndOutputPower()` 在 doppler 里只在 `AudioOpen`/`AudioRestore` 调（`doppler.c:1282`、`:1333`），**每次调谐不调**。

→ 从 145.800 的表项切到 436.795 的表项：
- 芯片在 436.795 收（`BK4819_SetFrequency` 只吃频率，`App/driver/bk4819.c:728-731`）；
- 静噪门限按 400 MHz 段 flash（现算 band）；
- 但 `$D` 的修正量仍是 `dBmCorrTable[BAND2] = -10`，而 400 MHz 应为 `-1`；
- **同一档信号，屏幕读数比实际情况低 9 dB**（50 MHz↔470 MHz 最坏差 14 dB：`-15` vs `-1`）。

已修例 1 修的是"漏加修正"，这里是"加错了段"——同一症状、不同根因。

**严重度：高**（S 表/$D 是"这台机器是死是活"的唯一数字来源；跨波段 9 dB 相当于 3 个 S 点）。

**验证**：接管状态下用手机把 `rx10` 从 145.800 改到 436.795，同一天线同一信号源，`$D` 前后应连续，实测会跳 9 dB 左右；同时用 `0x0528` 读 `REG_67` 原始值，按 `rssi/2-160+corr` 手算两个 band 的结果对比。

## 4. 【高】F_CAL 抹掉多普勒 ppm 校准，"校准已生效"仍照报

多普勒把 ppm 校准做成 `REG_3B` 上一段步进：

`App/app/doppler.c:391-423`（`DPH_ApplyXtalTrim`）
```c
base = DPH_XTAL_BASE + (int32_t)gEeprom.BK4819_XTAL_FREQ_LOW;   /* 22656 + 粗调 */
...
BK4819_WriteRegister(BK4819_REG_3B, (uint16_t)(base + (int32_t)steps));  /* steps = ppm*5.2005 */
```

但 F_CAL 菜单走的是另一条路：

`App/app/menu.c:155-158`
```c
void writeXtalFreqCal(const int32_t value, const bool update_eeprom)
{
    BK4819_WriteRegister(BK4819_REG_3B, 22656 + value);   /* 只叠粗调，steps 直接没了 */
```

- 触发链：操作员在 F_CAL 里动一格（`menu.c:1290` 显示的是 `gEeprom.BK4819_XTAL_FREQ_LOW`，与 ppm 完全无关的两个数）→ `REG_3B` 被改回"只有粗调"。
- 而屏幕上 `$>`（`doppler.c:3277-3286`）和 `0x0773` 的 `Ppm` 字段（`uart.c:1513-1528`，`DPH_PpmGet()` 读 flash 里 `DPC1` 记录）**仍然报原来的 ±ppm**。
- `doppler.c:459-466` 的注释承认 `0x0602` 能背后改 `REG_3B`，`uart.c:748-753` 也给了防护，**但 `menu.c:157` 这条自家路径没有防护、也没有重放**。
- 结果：0.19 ppm/步 × 最多 400 步 ≈ ±76 ppm 的校准，屏幕上"已校准 +62 ppm"，晶振实际只有粗调 → 435 MHz 上最多差 ~27 kHz，**过境跟踪会持续偏一个音调以上**。

**严重度：高**（静默毁掉校准，且显示层坚持说没问题；这是"表里不一"最典型的一类）。

**验证**：先在校准页写 `ppm=+60`（`DPH_SaveCal`），读 `0x0601` 回 `REG_3B`；再进 F_CAL 空按一次确认（值不变也算写一次），重读 `REG_3B` 应少 `60*5.2≈312`，而 `0x0773` 的 `Ppm` 仍是 60。

## 5. 【中】主界面 dBm 上钳 `-53`，过境页不钳 → 强信号两页差 6~10 dB

`App/ui/main.c:1106-1111`
```c
if (s_level == 9) {
    overS9dBm  = (uint8_t)MIN(rssi_dBm - (-93), 40);   /* 未钳值 */
    overS9Bars = overS9dBm / 10;
}
const int16_t display_rssi_dBm = (rssi_dBm > -53) ? -53 : rssi_dBm;   /* ← 硬钳 -53 */
```
`App/app/doppler.c:2943-2948`
```c

if (dbm <= -125) ... "<-125";  else "%d"
```

## 6. 【中】`0x0528` 的 RSSI 是原始寄存器，不是 dBm

`App/app/uart.c:575-586`
```c
Reply.Header.ID             = 0x0528;
Reply.Data.RSSI             = BK4819_ReadRegister(BK4819_REG_67) & 0x01FF;   /* 0..511 裸值 */
Reply.Data.ExNoiseIndicator = BK4819_ReadRegister(BK4819_REG_65) & 0x007F;
Reply.Data.GlitchIndicator  = BK4819_ReadRegister(BK4819_REG_63);
```
- 屏幕那一套是 `(rssi/2) - 160 + dBmCorrTable[band]`（`bk4819.c:398-401`+`misc.c:153`）。
- 于是同一次读数有**三套口径**：`0x0528` = `0..511` 寄存器值；屏幕/`$D` = 加了频段修正的 dBm；`0x0771` = 频率（10 Hz）。PC 工具/脚本若把 `0x0528` 当 dBm，误差可达 100+。
- 与"频段修正"叠加后更糟：`0x0528` 没有 band 信息，外部无法复现屏幕值（必须先知道 `gRxVfo->Band`，而它本身可能过期，见 #3）。

**严重度：中**（对外协议的可解释性；文档未标注单位）。

**验证**：同一天线，`0x0528` 读 `RSSI`，与屏幕 dBm 对比：`RSSI/2-160+corr` 应等于屏幕值，实测差值即 band 修正量。

## 7. 【中】`RADIO_ConfigureChannel` 的 "fix previously set incorrect band" 只算不写回

`App/radio.c:380`（先按信道属性写）
```c
pVfo->Band = band;          /* 来自 ChannelAttributes.band，且只夹到 ≤BAND7 */
```
`App/radio.c:485-486`
```c
// fix previously set incorrect band
band = FREQUENCY_GetBand(frequency);     /* 只改局部变量 */
```
- 局部 `band` 之后用于裁剪频率（`radio.c:488-491`），**但从不 `pVfo->Band = band`**。
- 所以"band 与频率打架"的信道（手工改过频率的 MR 信道、`FREQ_CHANNEL` 与属性不同步、跨波段复制来的信道）会让 `pVfo->Band` 保持错值 → S 表/`$D` 错段（同 #3 的显示后果），而 `radio.c:551/617` 的静噪与功率用现算值 → 又是两把尺。
- 相关：`App/app/main.c:643` 在手动输频时确实写了 `Band`，`App/app/aircopy.c:1121` 也写了 —— 说明"该写"是共识，`radio.c:486` 是漏写。

**严重度：中**（只影响数据本身不一致的信道，但一旦遇到就是静默的 9 dB）。

**验证**：造一个 145 MHz 内容、`attributes.band` 靠 400 MHz 的 MR 信道；切到它后看 `$D`/S 表与 `0x0528` 推算值是否一致；不一致即复现。

## 8. 【中】状态栏计时：TX 显示"剩余"，RX 显示"已用"，同一格两种语义

`App/ui/status.c:52-62`
```c
uint16_t t = (type == 0) ? (gTxTimerCountdown_500ms / 2)
                         : (3600 - gRxTimerCountdown_500ms / 2);
```
- TX 侧 `gTxTimerCountdown_500ms` 在 `App/radio.c:1335` 被置为 `((TX_TIMEOUT_TIMER + 1) * 5) * 2`（500 ms 单位，即 `(t+1)*5` 秒）并递减（`scheduler.c:72`）→ `/2` 得到**剩余秒**。
- RX 侧初值 `7200`（`App/app/app.c:791/1264`）、递减同样在 `scheduler.c:68` → `3600 - n/2` 得到**已用秒**。
- 即：TX 上是"还能说多久"（倒计时），RX 上是"已经听了多久"（正计时），显示格式完全一样。
- TOT 关闭时 `gTxTimerCountdown_500ms = 0`（`radio.c:1328`），于是 TX 恒显 `00:00` —— 看上去像"计时坏了"，实际是"没开超时"。
- 菜单侧口径是对的：`App/ui/menu.c:1189-1195` `seconds = gSubMenuSelection*5 + 5`，与 `radio.c:1335` 完全一致（此项**已核对无 bug**）。

**严重度：中**（长时间发射时容易把"剩余"读成"已用"，导致误判 TOT 是否生效）。

**验证**：TOT 设 1 分钟，按 PTT 观察状态栏数字递减；松开听 RX，同一格数字从 0 递增。

## 9. 【中】`$H` 变化率两套精度，同一格写 "km/s"

离线过境页（固件按表插值）—— `App/app/doppler.c:2904-2915`
```c
int32_t rate = (int32_t)DPH_RateAt(elapsed * 10u);   /* 0.1 km/s 单位 */
n = DPH_Put(out, n, cap, "%c%d.%d", sign, (int)(rate / 10), (int)(rate % 10));
```
接管页（手机推帧）—— `App/app/doppler.c:2804-2812`
```c
int32_t r = ext_rate01;                              /* 0.01 km/s 单位 */
n = DPH_Put(out, n, cap, "%s%u.%02u", sign, (unsigned)(a / 100), (unsigned)(a % 100));
```
- 量纲都对（`安卓App/.../MainScreen.kt:363` `rate01 = (lv.rateKmS * 100).toInt()`，表内样本 6 B 里 `rate` 是 int8/0.1 km/s，见 `文档/项目交接-4.md:152`），但**分辨率不同**：同一颗星、同一时刻，离线页 `-1.2`、接管页 `-1.24`。
- 布局只有一格（`App/app/doppler_layout.h` page1 的 `$H km/s`），两种模式共用 → 看起来像"接管后精度变好了/变差了"，也让人怀疑哪一个是真值。

## 10. 【中】功率档：`$Q` 印 `USER` 不印实际瓦数；固件里功率有 4 个读取点

## 11. 【中】静噪门限裸读 flash，`0xFF` 无哨兵判断

`App/radio.c:565-580`
```c
Base += gEeprom.SQUELCH_LEVEL;
```

**验证**：用 PC 工具把 `0x1E00` 那段擦成 `0xFF`，看菜单 `SQL` 是否仍正常显示、静噪是否失效；或串口 `0x0601` 读 `REG_6A/6B`（静噪寄存器）对比菜单档位。

## 12. 【低】接管无帧时"半屏 `--`、半屏真数字"
