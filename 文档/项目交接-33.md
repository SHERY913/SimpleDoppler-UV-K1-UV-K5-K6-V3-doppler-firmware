## 二、控频协议（把交接-32 §七.1 的笔误改对）

交接-32 写的是「0x0768 接管 + 每秒一帧 0x0770」——**0x0770 是读回 VFO，不是推帧**。
真实流程：

| 步骤 | 命令 | 回包 | body |
| --- | --- | --- | --- |
| 开页 | `0x076E` =1 | `0x076F` | 5（State 1 字节） |
| 接管 | `0x0768` =1 | `0x0769` | 5 |
| 推帧 | `0x076C` | `0x076D` | 5 |
| 读 VFO | `0x0770` | `0x0771` | 8（Rx10 u32） |
| 设亚音 | `0x0774` | `0x0775` | 7（Tone10 u16 + State u8） |
| 交还 | `0x0768`=0 → `0x076E`=0 | — | — |

要点（都踩过）：

1. **必须先开页再接管**。`doppler.c:2954` 起，ext_ctrl 真而 ext_page_on 假时
   固件有防呆会把控制权收回去，表现是「接管了却什么都没发生」。
2. 0x076C 帧布局（`DOPPLER_ExtPush`）：`rx10 u32 | tx10 u32 | dopp i16 |
   dist u16 | remain i16 | el01 i16 | rate01 i16 | progress u8 | flags u8 |
   nameLen u8 | name(nameLen≤8)`，`len<21` 整帧丢。
3. `ext_flags` bit0 数据有效 / bit1 过境中 / bit2 只收不发。
   **bit2 必须与 tx10 成对写**：有上行 → tx10≠0 且 bit2 清；纯收星 → tx10=0 且 bit2 置 1。
   否则 `DPH_EXT_RXONLY()` 判错，PTT 会被拦或者放行到错频。
4. 接管期上行频 = `up10 - hz2ten(tx_off)`，其中 `tx_off = off*up10/down10`
   （`doppler.c:DPH_TxOffset`，off 先夹 ±12000，int64 中间量）。App 侧照抄在
   `orbit/Tracker.kt:txOffHz`，单测盯了 `txOffHz(900,1459000,4378000)=299`。
5. `remain` 正 = 距 LOS 秒，负 = 还没过境（屏上印 `-MM:SS`）。

## 三、固件改了一处

`App/app/doppler.c` 外推段（原 2925-2937）：

- 节流 `>= 10u` → `>= 1u`（**100 ms → 10 ms**）。表内本来就是每 10 ms 写一次
  `BK4819_SetFrequency`，接管分支之前被这个节流卡成 100 ms，才显得"手机推的比电台自己跑的粗"。
- `DPH_PickFrontEnd(ex)` → `DPH_FrontEndHeal(ex)`。前者不看影子状态，10 ms 节奏下
  每秒白写 200 次 REG_33；后者用 `BK4819_IsGpioOutSet` 守卫。
- `gap 30..200`（300 ms~2 s）与 `span 10..500` 的门槛**没动** —— App 400 ms 推一帧正好落在里面。

## 四、验收结果（真机：iQOO Neo3 / 2c611462 + COM7 真电台）

链路：`手机 → adb reverse tcp:7878 → PC serial_bridge.py → COM7 → 电台`。

| 级 | 判据 | 实测 |
| --- | --- | --- |
| ① 单测 | 逐点复算 PC 金样本 | 771 点 rx10/tx10 **各翻 0 格**，峰值 6.84 km/s |
| ② VFO 回读 | 0x0770 读回与界面差 <50 Hz | **连续 21 次采样全 0 Hz** |
| ③ 长跑 | 连推 10 min 不掉接管 | 00:44:51→00:56:14（11 min 23 s）**1811 帧**，`接管中` 21/21，0 次重连，RTT 5~17 ms |

单测总量 22 项，`bash verify.sh` 全绿（`--rerun` 防止 FROM-CACHE 假绿）。

**没验到的**：
- ②/③ 是在「卫星在地平线下 + 只收星」和「过境中 + 收发星」两种状态下各跑了一轮，

## 五、这一轮最大的坑：桥接（`serial_bridge.py`）

症状：跟踪页永远卡在 `电台没有响应（0x076A，已收 0/4 字节）`；
换一次又变成 `回包头不对：cd 07 00 7d`。

定位过程（值得记）：直接串口 `doppler_tool.Link('COM7').ask(0x076A)` 一切正常 →
写了个 `fake_radio_tcp.py` 假电台，App 连它完全正常 → 问题锁死在桥上。
真因有三层，全在桥上：

1. **端口每个 client 开关一次**。关闭句柄时正挂着 overlapped read，pyserial 的
   `_overlapped_read` 变成 None，之后每次 `read()` 抛
   `TypeError: byref() argument must be a ctypes instance, not 'NoneType'`，
   读线程当场死掉 → 能发不能收。**改成全程只开一次**。
2. **每个 client 一个读线程**。「踢旧 client」只是 `stop.set()`，旧线程还卡在
   read 里，新线程已经开跑，一帧 13 字节被两边分食 → 少掉开头的 `ab`，
   App 报「回包头不对」。**改成全局唯一读线程，只换它写往哪个 socket**。
3. `listen(1)` + 串行服务 → App 断链重连时新连接直接被拒（WinError 10061），
   表现为「重连要等好几秒」。**改成 `listen(8)` + 新 client 到了主动踢旧的**。

另外 `read_some()` 现在把 `TypeError` 翻成 `OSError("overlapped read 句柄已失效")`
走重开，`pump` 层加 `except Exception` —— 读线程不能再有"死法"。

排查工具留在仓库里：`fake_radio_tcp.py`（假电台，按真帧格式回
0x076B/0x076F/0x0769/0x076D/0x0771/0x0775）。**App 侧出问题时先连它**，
一次就能分清是 App 的错还是链路的错。

## 八、附录：从交接 31/32 里留下来的东西

31/32 已删（内容被这份吸收）。下面这些是它们里**仍然有效**的部分。

### 8.1 表格式 v5

```
表区   0x162000 .. 0x172000   64 KiB，每扇区 4096 B
表头   16 B : "<4sBBHII"  DPT1 | ver=5 | count | hdr=16 | data_off | hdr_date
条目   40 B : "<16sIIIHHHHHBB"  name | freq10 | data_off | up10 |
                               aos2 | dur | npts | step_ms | ctcss10 | day_idx | max_el
样点    6 B : "<hBHb"  off_hz(int16) | el(u8) | range_km(u16) | rate_ds(int8)
样点区 SAMPLE_OFF = 0x1000（表镜像永远 ≥ 4096 B）
```

- `freq10` / `up10` 单位 **10 Hz**（437.55 MHz → 43_755_000）。
- `aos2` = 本地**秒/2**，先把 AOS 向上取整到偶数秒再除 2，否则整条曲线平移 2 s（437.8 MHz 上 248 Hz）。
- `hdr_date = ((year-2000)&0x7F)<<9 | (month&0xF)<<5 | (day&0x1F)`；`day_idx` 4 bit，上限 15 天。
- `dur > 1500` 抛错；`step_ms` 下限 5000（历史上写成上界 → 「构表成功、写表被拒」）。
- 表头剩余**补 0，不能补 0xFF**（`verify_layout` 会把 0xFF 判成脏表）。

### 8.2 串口帧（修正版，实测为准）

```
AB CD | SIZE(2) | masked body | CRC16(2) | DC BA
body   = ID(2) + 载荷 (+ 2 字节补齐)      ← SIZE 数的就是这一段
masked = body ^ MASK[i%16]，CRC 算在未混淆的 body 上，脚标 = 掩码后的 CRC + DC BA
回包 ID 必须 == (发送 ID + 1) & 0xFFFF
```

- **帧头后面紧跟的是 SIZE，不是 ID** —— 交接-32 写成「ID(2) SIZE(2)」是错的，
  按那个顺序解出来的长度永远对不上。
- `ask()` 的 expect 是 **body 字节数（4 + 载荷）**，不是载荷长度。
- `UNLOCK_TOKEN = 0x31555044`（"DPU1" 小端）。

### 8.3 擦除状态码

`0 OK / 1 BADPARAM（地址没对齐、越界、正在发射）/ 2 FLASH（芯片写失败）/
3 VERIFY（回读不一致）/ 4 OCCUPIED（这块地是别人的，拒擦）`。
**擦除必须从高地址往低地址**（`sectors.sortedDescending()`），否则撞 code=4。

### 8.4 Kotlin / Compose

- `Modifier.clickable(enabled = false)` **会把整个手势节点摘掉**，adb 点上去连水波都没有 →
  一律保留节点、在 lambda 里 `if (enabled) onClick()`。
- **尾随 lambda 只能匹配最后一个参数**：`GhostButton(text, width = 0, onClick = {})`。
- `var station` 的属性 setter 与 `fun setStation(...)` 同 JVM 签名 → `Platform declaration clash`，改名 `useStation`。
- `break` 不能写在 `try/catch` 表达式里（被当 lambda 非局部跳转）。
- 点星图要 `pointerInput { detectTapGestures { tap -> } }`，`clickable{}` 的 lambda 没有坐标。
- 字符串里嵌英文双引号直接语法错，用中文引号「」。

### 8.5 usb-serial-for-android 3.7.0

`javap` 实测 `UsbSerialPort` 只有 `open/read(byte[],int)/write(byte[],int)/setParameters`。
**`read(byte[], int)` 第二参是超时毫秒，不是长度**，传长度会立刻返回 0。

### 8.6 adb / vivo

- adb 起不来是写 `%TEMP%\adb.log` 被拒：`export TMP=$TEMP=<ws>/_shots/tmp`。
- Git Bash 必须 `export MSYS_NO_PATHCONV=1`，否则 `/data/local/tmp/x.apk` 被改写成 Windows 路径。
- **`input swipe` 起点 x=50 会触发 vivo 侧边返回手势**，把 App 关掉；拖滑条从 x≥300 起手。
- 装机：`pm install -r -t` 后台跑 → 等 14~20 s「vivo 正为您云端检测风险」→ 勾复选框
  → 「继续安装」变蓝后 `input tap` 生效；tap 没反应再退键盘 `61 61 61 66`。
  成功判据只看 `dumpsys package com.f4hwn.doppler2 | grep lastUpdateTime`。
- 前台被 `com.vivo.easyshare`（互传）占着时安装页弹不出来，先 `am force-stop`。
- **截图目测坐标经常差 100+ px**（Compose 重排），一律先 `uiautomator dump` 拿真实 bounds 再点。

### 8.7 数值对齐（每一处都是静默分歧）

- Python `round()` 是银行家舍入，Kotlin 用 `kotlin.math.round(x).toInt()`（ties-away）。
- `rateDs` 夹 **±70**，不是 ±128。
- 过境搜索**穿越门限恒 0°**，`minEl` 只过滤 maxEl。
- 找到一趟后 `prevEl = elAt(los)`；写成 `0.0` 会静默吞掉紧跟的下一趟。
- maxEl 用抛物线插值，取采样点最大值在 10 s 间隔下差零点几度，而它决定电台收不收这趟。

### 8.8 目录与版面

- 固件 BK4819 实收 **1.8 MHz ~ 1300 MHz**；最终目录 1071 颗，其中「固件能收」627 颗（列表默认只显示这批）。
- CelesTrak 有 2 小时限速，重复下载返回纯文本 `GP data has not updated since...`，脚本必须检测。
- 版面：`PC工具/多普勒工具/layout_editor.html` 排版 → `gen_layout.py` 生成
  `固件源码/…/App/app/doppler_layout.h`。**那是生成物，不许手改。**
