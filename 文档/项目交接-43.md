## 3. 本轮 App 线做了什么（12 项，全部落盘 + 装机）

### 3.1 USB 直连（这一项最费劲，结论要记住）

**现象链**：手机直连电台 → 报"没找到串口设备"→ 换 OTG 转接头后电台冒蓝灯（USB 已枚举）→
App 报 **`0x076A` 没有响应**。

**已经排除掉的假设（别再查一遍）**：

- **组帧错了？不是。** PC 的 `radio_proto.py` 和 App 的 `RadioProto` 对 0x076A 生成的帧**逐字节相同**：
  `AB CD 04 00 7C 6B 14 E6 C7 25 DA BA`（12 B）。
- **DTR/RTS 让它不回话？不是。** 固件 `Middlewares/CherryUSB/class/cdc/usbd_cdc.c:53` 只把 dtr 存进变量，
  `:115 usbd_cdc_acm_set_dtr` 是 `__WEAK` 空实现，不拦发送。
- **权限框没结果？是旧 bug，已修。** 旧代码 `RadioBus.kt:78` 把 `requestPermission(dev, null)` 的返回值丢掉、
  直接 `false`，用户点"允许"App 也已经当失败处理了。
- **第三方串口库能读？不能。** 它 open 时先发 `SET_LINE_CODING`，固件返回 -1，恢复路径把读请求排空了。

**关键证据（朋友那台 Xiaomi 24117RK2CC / Android 16）**，App 的「USB 自检」打出来的：

```
设备 1 台 36B7:FFFF 接口数=2
接口[0] class=0x02(COMM) 端点 0x83 INT IN
接口[1] class=0x0A(DATA) 端点 0x02 BULK OUT 64B / 0x81 BULK IN 64B
claimInterface(1)=true
OUT 12B  AB CD 04 00 7C 6B 14 E6 C7 25 DA BA
IN  15B  AB CD 07 00 7D 6B 17 E6 29 91 0D 76 7A DC BA
```

**解法：不用那个库，自建 CDC 通道。** 落到：

- `link/CdcLink.kt:29 class CdcLink` —— 按 `USB_CLASS_CDC_DATA(0x0A)` 找数据接口、`USB_CLASS_COMM(0x02)` 找控制接口，
  裸 `bulkTransfer` 收发；`SET_LINE_CODING` / `SET_CONTROL_LINE_STATE` 用 `runCatching` 包住（固件返回 -1）。
- `link/CdcRxBuffer.kt` —— 收字节暂存（`read` 带 deadline）。
- `link/UsbPerm.kt:46 suspend fun request(...)` —— `PendingIntent.FLAG_MUTABLE` + 包内广播 + 12 s 超时，
  返回 `GRANTED / DENIED / NO_ANSWER`，**先注册 receiver 再 requestPermission**。
- `link/UsbProber.kt` —— 在 `getDefaultProbeTable()` 上补 `0x36B7/0xFFFF → CdcAcmSerialDriver`，
  另加 CH340 / CP2102 / FT232 / STM32 VCP。
- `link/RadioBus.kt` —— `RawThenLibrary(raw, library)`：**只在 `raw.open()` 抛异常时**才回落到库。
  `Prefs.cdcDirect` 默认 true（设置页有个「USB 直连（自建 CDC，实验）」开关）。

**物理层结论（别再让操作员试 C→C 线）**：电台 C 口**没有 CC 下拉电阻**，C→C 线插上电台不充电也不枚举
（`dumpsys usb` 里 `host_manager num_connects=0`，`/sys/class/tty` 没有 ttyACM*）。
唯一可行：**C 公→A 母 OTG 转接头 + 原 A→C 数据线**。他手上那个白色"120W"块是**充电头**
（PC 上 `Get-PnpDevice` 看不到 `VID_36B7&PID_FFFF`、COM 口为空），要买的是**带数据的 OTG 转接头**。

## 6. 环境坑（每条都踩过，别再踩）

1. **`adb` 必须指 TMP**：不然 `cannot open C:\Users\…\Temp\adb.log: Permission denied`。
   无线 `192.168.0.7:5555` 和 USB `2c611462` 会轮流掉线，动手前先 `adb devices`。
2. **`input tap` 要用实际坐标**：`screencap` 是 1080×2340，模型看到的是 872×1890 的预览，
   换算 ×1.2389。点错一次会点进拨号盘/通知栏。
3. **`deploy.py` 才是装机入口**：vivo 有云检，`adb install` 必被拒；deploy 会自动点掉"继续安装"。
   失败时看它打印的三段：屏幕是否点亮 / 前台是否被抢占 / 再试一次。
4. **`build.bat` 把 gradle 输出重定向到 `_shots/tmp/`**：这个目录不存在，命令直接失败（只打 cmd banner）。
5. **禁止 `cmd ... | tail` 起后台任务**：`tail` 永远等不到 EOF，我因此卡掉一个 agent（19 步、38 分钟空转）。
   要后台就用 `run_in_background`，别用管道。
6. **微信发不了文件**：操作员装了「高三定时锁屏程序」，到点全屏接管、**键盘鼠标带钩子**，
   自动化（`SendKeys` / SetForegroundWindow）全部无效。锁屏时只能把包放桌面，等解锁。
7. **Gradle 令牌制**：多个 agent 并行时，写代码可以并行，`build.bat` 必须串行（一个令牌）。
   `_shots/tmp/build.log` 会被覆盖，别拿它当证据；读 `test-results/*.xml`。
8. **消息驱动的 agent 会"假活"**：`interrupt_agent`/`send_message` 对已结束的 subagent 返回
   `active teammate ... not found`，这时重派一个新卡，别等。
