## 二、两个 P0

### P0-1　写表会把操作员自己的信道改掉，且无还原路径

`DOPPLER_ReloadTable()`（交接-13 P1-2 加的）不看状态就把条目装进来。
而 `DPH_LoadEntry` 会写发射频点和亚音，三个 Store 封装都是
`radio_saved ? 写私有副本 : 写 gRxVfo 本体` —— `gRxVfo` 本体就是
`gEeprom.VfoInfo[]`，会被存盘。

**触发**：新刷固件 → 开机从没进过多普勒页 → 手机/PC 连上写表 →
表头固定在最后写（`uart.c:1421`）当场触发重载 → 主界面信道变成卫星上行频点 +
表里那颗亚音，芯片被 `DPH_Tune` 真的调过去，操作员一存信道就永久落盘。
`DPH_AudioRestore` 因为压根没 `SaveRadio` 过，是空操作。

**这条路是 P1-2 开出来的**：修之前 `DPH_LoadEntry` 只有 `DPH_Enter` 一个调用点，
而 Enter 第一件事就是 `DPH_SaveRadio`（`doppler.c:1995` 那句注释就是在说这个顺序）。
`DPH_FinishRun` 里也数落过同一个洞，只是换了触发路径。

**改法**（`doppler.c:2033` 起）：
- `phase == DPH_OFF` → 只 `DPH_LoadHeader()` 刷新"有没有表"，条目留给下一次进页
- 页面开着但 `radio_saved` 为假（空表页 / DONE 页还原之后）→ 先 `DPH_SaveRadio()`
  再装条目，顺序与 `DPH_Enter` 一致（该函数幂等）

### P0-2　表里的发射频率没做范围校验

`DPH_LoadEntry` 只查 pts / step_ms / dur_s / data_off，**`freq10` 与 `up10` 一个字没查**，
下一行就把 `cur.up10` 塞进 pTX；`radio.c` 按 PTT 时拿 `pTX->Frequency` 直接
`BK4819_SetFrequency`，中间没有闸门。接收侧一直有（`DPH_Tune` 里 `DPH_Freq10Ok`），
发射侧没有。

半截表不是理论：这一轮之前才刚修完"擦除只验首字节""重复写落 old & new"
"缓存谎报扇区已空"三个会造成半截表的路径，而那 11 处一处都没上真机。

**改法**：`DPH_LoadEntry` 补两道 `DPH_Freq10Ok`（`up10 == 0` 是"只收不发"，合法放过）；
口径与接收侧一致（29–1300 MHz），**不趁机改成 BK4819 实际的 620 MHz** —— 那是另一条
已知待办，动了要三端同步。
另外把 tick 里一处裸写 `gRxVfo->pTX` / `gTxVfo->pTX` 改走 `DPH_TxStore`（`doppler.c:2585` 附近）。

## 四、PC 工具与自检层

1. **`doppler_core.py:_measure` 补采样原点对齐**。表里的 `aos2` 只存"当天秒数 / 2"，
   PC 从**真实 AOS**（带小数秒）起采、表头却向下取整 → 整条曲线提前最多 2 s，
   437.8 MHz 上 248 Hz。App 的 `PassCalc.kt:121-124` 10-28 就修了自己那一份
   （注释里写明这就是"表感觉不准"的老账），**PC 这份一直漏着**：同一颗星同一台站，
   手机写的表和电脑写的表对不上，谁也不报错。
   改法：`_measure` 里把 aos 四舍五入到偶数秒并从那一秒起采 —— 所有时区偏移都是整分钟
   （偶数秒），"偶数秒"这个性质与本地/UTC 无关，所以不必把 tz 传进来，
   `build_table` 里那句 `//2` 不用动就自动精确了。
2. **删掉两条永绿断言**（`verify_link_ask.py`）：`check("erase 不再抛 IndexError", True)`
   和 `check("erase 的 expect 是 9", "9)" in open(__file__).read() or True)`
   —— 后者 `or True` 恒真，而且 grep 的是**本文件自己**，`doppler_tool.py` 里的
   expect 改了也照绿。前者改成真的 try/except 接住异常判红。
3. **`verify_layout.py` 条目上限那条会假绿**：三端正则全失配时三个值都是 `None`，
   `len({None}) == 1` → 走 else → 打印"条目上限 = None（三端一致）"并算通过。
   本文件第 14 行自己写的原则是"解析不到 = 报错，绝不静默通过"，这条漏了。补 None → BAD。

## 五、审查里排除掉的（别再当 bug 找）

- **16 字节星名没有终止符会溢出** —— 不成立。`DPH_TakeName` 是
  `memcpy(name, cur.name, 16); name[16] = 0;`，缓冲区 17 字节，终止符补了。
  98 颗里确实有 8 颗名字 ≥16 字符（`HADES-SA (SpinnyONE)` 20），是截断显示不是溢出。
- **128 B 分块写表跨 256 B 页** —— 驱动自己会拆：`SectorProgram` 第一行就是
  `PAGE_SIZE - (Addr % PAGE_SIZE)`，且 physical 路径每次改完都 `InvalidateCache`。
- **tick 与 UART 抢静态变量撕裂** —— 不成立。两者同在 `APP_TimeSlice10ms` 主循环里
  顺序执行（`app.c:1918/1926`），显示读 `ext_*` 不会被 UART 打断。
- **回包长度算术、BankMap 七条路径、DMA 16 位长度、10 ms tick 回绕、
  `data_off` 越界、packed 成员非对齐** —— 逐条核过，都是干净的。
- **单位不变量**（频率全是 10 Hz）：全文再无 `*10`，`100000u` 只用于格式化。

## 六、下一轮候选（本轮判定"不改"，理由随条记）

按优先级：

1. **`DPH_ExtFreq10` / `DPH_Freq10Ok` 允许到 1300 MHz，BK4819 实际约 620 MHz**
   （交接-13 §6 第 5 条，仍未修）。本轮刻意不趁机收紧，因为三端要同步。
2. **`PY25Q16_WriteBuffer` / `SectorErase` 公开入口仍是 void**，失败连"剩余扇区"一起丢
   （`py25q16.c:345/454`，早退点 `:407/418/427/436`）。改它要动 EEPROM 写入语义。
3. **`ReadBufferPhysical/Safe` 丢掉 `WaitWIP()` 返回值**（`py25q16.c:308/340`），
   而 `:333-336` 的注释反过来说"先等 WIP=0"。超时后照样读 → 0x0764 读出乱值仍回 `Status=0`。
4. **0x0779 在发射中照样回"有效 dBm"**（`uart.c:1718`），而 `$D` 那格明确规定
   发射中无效印 `--`（`doppler.c:3407`）。操作员标定偏移量时正好把它当场核对成一次 PA 自激读数。
5. **RSSI 单读，改频后首读是陈值**（`radio.c:135`）：同仓 `chFrScanner.c:380` 与
   `spectrum.c:607` 都刻意丢弃第一读（AGC 还在过渡），这里没丢。
6. **`find_port.py:76` 探针逻辑坏掉**：迭代 `parse_replies` 返回的元组，首帧未收满时
   `r[0]` 抛 IndexError → 探针几乎恒假 → 落到"score≥50 直接用"，正是该文件注释里
   承认造成"写表写到别的串口"的老路径。
7. **`verify_table_live.py` 回读不验 CRC/脚标**、`probe_fw.py` 同样不验 ——
   这两个脚本的立身之本是"把字节读回来才算数"。
8. **`serial_bridge.py:169` 写超时后 `continue`**：pyserial 超时是**部分写入**后抛，
   丢掉的尾巴字节直接打烂字节流。
9. **VCP 回包会被静默丢弃**（`usbd_cdc_if.c:216`，IN 端点 IPR 未清时 `return -3` 没人看）：
   手机把 0x076C 与 0x076A 塞进同一次 USB OUT 包时，第二帧回包整帧消失而电台动作已生效。
10. **信号表那批"表里不一"注释**（`doppler.c:3432/3441`、`ui/main.c:1078`）还在说
    "3 点中位数 / 1.5 dB 迟滞 / 峰值保持 / 连续 2 s 无输出"，而 `radio.c:95-98` 明说这些
    全没实现。交接-13 只改了 `radio.h` 那一处。
11. **`$X` 校准页在合法量程内恒印 "1.0000"**（`doppler.c:3576` 附近）：小数位分辨率
    100 ppm 而量程只有 ±76，校完与没校长得一模一样，校准页等于没有反馈。
12. **武装倒计时被子页静默吞掉**（启动条件带 `sub == 0`，而 READY 下按 8/9/5 都允许）：
    武装后进校时/校准/信息页，到 AOS 不启动、不开音频、不响，屏幕还挂着 "ARMED"。
13. **`DPH_LoadCal` 不钳 `clk_ppm`**（`doppler.c:584`），而两处注释都断言"读写两条路都钳过"：
    旧固件写的 ±20000 记录读出来照用 → 信息页印 +200、0x0773 的 int8 截成 −56、
    REG_3B 实际按 76 走，同一事实三个数。
14. **App 侧 8 条**：写表全程没有 WakeLock/前台服务保护（锁屏可能擦完只写半截）、
    推帧 `join(80)` 超时后迟到回包仍写全局状态且不校验链路身份、
    `connectNet` 回调不 hop 主线程直接写 Compose 状态、`KeepAlive` 的锁只 10 分钟且
    第二次接管不重取、`fwInfoLine()` 不验回包长度（短帧 AIOOBE 被吞成"还是旧固件"）、
    亚音超时被判成"老固件"并把 `toneSent` 提前记为已发、Manifest 缺
    `USB_DEVICE_ATTACHED` intent-filter 与 `configChanges` 不全、
    `PassLog` 多个线程共用一个 `SimpleDateFormat`。
15. **三仓的 `.gitattributes` 还没钉 `.c/.h/.kt` 行尾**（主仓 10-27 那次假分叉同源，
    固件仓与 App 仓漏了；本轮编译时 git 已在警告）。

## 九、教训

1. **"补一个正确动作，会开出一个新入口"。** P1-2 加当场重载是对的，但它绕过了
   `DPH_Enter` 里"先 SaveRadio 再 LoadEntry"这个顺序约定 —— 约定没有变成代码里的
   断言，就等着被下一个入口违反。这一轮之后，隔离判断落在 `ReloadTable` 自己身上。
2. **发射侧和接收侧的闸门必须成对出现。** `DPH_Tune` 的范围校验存在了很久，
   而 pTX 那条路一个字没查 —— 同一个"坏表"，收的时候安全，按 PTT 就出界。
3. **两端各自修过的 bug，只算修了一半。** 采样原点那件事 App 10-28 修了并写了注释，
   PC 漏着，于是"两台机器写出的表不一样"这种谁也复现不了的症状又留了三天。
4. **自检里一条 `or True`，比少一条检查更坏。** 它让"8 层无 FAIL"这句话
   在它覆盖的那一项上完全不带信息量，而读的人无从分辨。
