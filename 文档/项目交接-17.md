# 项目交接-17

**日期**：2026-10-31 20:20　**基线**：项目交接-16（2026-10-31 19:35）
**这一轮的主题**：外部 flash 是**共享地盘**，过境表只是租客 —— 把"约定"变成"编译期必须成立的事实"

---

## 一、一句话结论

起因是一句"我这台机器有 1 主 + 4 多系统 + 中文字库，过境表还写得下吗、会不会破坏别的系统"。
查完发现：**你那 5 个系统和字库都在表区之下，碰不到**；但表区声明越进
Sonic 4K 互操作保留区 132 KiB，而 **PC 与 App 的擦除范围是从"表区大小"推导的** ——
那不是写坏，是**擦坏，不可恢复**。
本轮：表区 628→496 KiB、一次最多 64 趟、三条编译期断言、擦除前占位检查，
并修掉 App 里"界面说只收不发、芯片却装着上行频点"的档位分叉。
产物：固件 `85aa664f`、App **1.5**、`DopplerPass.exe`。

## 二、外部 flash 的真实布局（权威表在 `App/driver/mb_flash.h`）

2 MiB NOR，**没有文件系统**，每个功能自己认领一段地址，谁也不向谁登记。

| 地址 | 用途 | 结束 |
|---|---|---|
| 0x000000 | 配置 bank 0 | 0x010000 |
| 0x010000 | 校准 512 B / 开机 logo / 通联日志 32 KiB | 0x020000 |
| 0x020000 | **固件槽 0(备份)+1..4 = 你的 5 个系统**，各 128 KiB | 0x0C0000 |
| 0x0C0000 | 配置 bank 1..4（各 64 KiB，一槽一 bank 不串设置） | 0x100000 |
| 0x100000 | multiboot 状态标记 A/B（存"这次开机是哪个槽"） | 0x102000 |
| 0x102000 | 48 个 overlay app 槽；**中文字库/语音在 0x14C000** | 0x162000 |
| 0x162000 | ← **过境表从这里开始** | ~~0x1FF000~~ → **0x1DE000** |
| 0x1DE000 | **Sonic 4K 互操作保留区**，到 0x1FFFFF（136 KiB） | |

两个容易踩的点：

- **低段是分 bank 的**：`PY25Q16_SetBankBase()` 给 0x010000 以下的地址加偏移，
  同一逻辑地址在不同配置 bank 落到不同物理地址。`*Physical` 系列就是专门绕开这层的。
- **读数据没有索引**：表头地址是常量，条目靠 `base + 16 + i*40` 算术定位，
  样点用条目里存的**绝对 flash 地址**。所以"找最近一趟"（`DPH_FindNext`）只能把
  `count` 条全读一遍 —— 255 条 = 255 次同步 SPI 读塞进一个 10 ms tick。
  **收到 64 条顺带把这个隐患也压下了**（最多 64 读）。

## 三、本轮改动

### 1. 表区收缩 + 64 趟上限（三端同一个数）

| 端 | 常量 | 旧 → 新 |
|---|---|---|
| 固件 | `DPH_REGION_SIZE` / 新增 `DPH_PASS_MAX` | 0x9D000 → **0x7C000**；新增 **64** |
| PC | `DPH_REGION` / 新增 `DPH_PASS_MAX` / `SONIC_RESERVE_BASE` | 同上，9 处策略判断从 255 改走 64 |
| App | `MAX_TABLE_BYTES` / 新增 `PASS_MAX` | 同上；`DetailScreen` 的 `maxPasses` 80 → 64 |

**为什么是 64**：255 只是表头 `count` 那个 u8 的**格式**上限，不是"放得下"。
典型 LEO 过境（13 min / 2 s 采样 = 391 点）一条 2,386 B，255 条 = 606 KiB > 496 KiB。
64 条 = 165 KiB，落在 `0x18A600`，离那条线还有 320 KiB 余量；就算 20 分钟长过境也只到 `0x19E400`。

**格式上限 255 保留**（`DPH_ENTRY_MAX` / `ENTRY_MAX`，struct 打包还要用），
策略上限 64 是另一个数 —— 两个概念分开，别再混。

固件侧 `DPH_LoadHeader` 现在按 64 拒收（`dph_tbl_err = 4` → 屏幕 `BAD COUNT`）：
宁可什么都不播，也不能悄悄踩别人的地盘。

### 2. 三条编译期断言（这轮真正的价值）

| 位置 | 断言 | 拦的是什么 |
|---|---|---|
| `doppler.c` 头部 | `DPH_BASE_ADDR == APP_SLOT_BASE(APP_SLOT_COUNT)` | app 槽加一个，表就悄悄盖住第 49 个 app |
| `doppler.c` 头部 | `DPH_REGION_END <= MB_SONIC_RESERVE_BASE` | 表区（= 擦除上限）越进保留区 |
| `mb_flash.h` | `(MB_BANK_COUNT-1)*64KiB` 不得盖住状态标记 A | **加第 6 个系统** → bank 5 落在 0x100000，开机身份记录被踩 |

`MB_SONIC_RESERVE_BASE` 是本轮新命名的常量（原来只有注释里一句"0x1DE000 Sonic reserve"），
没有具名常量就没法断言。

**"多系统再多"的答案**：**5 个系统已经是满配**。配置 bank 现在
`0x0C0000..0x100000` 一格不剩，加到 6 个就会盖住 multiboot 状态标记 ——
那个后果比过境表越界严重得多（可能拒绝启动或认错主系统），
而且跟多普勒一点关系都没有，纯粹是布局没人统一管。现在它会**编译不过**。

### 3. 擦除前的占位检查（你那个直觉的可用版本）

`DPH_TableErase` 在擦**表头那一扇区**之前判一次：有 `DPT1` 魔数 → 是我们自己的旧表，放行；
全 0xFF → 没人用过，放行；既没魔数又非空 → **别人占着**，返回新状态码
`DPH_TBL_OCCUPIED = 4` 拒写。一次写表只扫 4 KiB，代价可忽略。

**为什么不做"每次擦除都扫一遍"**：重写时整段本来就不是空的（我们自己的旧表），
那种检查会把正常重写也挡住，最后一定被人关掉，等于没有。
它挡不住"别人把数据放在表区中间且不写魔数"——兜住那条的是上面的 `_Static_assert`
（表区根本够不着保留区）。**边界保证"够不着"，这道保证"真伸手前先问一句"**，两道一起才完整。

### 4. App 档位频率三处收成一处

`MainScreen` 推帧、接管确认弹窗、`Model.rxOf/txOf`（详情页与追踪页用）**各写了一遍**
"这一档用哪两个频率"，而且三份不一样。后果不是显示问题：

> 选「SSTV 只收」而这颗星没有 SSTV 频点时，推帧那份退回中继档、
> **把中继的上行频点推给电台**，而弹窗和详情页同时显示"只收不发 · RX ONLY"。
> 操作员以为不会发射，芯片里却装着一个按 PTT 就发出去的频率。

现在统一走 `Model.modeFreqs()`，返回 `rxMhz / txMhz / rxOnly / fellBack`；
`rxOf`/`txOf` 变成它的薄封装。状态行会写「直通→中继」这样的回退标记，
"这颗星没有上行"的提示只在**不是主动选的只收**时出现（SSTV 档本来只收，不重复唠叨）。

## 五、遗留

1. **校准记录仍在 `0x1FF000`（保留区内），没搬**。搬它会让已校准的电台丢值，
   而你说校准暂时用不上。收缩后它是多普勒唯一还留在那块里的 4 KiB。
   要彻底清掉就得先确认没人用校准，并做"读双写新"的迁移。
2. `DPH_TBL_OCCUPIED = 4` 是新状态码：**PC 工具的 `_writer` 把非 0 一律当失败并整遍重来**，
   遇到"真有主"的情况会重试到上限。方向是安全的（不会写坏），但会白跑一趟 ——
   下次动 PC 工具时给它一句人话提示。
3. 交接-15 §六那 15 条 + 交接-16 §七那 6 条仍然有效。头几条没变：
   BK4819 实际 620 MHz 上限没进闸门；`PY25Q16_WriteBuffer` 公开入口仍是 void；
   `ReadBufferPhysical` 丢 `WaitWIP()` 返回值而注释反过来说。
4. **App 那 8 条并发/生命周期问题一条都没动**（写表无 WakeLock、推帧迟到回包写全局状态、
   `connectNet` 后台线程写 Compose 状态、KeepAlive 锁只 10 分钟、Manifest `configChanges` 不全等）。
   本轮只做了"会导致电台做错事"的那一类。
5. 桌面快捷方式仍指向工作区里的 .bat（源码版，要本机有 Python）。

## 六、教训

1. **"表区多大"不是容量问题，是擦除范围问题。** 两端工具的擦除上限都从它推导，
   所以一个注释里的字面量能变成不可恢复的数据损失。声明得比需要大，
   在这个项目里的含义是"敢擦得比需要多"。
2. **共享地盘的所有者必须用编译期边界，不能用运行时礼貌。** 三个头文件各抄一份地址，
   没有任何东西保证它们不重叠 —— 这就是这次 132 KiB 越界的成因。
   具名常量 + `_Static_assert` 把"约定"变成"不成立就编译不过"。
3. **上限取保守值，并且要主动推演 N+1。** 用户问"再多几个系统会怎样"，
   答案是 6 个就坏，而且坏的是跟多普勒无关的启动记录。
   只看"现在够不够"永远看不到这种墙。
4. **同一个事实写几遍，就会在某一遍上出错。** 档位→频率这张表写三份，
   于是出现"界面说只收、芯片装着上行"。这已经是本项目第 N 次同一形状。
