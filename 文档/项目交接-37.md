## 六、罗盘（本轮核心，规格不许再改）

### 6.1 十一条规格（操作员口述逐条落实）

| # | 元素 | 规格 |
|---|---|---|
| 1 | 刻度盘 | 锁真北：刻度的「北」永远指向地理真北，手机转多少盘就反转多少。**数字与刻度一起转**（北转到盘底就是倒的，他接受） |
| 2 | 白色箭头 | 钉死在屏幕上边框那一侧（12 点），读「手机上边框现在的方位角」 |
| 3 | 红色圆圈 | 水平仪气泡：**往高的一侧跑**，半径 = sin(误差角)/sin(量程)，0° 在盘心、量程处压内圈 |
| 4 | 误差角 | 指向轴与「手机→卫星」连线的夹角；指向轴可设 `-Z 背面`(默认) / `+Z 正面` / `+Y 上边框` |
| 5 | 白色圆圈 | 准星（卫星本体不在盘上）：钉死盘心、直径固定、比红圈大一圈 |
| 6 | 无目标 | 退回**真水平面**（纯水平仪），准星降饱和 |
| 7 | 红横线 | 卫星方位：内圈外的短截、压在刻度上。三态 `起 349°`虚线 / 实时实线 / `下次起 12°`虚线 |
| 8 | 量程 | 15° / 30°(默认) / 90°，设置里选。**量程不是精度** |
| 9 | 对准 | 误差 ≤ 2° 持续 0.5 s → 准星变绿 + 震一下；出圈复位 |
| 10 | 读数 | 原 8 项全留 + 「误差」与「量程 / 指向」两格 |
| 11 | 夜视 | 准星用低饱和粉白 `0xFFE8CCCC` |

量程依据：2 m 段八木偏轴损失 ≈ `12×(θ/HPBW)²` dB；3 元 HPBW≈70°、5 元≈55° →
5°≈0.1 dB、10°≈0.4、15°≈0.9、25°≈2.5。30° 给"粗找星"，15° 给对表。

### 6.2 几何（改之前先读懂这三句）

1. **气泡位移 = 参照方向在「垂直于指向轴的那个平面」上的投影**；参照方向：有目标 = 卫星方向，
   没目标 = 天顶（所以变成水平仪）。
2. 指向轴 `-Z` 时那个平面就是屏幕平面，气泡取 `X/Y` 分量；`+Y` 时取 `X/Z` 分量
   （否则气泡只会左右跑）。
3. 误差 ≤90° 与 >90° 的 `sin` 相同、方向翻 180°：手机翻过 90° 气泡会从内圈往回走并翻到对面，
   这是水平仪的物理行为，**不要钳**。`backwards=true` 时红圈画空心、状态行写「指反了」。

代码：`CompassMath.kt`（纯逻辑）/ `CompassDial.kt`（传感器 + Canvas）/ `TrackScreen.kt`（三态横线 / 对准 / 读数）/
`AlignedLatch`（≤2° 稳 0.5 s 的判据本体，单独一个类就是为了有单测）。

### 6.3 真机踩过的四个坑

1. **矩阵的列才是设备轴**：`v_world = R · v_device`，`col j = (rot[j], rot[3+j], rot[6+j])`。
   旧实现取行，等于把"重力方向"当"手机指向"，竖立时方位错 180°。
2. **"平放却显示倾 179.5°"不是 bug**：加速度计读 `(0.11,0,-9.94)`、四元数 `w≈0`（绕水平轴 180°），
   两条证据同向 → 那台手机当时**屏幕朝下扣着放**。`col2 = (0,0,-1)` 完全正确。
   教训：`dumpsys sensorservice` 的原始值比截图更能定案，别看到数不对先改公式。
3. **无目标时不能用"指向轴 vs 卫星"的公式**：参照是天顶而 `-Z` 指天底，恒差 180°-倾角，
   屏上会写「指反了 102.7°」。现在两口径：有目标 `acos(p·target)`，无目标 `acos(FRONT·天顶)`。
4. **版面**：盘 300 dp 装不下（超 780 dp 约 69 dp，"记一笔/交还"被挤出去）→ 盘 264 dp +
   读数区 `weight(1f)+verticalScroll`；模拟模式剩余时间要用 `SimPass.remainS()`，不能算真 SGP4 窗口。

## 七、规矩（先读这一节，比技术细节重要）

### 7.1 操作员怎么工作

- **他不看长回复**（原话：「你埋头搞就行，不用给我输出太多文字，我一般也只看你给我提的问题」）。
- **决策必须做成选择题**：`ask_user_question`，一次一件，2~4 个选项，每个选项一句话写清代价。
- **提问要带实测数字**：「这个目录 144M，删了以后 `gradle assembleDebug` 要重跑 36 秒」比
  「要不要清理构建产物」有用一百倍。他会在两个数字之间做选择，不会在形容词之间做选择。
- **不汇报进度、不贴过程**：干完给一句话结果 + 一张表。
- **他反问是在纠你的用词**：问「这个目录是啥东西」= 你的提问里用了没解释的名词。
- **他会推翻需求**：一句「不应该是我在 APP 上勾选什么星，哪次过境，就写哪次吗」就把整个自动排表设计作废。
  这种推翻要**立刻接受、重做**，不要解释原来为什么那么设计。
- **他不在的时候别问**：说「先不干了 / 我睡了」就是真的停。

### 7.2 硬规矩

- 改固件 → 重编 → 换 `交付/` → 跑 `verify_all.sh --fast`，三件缺一不可。
- 每修一条缺陷，同时加一条 `tests/sim` 断言 + 一条 `negctl.sh` 阳性对照
  （删掉修复 → 场景必须红，放回去 → 必须绿）。**只有绿、没有红过的测试等于没有测试。**
- 版式文案与几何一律**照操作员的话**，不做"语义重解释"、不自己发明映射。
- 交付件是可再生产物：bin 的 md5 每次重编都变（镜像里编进 `__DATE__`/`__TIME__`），
  **md5 不是源码指纹**；认源码读 `0x0772` 回包（版本串 + ppm + proto + phase）。
- 构建产物、缓存、截图不进库；`临时/` 是清理目标，别往里放东西。
