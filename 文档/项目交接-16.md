## 二、审查结果与修复

### P0-1　写表会改掉操作员自己的信道，且无还原路径

`DOPPLER_ReloadTable()`（交接-13 的 P1-2 加的）不看状态就装条目，而 `DPH_LoadEntry` 会写发射频点和亚音，
三个 Store 封装都是 `radio_saved ? 写私有副本 : 写 gRxVfo 本体` —— 本体就是 `gEeprom.VfoInfo[]`，会被存盘。

触发路径很普通：新刷固件 → 开机从没进过多普勒页 → 手机/PC 写表 → 表头最后写、当场触发重载 →
主界面信道变成卫星上行频点 + 表里那颗亚音，PLL 真的被 `DPH_Tune` 调过去，操作员一存信道就永久落盘。

**这个洞是 P1-2 开出来的**：修之前 `DPH_LoadEntry` 只有 `DPH_Enter` 一个调用点，而 Enter 第一件事就是
`DPH_SaveRadio`。`DPH_FinishRun` 的注释早就数落过同一个洞，只是换了触发路径。

改法：`phase == DPH_OFF` 只刷新"有没有表"，条目留给下一次进页；页面开着但 `radio_saved` 为假
（空表页、DONE 页还原之后）先按 Enter 同一顺序 `DPH_SaveRadio`（该函数幂等）。

### P0-2　表里的发射频点没有闸门

`DPH_LoadEntry` 只查 pts / step_ms / dur_s / data_off，`freq10` 与 `up10` 一个字没查就塞进 pTX；
`radio.c` 按 PTT 时拿 `pTX->Frequency` 直接 `BK4819_SetFrequency`。
**接收侧一直有 `DPH_Freq10Ok`，发射侧没有。** 半截表不是理论——上一轮才刚修完三个会造成半截表的路径。

改法：补两道同口径校验（`up10 == 0` 是"只收不发"，合法放过）。
**刻意没趁机收紧到 BK4819 实际的 620 MHz**，那是另一条待办，动了要三端同步。
顺带把 tick 里一处裸写 `gRxVfo->pTX` / `gTxVfo->pTX` 改走 `DPH_TxStore`。

### P1 三处

| 位置 | 症状 | 改法 |
|---|---|---|
| `doppler.c` ExtPush 写 PLL 的闸门 | 判据是"手机推的**目标**变了没"，可芯片落的是**平滑后的中间值**：目标一不动（过境两端 10 Hz 量化下相邻帧同值很常见），屏幕每帧继续爬、芯片停在第一步，差最多 4 kHz 且不自愈 | 改成比 `shown != last_freq`，`ext_last_rx10` 跟着记已落盘值 |
| `uart.c` 0x076C | 不查长度就续串口倒计时并回 ack，而 `ExtPush` 内部按 `len<21` 丢帧 → 主机每 200 ms 收到"成功"，电台 5 s 后判它掉线自己交还 | `Header.Size` 不在 21..255 内**不续心跳**，回包照发、State 一个位不动 |
| `DetailScreen.kt:91` | 重算 key 里没有 `station`（列表页一直有）：改完台站回详情页，AOS/LOS/样点还是旧坐标算的，勾上就写进电台 flash，界面报"已写入" | key 补 `station` → App 1.3 |

### PC 工具与自检层三处

1. **采样原点三端对齐**：`doppler_core._measure` 原来从真实 AOS（带小数秒）起采、表头却向下取整，
   整条曲线提前最多 2 s（437.8 MHz 上 248 Hz）。App 的 `PassCalc.kt:121-124` 10-28 就修了自己那一份
   并写明这就是"表感觉不准"的老账，**PC 漏着** —— 同一颗星同一台站，手机写的表和电脑写的表对不上，
   谁也不报错。现在 `_measure` 里对齐到偶数秒；UTC 秒数的奇偶与本地一致（偏移都是整分钟），
   所以不必把 tz 传进来，`build_table` 那句 `//2` 不用改就自动精确。
2. **删掉两条永绿断言**（`verify_link_ask.py`）：`check(..., True)`，以及
   `check(..., "9)" in open(__file__).read() or True)` —— 后者 `or True` 恒真，而且 grep 的是**本文件自己**，
   `doppler_tool.py` 里的 expect 改了也照绿。前者改成真的 try/except 接住异常判红。
3. **`verify_layout.py` 条目上限那条会假绿**：三端正则全失配时值都是 `None`，`len({None}) == 1`
   → 走 else → 打印"条目上限 = None（三端一致）"并算通过，违反本文件第 14 行自己写的
   "解析不到 = 报错"。补 None → BAD。

### 审查里排除掉的（别再当 bug 找）

- **16 字节星名没终止符会溢出** —— 不成立，`DPH_TakeName` 是 `memcpy(name, cur.name, 16); name[16]=0;`，
  缓冲区 17 字节。98 颗里确有 8 颗名字 ≥16 字符（`HADES-SA (SpinnyONE)` 20），是截断显示不是溢出。
- **128 B 分块写表跨 256 B 页** —— 驱动自己会拆（`SectorProgram` 第一行就是 `PAGE_SIZE - Addr%PAGE_SIZE`）。
- **tick 与 UART 抢静态变量撕裂** —— 两者同在 `APP_TimeSlice10ms` 主循环里顺序执行。
- 回包长度算术、BankMap 七条路径、DMA 16 位长度、10 ms tick 回绕、`data_off` 越界、packed 非对齐 —— 逐条核过干净。
- 频率单位不变量（全是 10 Hz）：全文再无 `*10`。

## 三、第一次做出能发给别人的东西

起因是一句"我发给别人为什么跑不起来"。查清是三层原因：
桌面那个是**快捷方式**（里面是本机绝对路径）；bat 只检查环境不装 Python；
而且 `doppler_tool.json` 里存着作者自己的经纬度和 COM7，打包发人等于把别人的台站塞给对方。

### 打包时撞出一个真 bug（比 exe 重要）

`doppler_tool.py` 把**乌鲁木齐坐标 43.83 / 87.62 写死成默认台站**，而且两份：
`load_cfg` 的默认值里一份，`compute_next` 的 `cfg.get("lat", 43.83)` 兜底里又一份。
别人装上，所有过境时刻、仰角、斜距、多普勒样点全按别人的城市算，还能把这张错表写进他的电台，
界面一路报成功。**App 侧同一个 bug 1.1 就修过**（`Geo.StationStore` 用 NaN 表示未设，
`verify_layout.py` 还有一条"不许硬编码台站坐标"的检查），只是那条检查只管 App 那一端。
现在 PC 端同口径：默认空、未填时挡住并明说，参数报错也分成"没填"和"填错了"两种。

### 为打包必须改的两件事

- **路径分家**：配置/TLE 缓存/日志原来全写 `os.path.dirname(__file__)`。源码下没事，
  PyInstaller 单文件模式那是**每次随机命名、退出即删**的临时解包目录 —— 写进去等于每次开机失忆。
  拆成 `RES_DIR`（只读资源，走 `sys._MEIPASS`）与 `DATA_DIR`（可写，exe 模式落
  `%LOCALAPPDATA%\DopplerPass`）。源码运行两者仍是脚本目录，行为不变。
- **启动与崩溃落日志**：窗口程序起不来时屏幕上什么都不留，"双击没反应"分不清是没启动、崩了、
  还是被杀软拦。现在入口先写一行 `start … 打包=True · py=… · 数据目录=…`，再用 try 把 traceback
  落到同一个文件。**日志里没有 start 那行 = 进程从没起来过**，这是远程定位的唯一依据。

重打包命令、两个坑（`--add-data` 必须 Windows 绝对路径；本机沙箱里跑 exe 要把 `TMP` 指到工作区外）
写在 `PC工具/多普勒工具/发布-单文件exe.md`。

### 数字签名：查过，结论是不办

代码签名证书要企业营业执照做组织验证，个人基本办不到；微软从 2023 年起强制私钥放 FIPS 认证的
U 盾/云 HSM 里；而且**签了不治真正的病** —— 拦你的是火绒/360 的行为特征，不是微软的信任链，
PyInstaller 单文件"解包到临时目录再执行"这个动作天生高危。自签证书更糟（要对方装根证书）。
真要办只在"上软件站、给不懂技术的人用"那种规模下才值。

## 八、教训

1. **"补一个正确动作，会开出一个新入口。"** P1-2 加当场重载是对的，但它绕过了
   `DPH_Enter` 里"先 SaveRadio 再 LoadEntry"这个**只写在注释里的顺序约定**。
   约定不变成代码里的断言，就等着被下一个入口违反。
2. **接收侧和发射侧的闸门必须成对出现。** `DPH_Tune` 的范围校验存在了很久，pTX 那条路一个字没查 ——
   同一条坏表，收的时候安全，按 PTT 就出界。
3. **两端各自修过的 bug 只算修了一半。** 采样原点、硬编码台站都是"App 修了、PC 漏着"，
   症状是"同一件事两台机器结果不一样"，谁也复现不了，而且会长期被当成玄学。
4. **自检里一条 `or True`，比少一条检查更坏。** 它让"8 层无 FAIL"这句话在对应项上完全不带信息量，
   而读的人无从分辨。同理：`len({None}) == 1` 判"三端一致"。
5. **"发给别人跑不起来"不是环境问题，是产品没做完。** 查下去撞出的是默认台站写死别人城市 ——
   打包这个动作本身就是一次强制验收。
