# 多普勒 —— 项目说明

给 F4HWN SSTV 电台（v6.3.0 基座）加的一页「卫星多普勒跟踪」，外加一个配套的安卓 App 和一套 PC 工具。
作者 BG0FPJ。本文只介绍项目本身：是什么、由什么组成、数据怎么流、怎么编译运行。

---

## 一、这个项目解决什么问题

业余卫星是低轨的，过境只有几分钟，多普勒频移能让 FM 话音从清楚变成噪声。
传统做法是电脑开着软件，实时把频率喂给电台——电台必须连着电脑。

这个项目把这件事前置：**过境之前在 PC 上算好整趟的频率变化，写成一张表烧进电台的外部 flash**，
电台自己按表改频，全程不需要电脑，也不碰静噪和音频通路。

- 表区：`0x162000..0x172000`（64 KiB）
- 表格式：v5，串口协议 proto 7
- 播放：电台每 10 ms 一拍，按表算出的频率字写进 BK4819（收/发两侧都给）
- 旧表通用：重刷固件不必重写表

## 二、三块组成

| 组成 | 位置 | 语言/技术 | 干什么 |
|---|---|---|---|
| 固件 | `固件源码/uvk1-v6.3.0/` | C（ARM） | 电台里的程序：多普勒页、串口协议、按表改频 |
| PC 工具 | `PC工具/多普勒工具/` | Python | 算过境、生成表、写表、校验、回归测试 |
| 版面排版器 | `PC工具/App排版器/` | React 18 + TypeScript + Vite | 拖版面 → 导出 JSON → 同时落固件和 App |
| 安卓 App「多普勒 NG」 | 同级目录 `doppler-ng/`（不在本仓） | Kotlin + Jetpack Compose | 查卫星、看过境、生成并写表、SSTV、天图、地图、设置 |

固件入口是 `App/app/doppler.c` / `doppler.h`，路由在 `App/app/app.c` 搜 `DISPLAY_DOPPLER`，
串口协议在 `App/app/uart.c`；版面坐标表 `App/app/doppler_layout.h` 是脚本生成物。

安卓 App 的源码单独放 `<workspace>/doppler-ng/`：**路径必须是纯 ASCII**，
Gradle 的 test worker 在中文路径下会整包 `ClassNotFoundException`。
它的构建产物 `app/build`、测试素材 `sstv-fixtures` 都不入库。

## 四、数据怎么流

**频率表这条路：**

```
数据/sat_freq.json（频点）
        │  过境计算（SGP4）+ 多普勒频移
        ▼
PC工具/多普勒工具/doppler_tool.py  →  表（v5 格式，最大 64 KiB）
        │  USB 串口，proto 7
        ▼
电台外部 flash 0x162000..0x172000
        │  10 ms 一拍
        ▼
BK4819 频率字（收 / 发两路）
```

**版面这条路：**

```
PC工具/App排版器（128×56 画布，worst-case 实时告警）
        │  「复制 JSON」→ gen_layout.py
        ▼
固件 App/app/doppler_layout.h   +   App assets/layout/*.json
        │                              │
        │                              └─ Render.kt 按节点画 Text/Box/Slider/LazyColumn
        ▼
电台屏幕（128×56 像素，逐像素对应）
```

一套坐标，两头渲染：排版器里看到的，就是电台和手机上看到的。

## 五、常用命令

工作区根目录记为 `<workspace>`。

```bash
# 编固件 → 产物 .gobj/f4hwn.sstv.bin
cd 多普勒/固件源码/uvk1-v6.3.0 && PATH=<workspace>/tc/root/mingw64/bin:$PATH \
  PYTHONIOENCODING=utf-8 python .gfw.py

# 回归（离线六层；后三层要电台或模拟器）
cd 多普勒/PC工具/多普勒工具 && bash verify_all.sh --fast

# 假电台仿真（不需要硬件，不改固件源码）
bash 多普勒/tests/sim/build.sh all        # all = 两个静态守卫 + 全部场景
bash 多普勒/tests/sim/negctl.sh 9         # 阳性对照：删掉某条修复，看对应场景是否变红

# 版面：排版器导出 JSON → 同时落固件与编辑器
python 多普勒/PC工具/多普勒工具/gen_layout.py "<导出的.json>" "2026-11-02 01:09"
python 多普勒/PC工具/多普勒工具/verify_layout.py      # 排版器 ↔ 固件表逐条一致
python 多普勒/tests/sim/check_layout_overlap.py       # 像素级重叠/出屏/内容要求

# 打开排版器（画布 128×56，与真机逐像素对应）
多普勒/PC工具/多普勒工具/打开排版器.bat

# 打 exe → 产物复制成桌面 DopplerPass.exe
python -m PyInstaller --noconfirm --clean --distpath OUT/dist --workpath OUT/build \
  F4HWN-Doppler-Tool.spec

# 编安卓 App（Gradle 必须在 ASCII 路径下跑）
cd <workspace>/doppler-ng && ./build.bat          # 内部是 gradle --offline assembleDebug
# 装到手机：不要用 adb install（vivo 会弹确认页导致失败）
python <workspace>/doppler-ng/tools/deploy.py
```

## 七、几条容易踩的约定

- `doppler_layout.h` 是**生成物**，不要手改；改版面走排版器。
- 交付的 bin 每次重编 md5 都会变（镜像里编进了 `__DATE__`/`__TIME__`），
  **md5 不是源码指纹**；要认版本读 `0x0772` 回包（版本串 + ppm + proto + phase）。
- 编译绿 + 自检绿 ≠ 能用；注释说它做了 ≠ 代码真做了。
- 改动有未提交内容时，禁 `git checkout .` / `git restore .`。
- 安卓 App 的布局参数写死在一个 360×672 的"设计空间"里，由 `Render.kt` 等比映射到真机；
  页面内容区实际高度（约 644 dp）比设计高度小，所以贴底的节点必须写 `anchor` 含 `b`。
