## 1. 这段时间到底改了什么（只看这一节也能接手）

### 1.1 固件（`_src/uvk1-v6.3.0/App/app/doppler.c`，2924 → 3112 行；`doppler_layout.h` 62 → 64 行）

| 版本 | 改动要点 |
|---|---|
| v10rxonly | 新增 `DPH_EXT_RXONLY()` 宏，PTT 闸门 / `$V` / `$Y` 四处判据合一 |
| v10b | ExtPush 同步 `gRxVfo->pRX->Frequency`；`DPH_TriAuto` 认 `$V`；EXT 下 `$O` 显示手机多普勒；交还时不 `DPH_Tune(cur.freq10)` |
| v10c | 表错原因码 `dph_tbl_err` + `$@`（`NO TABLE`/`VER x ONLY`/`BAD HDR`/`BAD COUNT`/`NO DATA`）；`dur_s>7200` 拒收；`span_hz` 32 位；`FindNext` 兜底；LOCKED 期不画百分比；加 `$O Hz` 格 |
| v10d | 公共 switch 补 `case 'V'`；多普勒格 font0 / y33 |
| **v11** | **十倍频 P0**：11 处 `ext_*10 * 10u` 去掉；新增 `DPH_ExtFreq10()`（29–1300 MHz 校验）、`DPH_ExtStopTx()`；`ExtSessionReset` 清子页/编辑态；`FinishRun`/`Leave` 收尾；`ExtState` 补 0x02 |
| **v12** | `case 'F'` 删掉发射分支 —— 发射时上方主频率不再变成发射频率 |

**十倍频那条值得单独记住**：VFO 与 BK4819 REG_38/39 都是 **10 Hz 单位**（`frequencies.c:51 = 16255000`、`app.c:953 = 43300000` 为证），旧的 `*10u` 让 PLL 落在 1459.875 MHz。**屏幕全对、硬件全错**，没有任何报错，纯靠单位链推出来的。

## 3. 协议与数据格式（实测校正版）

`项目交接-2.md` §3/§4 的帧结构、掩码表、命令表、表格式都还准，这里只补三条**这次真机测出来、文档里原来没有**的事实：

1. **回包的 `crc` 字段恒为 `0xFFFF`** —— 固件根本不计算它。所以客户端不能拿"CRC 不符"当坏帧。
2. **尾部 `DC BA` 不参与掩码**，是明文；掩码只覆盖 `msg + crc`，索引从 0 起算。
3. **回包 msg 不补零**，长度可以是奇数（`0x076A` n=7、`0x0764` n=27、`0x076E` n=5 实测）；请求方向补到偶数是固件允许的。

回包体布局统一是 `cmd(2) + payloadLen(2) + payload`，**判断状态码要从 payload 起算**——
写完一块的 `0x0763`：payload = `addr(4) + size(2) + status(1)`，status 在 `body[10]`。
（App 以前按 `body[6]` 判，每块都"失败"，白跑三遍重试，写表 150 ms/块。）

## 4. 已验证的事实（照着这个报"能跑"）

真机 COM7、MuMu 模拟器、桥接 `7878`：

- 对时 `0x0766 → 0x0767` 成功；自检 `0x076A → 0x076B` 回 `proto 6 / state 0x04 / phase 1`。
- 擦 8 个扇区、写 372 块、回读表头校验 `DPT1` —— 整条离线链路走通。
- 写 2 趟：`16152 B / 8 扇区 / 10.0 s`（模拟器）；同样内容 PC 直连只要 **1.7 ms/块**。
- 回读校验：`DPT1 / ver 5 / count 2 / 145.80000 MHz / up 0 / pts 269 / step 2000 ms`，样点首值 `0x2035`(8245 Hz)。
- 接管控频：`0x0768 → 0x0769`、开页 `0x076E → 0x076F`、推帧 `0x076C → 0x076D` 每 ~200 ms、停止时关页 + 交还。

**没验过的**：手机 OTG 直连（模拟器测不了）；写表过程中掉线的恢复；长时间（>30 min）控频的稳定性。

## 5. 踩过的坑（下次别再踩）

| 坑 | 现象 | 真相 |
|---|---|---|
| `.cmd` 存成 UTF-8 | 满屏 `'ge.py" --port …' 不是内部或外部命令` | cmd.exe 按 GBK 解析批处理字节，中文变乱码后把命令行拆断。`.cmd`/`.vbs` 一律 **GBK** |
| Windows 上 `SO_REUSEADDR` | "有时能连、点对时又没反应" | 它允许**抢占**已被监听的端口，假电台和真桥接同时占 7878。服务端要用 `SO_EXCLUSIVEADDRUSE` |
| `adb reverse` 隧道 | 每条命令多 44 ms | 隧道是 adbd 转发的；`10.0.2.2` 直连也测了，同样 44 ms（ping 只有 0.37 ms）。真机 OTG 没这问题 |
| adb 起不来 | `cannot open %TEMP%\adb.log` | 必须先 `export TMP=... TEMP=...` 指向可写目录 |
| Kotlin `"%.6X".format(...)` | `IllegalFormatPrecisionException: 6`，写表整次中止 | `%X` **不接受精度**，要零填充写 `%06X` |
| `timeout /t 3` | 在 MSYS/Git Bash 环境下行为诡异 | PATH 里的 GNU `timeout` 抢先；批处理里用 `ping -n 4 127.0.0.1 >nul` |
| 布局随状态变化 | 自动化点击老点空 | 「录音中」横幅、阶段文字都会把下面的行往下推，脚本按坐标点就要重算 |
| `.gtmp` 里的 `dec.py` / `fakeradio.py` | 假电台抢 7878 | 测试脚本用完要 kill，否则真机连上也是"没响应" |
