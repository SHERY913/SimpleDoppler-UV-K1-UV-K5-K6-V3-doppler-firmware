## 3. 这一轮真正变了的三件事

1. **"我方意图"和"固件在听"分开了**。`CtrlState.armed`（我发了接管命令）≠
   `CtrlState.takeover`（固件回包 `State.bit0==1`）。屏幕上说"控频中"之前，
   固件已经认了；`KeepAlive` 靠 `armed` 活，不靠 `takeover`。
2. **数据真值优先**。表擦写有回读校验（`DPH_TBL_*` 状态码），频率表只有一个真源
   （`数据/sat_freq.json` → 三端生成），屏幕印的值等于芯片里的值（含平滑中间值）。
3. **手机端日志能当证据**。`PassLog` 落 `logs/pass-日期.log`，接管全过程可复盘。

## 附：写表真机闭环（2026-10-28 夜补充）

`PC工具/多普勒工具/` 新增两个只能在真机上跑的脚本，用来回答"写表到底进没进 flash"：

```bash
# 桥接必须先关掉（它占着 COM7）
python verify_table_live.py  --port COM7          # 读回整表 + 逐条校验 + 对真源
python verify_table_write.py --port COM7          # 擦→写→回读，整段 md5 比对
```

结果：20480 B 整段擦除重写后回读 md5 与写前一致；表头 `DPT1 ver=5 count=3`，
条目与 `数据/sat_freq.json` 的 ISS 频点（437.800 / 145.990 / 67.0 Hz）一致。

踩过的坑：`freq10` 的单位是 **10 Hz**（437.8 MHz → 43_780_000），按 Hz 换算会
误报"频点不符"；`verify_table_write.py` 会先把原表落盘成 `table_backup.bin` 再擦。
