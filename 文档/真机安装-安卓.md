# 给这台 vivo 手机装 APK —— 全流程与本机实测坐标

> 目标机：iQOO Neo3 `V1936A` / `2c611462` / Android 11 (SDK 30) / arm64 / **1080×2340 @480dpi**。
> 换机型下面所有坐标都要重量。
>
> 脚本：`doppler-ng/tools/deploy.py`。本文是它的说明书 + 出问题时的排查手册。

---

## 一、为什么不能简单 `adb install`

这台机器上 `adb install xxx.apk` 走不通，原因有四层，每层都能单独把人卡住：

1. **adb daemon 起不来。** 它要写 `%TEMP%\adb.log`，那个目录不给写就静默失败，
   `adb devices` 只回一个空列表，看起来像"手机没连"。
2. **Git Bash 改写路径。** `/data/local/tmp/x.apk` 会被转成
   `C:/Program Files/Git/data/local/tmp/x.apk`，报 `remote secure_mkdirs failed`。
3. **vivo 的安装确认页对注入触摸免疫。** 「继续安装」按钮用 `input tap` 点不动，
   连按下的水波纹都不出现 —— 事件在系统层就被丢了，不是没送到 App。
4. **这一页 `uiautomator dump` 返回空。** 常规的"找节点、取 bounds、点中心"套路失效，
   只能靠固定坐标 + 截图人工核对。

## 三、装之前先确认两件事

### 1. 屏幕得亮着

```bash
$ADB shell dumpsys power | grep mWakefulness
```

不是 `Awake` 就：

```bash
$ADB shell input keyevent 224          # KEYCODE_WAKEUP
$ADB shell input swipe 540 1800 540 800 200
```

**屏幕睡着时所有 `keyevent` 全部无效**，后面的键盘确认会静默失败。

### 2. 前台别被互传占着

```bash
$ADB shell dumpsys window | grep -oE "mCurrentFocus=Window\{[^}]*\}"
```

看到 `com.vivo.easyshare/com.vivo.easyshare.connectpc.ui.ConnectPcActivity`
就先退掉，否则安装页根本弹不出来：

```bash
$ADB shell input keyevent 3            # HOME
$ADB shell am force-stop com.vivo.easyshare
```

这一条踩过：操作员正拿互传连电脑，`pm install` 挂在那儿等一个永远不会出现的确认框。

## 四、装（四步）

### 第 1 步 push

```bash
$ADB push doppler-ng/app/build/outputs/apk/debug/app-debug.apk /data/local/tmp/dng.apk
```

### 第 2 步 起安装，放后台

```bash
# 关键：必须放后台。pm install 会一直挂到用户在手机上点确认。
$ADB shell pm install -r -t /data/local/tmp/dng.apk &
```

`-r` 覆盖安装、`-t` 允许 test-only 包。

**有概率它直接回 `Success`** —— 操作员关过 vivo 的「应用安全验证」，那就没有确认页，
可以直接跳到第 4 步验版本。

### 第 3 步 过 vivo 的确认页（只有需要时才做）

页面长这样：

```
┌──────────────────────────────┐
│ 多普勒 NG                     │
│ 大小 15.96 MB  版本 2.0.0-m4   │
│ 来自"未知来源"  |  权限        │  ← 「权限」是文字链接，别让焦点落到这
├──────────────────────────────┤
│ 安全守护提示您                 │
│ 外部来源应用                   │
├──────────────────────────────┤
│ 防范未经检测潜在风险            │
│ 超级守护         [开启]         │
├──────────────────────────────┤
│  ☐ 已了解应用的风险检测结果      │  ← (540, 1995)，这一行认 tap
├──────────────────────────────┤
│      [  继续安装  ]            │  ← 只认键盘
└──────────────────────────────┘
  继续安装第三方应用需身份验证…
```

#### 3a. 先等 14 秒

页面刚出现时显示「vivo 正为您云端检测风险…」，这期间点任何东西都是点空。
实测 10~14 秒。

#### 3b. 点复选框 —— 用坐标

```bash
$ADB shell input tap 540 1995
```

这一行的节点 bounds 是 `[249,1929][831,2061]`，中心就是 `(540,1995)`。
**这一行认 `input tap`**，能点动。

> 为什么不用 `uiautomator dump` 拿 bounds：这一页 dump 返回空串。
> 试过 `adb shell uiautomator dump /sdcard/u.xml` 再 `cat`，文件是空的。
> 所以这一页的坐标只能写死。

#### 3c. 点「继续安装」

**勾上复选框之后，按钮从灰变蓝，这时它认 `input tap`。**

```bash
$ADB shell input tap 540 2166      # 按钮中心，2026-11-05 实测生效
```

按钮 bounds 大约 `[145,2085][935,2250]`，中心 `(540,2166)`。

> 早前记的"这一页对注入触摸免疫"是误判：那时按钮还是 **disabled 灰底**态，
> tap 不启动安装是正常的。先勾复选框、等按钮变蓝，再 tap 就行。
> `deploy.py` 现在的顺序是 tap 复选框 → tap 按钮 → 失败才退键盘。

键盘兜底（tap 不生效时）：

```bash
$ADB shell input keyevent 20    # DPAD_DOWN
$ADB shell input keyevent 20    # DPAD_DOWN
$ADB shell input keyevent 20    # DPAD_DOWN
$ADB shell input keyevent 66    # ENTER
```

**为什么是三格：** 焦点初始在顶部 toolbar（`[18,84][1062,264]`）上，
第一格落到「权限」文字链接，第二格落到「超级守护·开启」，**第三格才是「继续安装」**。

**绝不能按两格。** 两格之后回车的落点是「权限」那个链接，会跳进
`PermissionInfoActivity`，安装会话当场作废，`pm install` 返回
`Failure [INSTALL_FAILED_ABORTED: User rejected permissions]`。这个坑我踩过两次。

试过的、**无效**的办法（别再试）：
- `input tap 540 2127`（按钮中心）—— 无反应
- `input swipe 540 2127 540 2127 180`（原地点长按）—— 无反应
- `input tap 540 2180`（按钮文字）—— 无反应

### 第 4 步 验（唯一的判据）

```bash
$ADB shell dumpsys package com.f4hwn.doppler2 | grep -E "versionName|lastUpdateTime"
```

- `versionName` 变成你刚编的版本号
- `lastUpdateTime` 比装之前新

**不能看「安装页消失了」** —— 用户取消时页面也会消失。
**也不能只看 `pm install` 的返回值** —— 确认被取消时它返回的是 `User rejected permissions`，
但有时候（用户手点得比脚本快）安装其实已经完成了。

## 六、顺手要会的一件事：点 Compose 界面

装完之后要操作 App。**Compose 界面用截图目测坐标经常差 100+ px** ——
因为状态一变整个布局会重排，你量的是上一帧的坐标。

正确做法是每次点击前重新 dump：

```bash
$ADB shell uiautomator dump /sdcard/u.xml
$ADB shell cat /sdcard/u.xml | tr '<' '\n<' | \
  grep -oE 'text="[^"]+"[^>]*bounds="[^"]+"' | \
  sed 's/.*text="\([^"]*\)".*bounds="\([^"]*\)".*/\1 | \2/'
```

输出：

```
连接 | [144,837][232,910]        ← 中心 (188, 873)
24h  | [587,1296][663,1369]
写入电台 | [144,1790][319,1863]
```

```bash
$ADB shell input tap 188 873
```

封装好的脚本：`doppler-ng/tools/ui_tap.py`，`--list` 列当前屏幕所有可点文字，
`ui_tap.py 连接` 直接按文字点。

App 内的正常控件（按钮、chip、复选框）都是认 `input tap` 的，只有系统安装页那个按钮例外。

## 七、几个反直觉的事实

| 现象 | 真相 |
|---|---|
| 「继续安装」点了没反应，连水波纹都没有 | vivo 在系统层丢弃注入的触摸事件，防自动点击 |
| 安装页 `uiautomator dump` 返回空 | 这一页 Activity 的节点树不导出 |
| `input swipe` 从屏幕左边缘起手会把 App 关掉 | 触发了 vivo 的侧边返回手势，拖滑条要从 x≥300 起手 |
| `Modifier.clickable(enabled = false)` 的按钮点不动 | Compose 会**摘掉整个手势节点**，不是"禁用了但还在"，排查时极易误判成事件没送到 App |
| 手机在充电但 `adb devices` 空 | daemon 写日志失败，跟数据线无关 |
| 装完重启 App，`pm install` 又拉起安装页 | 正常，vivo 每次都问 |

## 八、一条命令跑完全部

```bash
cd doppler-ng && python tools/deploy.py
```

它会依次做：唤醒 → 退互传 → push → 后台 `pm install` → 等 14 s →
点复选框 → 键盘三下一回车 → 验 `lastUpdateTime` → 打印版本号。

APK 默认取 `app/build/outputs/apk/debug/app-debug.apk`，用 `--apk` 换。

失败时按这个顺序排查：
1. 屏幕亮着吗（`mWakefulness`）
2. 前台是 `packageinstaller` 吗（`mCurrentFocus`）
3. `install.log` 里 `pm install` 说的什么
4. 直接 `taskkill /F /PID $(pgrep adb)` 重启 daemon 再来一遍
