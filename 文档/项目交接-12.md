## 3. 信号表读数偏低 —— 全部证据与结论（未结案）

### 3.1 现场实测（COM7，437.8 MHz，桥接先停掉，`硬件测试/hw_rssi_probe.py` + 20 Hz 采样）

| 量 | 值 |
|---|---|
| `REG_67` 裸值 | 98…105（p50 = 101，max 105，60 样本无尖峰） |
| 折算 | `(101/2) - 160 = -109.5 dBm` |
| `dBmCorrTable[BAND6]` | `-6` → 上屏 **-115.5 dBm**（与操作员看到的 -120 吻合） |
| `REG_7E` | `0x303E`（bit15=0，AGC 固定档，与原厂初始化常量一致） |
| `REG_13` | `0x03DF`（固定档 3 的增益档，按任一张表解都只有 -4…0 dB） |

也就是说：**检波器此刻真的只有 100**。要让屏幕印 -76，`REG_67` 必须是 168。

### 3.2 与原厂固件的逐字对照（`C:\Users\13766\Downloads\f4hwn.fusion.v6.3.0.bin`，107,688 B，md5 `bfdec45cb8b19ae2d4a5d8b1a6d47013`）

反汇编命令（binutils 在 `./tc/root/mingw64/bin/arm-none-eabi-objdump.exe`；
ReVa/Ghidra 的 `import-file` **拒收裸 .bin**，别浪费时间）：

```
arm-none-eabi-objdump.exe -D -b binary -m arm --disassembler-options=force-thumb f4hwn.fusion.v6.3.0.bin > fusion.dis
```

| 地址 | 原厂实现 | 结论 |
|---|---|---|
| `0x1a30` | `movs r0,#0x67` → SPI 读 → `lsls #23 / lsrs #23` | 读 REG_67，`& 0x1FF` |
| `0x1a3e` | `lsrs r0,#1` → `subs r0,#160` → `sxth` | **裸 dBm，不折 AGC 增益** |
| `0xd23c` | `ldrh r2,[vfo,#0x30]` → `ldrsb r5,[dBmCorrTable,r2]` → `adds r5,r5,r0` | **直接拿 Band 当索引，没有 `%7`** |
| `0xd250` | `dbm+93` 判 S9；`dbm+141` 判 0 格；`r4=9` | 只是 S 表分档，不参与 dBm 计算 |
| `0x1a0dc` | 表字节 `F1 F0 F6 FC F9 FA FF` | 与 `App/misc.c:153` 的 `dBmCorrTable` 完全一致 |
| `0x12bc` | `mvns r3,r0; lsrs #15` → `cmp enable` → bit15 = `1^enable` | **原厂"开 AGC"写的就是 bit15=0** |
| `0x12a0` | 字面量 `0x303E` | 原厂初始化 REG_7E 就是固定档 |

因此 `App/radio.c` 现在（`radio.c:110` 附近）就是：

```c
*out = RADIO_ClampDbm((int16_t)((raw / 2u) - 160 + dBmCorrTable[gRxVfo->Band] + dbm_off_db));
```

`dbm_off_db` 默认 0（见 3.4）。

### 3.3 已经排除的方向（别再重复走）

- ❌ 中位数 / 迟滞 / 峰值保持 / 换频静默：全部删掉了，不是它们的问题。

### 3.4 本轮新增的唯一一件东西：`0x0778` 标定偏移（已编译，未刷）

- 固件：`App/radio.c` 新增 `dbm_off_db` / `RADIO_SetSignalOffsetDb(int8_t)` /
  `RADIO_GetSignalOffsetDb()`；`App/uart.c` 新增 `case 0x0778`：载荷 1 字节有符号
  dB（钳 ±60），回包 `0x0779`，载荷 5 B = `Offset(int8) + Dbm10(int16 上屏值×10，0x7FFF=无读数) + Raw(uint16 REG_67)`。
- 构建：`93/93 ok`，`size 103248`。
- **它不改 flash 布局**：偏移不持久化，由上位机每次连上重发。
- 用法：刷入后 `python 多普勒/PC工具/多普勒工具/doppler_tool.py` 那条链路里发
  `0x0778`，把 `Dbm10` 调到与参考表一致即可，**不用再刷机**。
- App 侧还没接这个命令（`RadioLink.kt` 里加一个 `setSignalOffset(db)` 就能用）。

### 3.5 结案前必须回答的一个问题

**把原厂 `f4hwn.fusion.v6.3.0.bin` 刷进同一台手台，在同一频点、同一根线缆下，
它印多少？**

- 印 -115 ~ -120 → 我们的表就是原厂的表，那条 -76 的账不在固件里（频点/环境/另一台设备量的）。
- 印 -76 → 说明确实有一个寄存器级差异，下一步是**把两套固件的 128 个 BK4819 寄存器值全读出来逐个对**
  （IF 带宽、LNA、RSSI 采样点），那是唯一还能产生 40 dB 的地方。
