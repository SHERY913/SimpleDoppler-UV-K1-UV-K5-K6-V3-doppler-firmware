### 2. 时区单一真值

口径：**手动填写 > 系统时区**，两者都不用时按设备默认。三处必须同一个数：

| 处 | 文件 |
|---|---|
| 写进电台的表头 | `ui/layout/WriteSheet.kt:377` → `Tz.offsetMinutes()` |
| 对时推钟 | `link/RadioSession.kt:224` → `ZoneOffset.ofTotalSeconds(Tz.offsetMinutes(whenMs)*60)` |
| 屏上显示 | `ui/layout/Expr.kt` 的 `Times`（三个 `SimpleDateFormat` 加共享锁 + `appliedOffset` 缓存） |

`data/Tz.kt` 是唯一实现：`offsetMinutes(nowMs)` = 手动且 `tzHours ∈ [-12, 14]` → `round(h*60)`，否则 `TimeZone.getDefault().getOffset(nowMs)/60000`。
设置页在 `ui/layout/LayoutSettingsScreen.kt` 的「Time zone」节（Follow system / Manual + 小时输入 + `UTC±HH:MM` 回显）。

### 3. 跟踪页底部排版

**根因**：`LayoutDoc.kt:265` 的贴底规则只对「离设计底 ≤100」的根部节点自动改 `lb`。MuMu 页面区只有 626.7 设计单位，Stop sim/linkText/framesText 被上浮 45.3，而 Progress 行/进度条/微调行不在 100 内仍钉死 → 一半贴底一半不动，相互插进去。

**改法**（只动 `assets/layout/track.json`）：底部整块 10 个节点全部显式 `"anchor":"lb"` 当刚体；上面压缩 56 让出空间 —— 罗盘 280→220（x40→70、半径 140→110），hint 340→282，读数 5 行×2 列整体上移 56。

改后间隙（uiautomator bounds ÷3 实测）：读数末行→Progress 8.0 dp，其后依次 4.7 / 4.0 / 4.0 / 4.0 dp。
**边界**：贴底块上浮量 = 672 − 页面区高，真机（设计高 672）上进度区上方会空 54 dp；页面区低于 ~618 的机型仍会撞读数区。

## 六、环境坑（本轮新增）

- **`build.bat` 在 Bash 里**必须写 `cmd.exe /c "build.bat :app:assembleRelease"`，写 `cmd //c` 只会开交互 cmd、gradle 不跑。
- **`_shots/tmp/build.log` 会被别的会话占用**（`The process cannot access the file`），换文件名。
- **adb**：`TMP`/`TEMP` 必须 Windows 风格 `C:/…`；命令执行完管道不退出，放后台轮询；`timeout` 包 adb 会连带杀 daemon。
- **两台设备同时在**（USB 真机 + MuMu）时必须显式指定：`adb -s <serial>` 或 `export ANDROID_SERIAL=`，否则 `more than one device/emulator`。
- **无线 ADB** `192.168.0.7:37797` 今天连不上（`10061`），改用 USB `2c611462`；Android 11+ 端口每次重启都变，要用户现查。
- **`deploy.py`** 默认推 debug 包、不认 `--help`，必须 `--apk <release>`；流程 push → `pm install -r -t` → 等 14 s vivo 云检 → `input tap (540,1995)` / `(540,2166)` → 兜底键盘 `20 20 20 66`。
- **MuMu**：`adb connect 127.0.0.1:7555`，`install -r -g` 走 Streamed Install，无 vivo 云检。
- **截图坐标**：`input tap` 用实际 1080×1920；预览图 961×1708 要 ×1.124。
- **`doppler-ng` 的 git**：本轮首次实质提交（`4fe80be`，149 文件）。**动 git 前先 `git status`** —— 其它会话可能正在改。
