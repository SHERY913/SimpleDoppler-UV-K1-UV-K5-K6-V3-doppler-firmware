## 一、BUG-1：一张表跨 16 天以上，被静默折回第 0 天

条目里"表头之后第几天"是 `dph_entry_t.flags` 的低 **4 bit**（`0..15`）。
三端各自把它 `& 0x0F`（PC）/ `and 0x0F`（App）写完就走，**越界不报错**。

跑红的证据（构造 18 条跨 18 个本地日的表）：

```
[修复前] 构表 18 条，10,684 B；validate_table 报错 0 条，警告 0 条
   第 16 条  真实本地日 +15   flags=0x0f -> +15
   第 17 条  真实本地日 +16   flags=0x00 -> + 0  <-- 折回了
   第 18 条  真实本地日 +17   flags=0x01 -> + 1  <-- 折回了
```

后果：电台把 11-17 显示成 11-01（`$B`），到 AOS 的倒计时（`$R`）跟着错，
长按 M 的"定时开始"因为算出来是过去时间而直接放弃武装，**而屏幕不会说它放弃**。

改法（写表的一方拦，固件不动）：

- `doppler_core.py`：新增 `DPH_DAY_MAX = 15`，构表时算出 `day_idx`，
  `> 15` 与 `< 0`（队列倒序排）都抛人话错误；**`& 0x0F` 删掉**——有了闸门它就是掩耳。
- `PassCalc.kt`：新增 `DAY_MAX = 15`，同样两条拒绝。
- 固件**故意没加检查**：折回后的 `+0` 和合法的 `+0` 在 flash 里是同一串字节，
  电台读不出差别；加"日偏移必须单调不减"那种启发式会把合法的非时序表判死。
  这条口径写进 `doppler.h` 的 `flags` 注释里。
- `verify_table_fit.py` 加了两条用例（越界必须拒 / 边界 16 天必须还能写）。
  **这条一开始是错的**：它用 `core.DPH_DAY_MAX` 推导期望，我把常量改成 100 之后
  它照样绿——永绿的自证。现在钉死字面量 15/16/17，并且验证过能红：

```
[变异：DPH_DAY_MAX=100] ✗ PC 的 DPH_DAY_MAX = 100，而条目的日偏移只有 4 bit，最大 15
                        ✗ 跨 17 个本地日的表竟然通过
                        rc=1     → 改回 15 后 rc=0
```

顺带说明：GUI 单次计算本来就把天数封在 1~10，所以只有"加入待写"跨几次计算攒队列
才可能撞上——这正是把上限做成人话错误而不是崩溃的原因。

## 二、我核错的一条：三端常量的比对**是存在**的

我上一轮说"源码四处注释都写 verify_three_way.py 会当场比，而它没比，
所以 App 的常量没有任何自动校验"。前半句对，**后半句错**——我漏搜了
`verify_layout.py`（第 3 层，26 KB），它确实把 `DPH_PASS_MAX`/`BASE`/`REGION`
比到了 App 的 `.kt`。真实缺口比这个小，但仍然要修：

| 常量 | 修前 | 修后 |
|---|---|---|
| 样点区起点 `SAMPLE_OFF` | PC/App **都解析出来了却没比**（抓了不用） | 三端逐值比 |
| 采样下限 `STEP_MS_MIN` | 只有 .h ↔ PC（第 8 层） | 三端逐值比 |
| 单趟时长 `DUR_S_MAX` | 同上 | 三端逐值比 |
| 本地日 `DAY_MAX`（本轮新增） | 没有 | PC ↔ App 比 |
| 解锁令牌 `DPH_UNLOCK_TOKEN` | **早就在比**（第 8 层 `verify_table_fit.py:554`） | 不动，只把注释指对的脚本 |

`SAMPLE_OFF` 这条抓了没比是有代价的：手机上那个 APK 1.5 还写 `0x3000`，
固件早就改成 `0x1000`（`git show 12ace21` 里 `SAMPLE_OFF = 0x3000`），
第 22 轮新加的 `data_off` 自洽检查一上机就会把手机写的表整张判 `BAD LAYOUT`。
现在这条能红了——把 App 改回历史的 `0x3000`：

```
✗ 样点区起点（条目区的物理边界） 三端不一致：固件 4096; PC 4096; App 12288    rc=1
✓ 改回后  = 4096（3 端一致）                                                  rc=0
```

注释指向（`doppler.h` 两处、`doppler_core.py`、`PassCalc.kt` 两处、使用说明一处）
都改成真正干这活的脚本名。

## 四、新功能：四相位状态机

这台机器的键矩阵是 5×4（`0-9 / MENU / ▲ / ▼ / EXIT / ★ / # / PTT / SIDE1 / SIDE2`），
**整个固件里没有编码器驱动，也没有左右键**。所以"转旋钮调频""按左右键"
落到真实存在的键上（你选的方案）：▲▼ 按相位复用。

```
READY ──M──▶ PRE-LISTEN ──M──▶ TRACKING ──数组跑完──▶ POST-LISTEN ──EXIT──▶ 退出并还原
  │              │                  │                      │
  └ EXIT 退出    └ EXIT 退出         └ EXIT 进尾音          └ ▲▼微调 / 1 换亚音 / PTT
```

| 位置 | 改了什么 |
|---|---|
| `doppler.c` 相位枚举 | `DPH_PRE=6`、`DPH_POST=7`，**只能往末尾追加**：`0x076A` 回包第 6 字节就是这个数（`DPH_PhaseGet`），插中间等于改了 `EMPTY/EXT` 的编号，症状是手机把"没表"当成"手机推数据"。`probe_fw.PHASE` 与 `radio_proto` 的口径同步加了 6/7 |
| 新变量 `hold_off` | 这一页**真正停在**的偏移（Hz，带符号）。预听=`样点[0]`（AOS 那一刻，你选的方案），尾音=`样点[pts-1]`（LOS），▲▼ 在它上面 ±100 Hz。`$O`、`$F`、PTT 的上行补偿、松手回拉**四路都读它**，不留第二份 |
| `DPH_PreListen()` | 开静噪+喇叭（走 `DPH_AudioOpen`，不新写一份）、停在 AOS 偏移、**不动 `t0_10ms`**（预听期间拧的频率不该把时间轴一起带走） |
| `DPH_FinishRun()` | 表路径不再 `DPH_AudioRestore()`+`DONE`+3 秒自动退页，改叫 `DPH_PostListen()`。**这条就是这一版要修的行为**：LOS 一到静噪关回去、喇叭断开、信道还给操作员，而尾巴恰恰在那之后。手机接管（`ext_ctrl`）那条路保持原样 |
| 退出清理 | 只有 `DPH_Leave` 一处还原（VFO 指针、收发频点、两个 VFO 各自的亚音、静噪电平与门限、喇叭、背光、键盘锁）。这套固件没有动态内存，"定时器"是 tick 差值比较，`phase=OFF` 就是停 |
| 相位补全 | 抢屏回归、背光保持、`ReloadTable` 不换 `cur`、手机接管切页的四张相位清单都加上 PRE/POST —— 漏一处的症状分别是"到点不跟踪""背光灭""半途跳到另一颗星""接管了退不回自己的页面" |
| 定时开始 | 由一跳变两跳：T-60 s 进**预听**（原样开静噪/三声提示），AOS 进**跟踪**。`auto_armed` 在两跳之间保持真，所以"F-P1-6 定时期间别抢页作废整趟"那条修复照旧成立 |

**关于"防抖"**：抖动在 `driver/keyboard.c` 的扫描计数器里吃掉，`app.c` 只在
按下沿与连发两种事件上调进来，`DOPPLER_ProcessKeys` 开头还有一道
`if (!bKeyPressed) return;`。所以状态机里每收到一次调用就是一个明确动作，
**没有再加第二层自己的计时器**——加了只会让连发手感变成"时快时慢"。
需要按住的重复用固件已有的 ▲▼ 快重复档。

## 五、按 1 换亚音 / ▲▼ 挪进度

- **按 1**：`DPH_CycleTone()`，在那 50 颗标准 CTCSS 里往后走，走完回 OFF。
  写入只走 `DPH_SetTone` 这一个入口（`0x0774` 也是它），**不回写 `cur.ctcss10`**：
  表里那颗才是这一趟的初始值，换星/重写表/关机都回到它，手动那颗只在本次停留期间有效。
  没借到信道（空表页）时拒绝并双响，避免直接改掉操作员存着的信道。
- **跟踪中 ▲▼**：`DPH_StepKey` 挪 `t0_10ms` ±1 s（100 tick）。**挪的是时间原点，
  不是频率**——偏移仍按数组在那个时刻查，所以进度条、剩余时间、`$O` 一起跟着跳，
  不会出现"屏和芯片各挪各的"。下限不越过 t=0，上限留最后一格（不会一按就跳尾音页）。
- **预听/尾音 ▲▼**：±100 Hz（`DPH_TUNE_STEP10`）。为什么不跟信道步进
  （`gRxVfo->StepFrequency`）：主界面最小也是 2.5 kHz，而折射尾巴上残余信号
  距 LOS 频点通常几百 Hz，一脚踏过头。100 Hz 是 10 Hz 栅格的整数倍，
  落进芯片不带半格量化误差。钳位 ±50 kHz，出 band 就整个不动（数字和芯片一起停）。
- 两处在发射中不碰 PLL：`DPH_StepKey` 里 `gCurrentFunction == FUNCTION_TRANSMIT`
  时只更新数字；松手那一下由 PTT 的 release 分支把芯片拉回 `hold_off`。
  **这条不加就是新 bug**：PRE/POST 没有 RUN 那种"每拍重算一次 DPH_Tune"的兜底，
  松手不拉就永远停在发射频率上，而操作员正在等的尾巴恰恰收不到。
- 子页面（校时/校准/信息，`sub != 0`）里 ▲▼ 不调频不改进度——那几个页面
  正在用方向键干别的，背后拧芯片是另一种两张皮。

版面新增两张（page 7/8）：横幅用 6×7 粗体，因为**横幅用大字放不下**——大字那一档
一格 13 px，`PRE-LISTEN` 要 130 px 超过 128，会被砍成 `PRE-LISTE`，而且它吃两个
frame row 正好压在下面的频率上（"大字只有数字字形"那句是我核错了，夜间复审的
更正见 §十；过境页的 big 走 `gFontBigPacked`，字母是全的）；"大字"给了频率本身
（`$F` 走 big）。
尾音页一开始排了 `EL $E`，查了 `DPH_Expand` 才发现非 RUN 相位 `$E` 回的是
`cur.max_el`（那页会把"当前仰角"显示成最高仰角），换成 `MAX $M` 说真话。
