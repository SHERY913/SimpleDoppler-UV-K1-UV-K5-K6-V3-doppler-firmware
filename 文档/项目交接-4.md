## 一、这是什么

给 Quansheng UV-K1/K5 手台加卫星多普勒追踪。三个组成部分：

| 件 | 语言 | 位置 | 作用 |
|---|---|---|---|
| 固件 | C / ARM Cortex-M0+ | `多普勒/固件源码/uvk1-v6.3.0/` | 存过境表、按时间自己算偏移、按表调频 |
| 安卓 App | Kotlin + Compose | `多普勒/安卓App/android-app/` | 算过境、写表、实时接管控频 |
| PC 工具 | Python | `多普勒/PC工具/多普勒工具/` | 串口桥接、烧写、解算校验、调试 |

固件基于 F4HWN Fusion v6.3.0 + SSTV 分支，多普勒功能是后来加的，入口在 `App/app/doppler.c`（约 3400 行）。

## 四、烧写与联调

### 烧固件

PC 工具 → 选 COM 口 → 烧 `多普勒/交付/f4hwn.sstv.doppler.bin`。
或 `多普勒工具` 里的烧写脚本。烧完手台会重启，屏幕回到主界面。

### 联调（模拟器没有 USB 直通）

MuMu 12 用的是 Android 15 x86_64 容器，**没有 USB host 透传**，`dumpsys usb` 里 `num_connects=0`，App 的「USB 连接」在模拟器里永远拿不到设备。走 TCP：

```bash
# 1. 桥接：COM 口 → TCP 7878
cd 多普勒/PC工具/多普勒工具
python -u serial_bridge.py --port COM7 --listen 7878 --log

# 2. 端口转发进模拟器
"C:/Program Files/Netease/MuMu/nx_main/adb.exe" connect 127.0.0.1:16384
"C:/Program Files/Netease/MuMu/nx_main/adb.exe" -s 127.0.0.1:16384 reverse tcp:7878 tcp:7878

# 3. App 设置页点「网络桥」
```

两个 bat 已经放在 `多普勒工具/`：`启动桥接.bat`、`一键连接.bat`。

**adbd 会同时挂两个设备**（`127.0.0.1:16384` 和 `emulator-5554`），所有 adb 命令都要带 `-s 127.0.0.1:16384`，否则报 `more than one device/emulator`。

桥接细节：
- `serve()` 用 `SO_EXCLUSIVEADDRUSE`，端口被别的程序占着会直接失败，不会静默半死。
- `Port` 类自愈：串口掉线后自动重开，每 20 次尝试扫描 VID `36B7` 或描述含「USB 串行」的口。
- 手台识别：VID 0x36B7 / PID 0xFFFF / 描述「USB 串行设备 (COMx)」/ 38400 8N1。

## 五、协议速查

帧格式：

```
AB CD  len_lo len_hi  body[len]  crc_lo crc_hi  DC BA
```

- `body` 与 `crc` 逐字节 XOR `Obfuscation[i % 16]`，表为
  `16 6C 14 E6 2E 91 0D 40 21 35 D5 40 13 03 E9 80`
- 尾部 `DC BA` 是明文
- CRC16-CCITT，多项式 0x1021，初值 0

命令（`App/app/uart.c`）：

| ID | 方向 | 说明 | 回包 |
|---|---|---|---|
| 0x0760 | 写 | 擦扇区（Size=4，地址） | 0x0761，9 B |
| 0x0762 | 写 | 写 128 B 块（Size=6+len） | 0x0763，11 B |
| 0x0764 | 写 | 读块（Size=6） | 0x0765，11+len |
| 0x0766 | 写 | 对时（**Size 必须 = 8**） | 0x0767，9 B |
| 0x0768 | 写 | 接管开关（0/1） | 0x0769 |
| 0x076A | 写 | 自检 | 0x076B，7 B（proto/state/phase） |
| 0x076C | 写 | App 推帧（绝对频率 + 显示数据） | 0x076D |
| 0x076E | 写 | 过境页开关 | 0x076F |
| 0x0601/0x0602 | 写 | 读写 BK4819 寄存器 | 0x0601 |

`state` 位图（0x076B / 0x076D 的 b[5]）：
`0x01` 接管 · `0x02` 过境中 · `0x04` 有表 · `0x08` 武装 · `0x10` 过境页 · `0x20` PTT · `0x40` 发射中 · `0x80` 刷写中

表格式（v5）：16 B 表头（magic `DPT1` + 版本 + 条数 + 日期 + CRC）+ 40 B 条目 × N + 样点区。
条目 40 B，样点 6 B（offset int16 / el u8 / range_km u16 / rate int8）。

## 六、架构上必须知道的几件事

### 1. 两套逻辑

| | 第一套 | 第二套 |
|---|---|---|
| 触发 | 手台 M 键进过境页（`DPH_Start`） | App 点「手机接管频率」（0x0768=1） |
| 谁算多普勒 | 固件自己按表插值 | App 算好绝对频率，5 Hz 推帧 |
| 显示 | 固件用 `$F/$Y/$E/...` 布局渲染 | 同一套页，但 EXT 分支优先 |
| 退出 | EXIT 逐级退 | 0x0768=0 |

两套共用同一个 Tick 状态机（`DOPPLER_Tick10ms`），用 `ext_ctrl` 区分。

### 2. VFO 隔离（血的教训）

`gRxVfo` / `gTxVfo` / `gCurrentVfo` 是**全局指针，指向 `gEeprom.VfoInfo[]` 主信道结构体本身**。多普勒要改频率，早期版本直接改这三个指针指向的对象 —— 结果退出时操作员的主信道被永久改掉。

现在的做法（照抄 `App/app/beam.c` 的模式）：

- `DPH_SaveRadio()` 把 `*gRxVfo` **值拷贝**到私有 `dph_vfo`，并按 `FrequencyReverse` 重新指向副本自己的 `freq_config_RX/TX`（不重指的话 `pRX` 还指着原件），然后三个全局指针都指向 `&dph_vfo`。
- 所有频率写入走 `DPH_RxStore()` / `DPH_TxStore()`：`radio_saved` 为真就写副本，为假才写原件。
- `DPH_GuardVfo()` 每 10 ms 检查一次，发现被 `RADIO_SelectVfos()` / 双守 / 全守抢回去了就抢回来（发射中只抢指针、不重写芯片，否则会推偏上行）。
- `DPH_AudioRestore()` 恢复频率、亚音、静音、`last_freq`，然后把指针还原。

`app.c` 里三处闸门（`#ifdef ENABLE_FEAT_F4HWN_DOPPLER`）：省电 `HandlePowerSave()` 早退、全守 `FullWatchPromoteCurrentBackground()` 跳过、双守 `DualwatchAlternate()` 跳过。

### 3. 频率算术

`saved_vfo` 里的频率单位是 **10 Hz**（145.8 MHz = 14580000）。
多普勒偏移用 `int32` Hz 算，写回时要 `/10`。
**`off / 10u` 这种写法是灾难**：`off` 是负的（靠近时约 -2825），`10u` 无符号，C 把 `off` 提成 unsigned，除法结果变成 4 亿多，加进频率就是「4714.76447 MHz」。现在统一走 `DPH_Hz2Ten()` / `DPH_Rx10WithOff()` / `DPH_Tx10WithOff()`，全在 `doppler.c` 前部。

### 4. 看门狗

App 断了以后固件必须自己归位：
- 5 秒（`DPH_EXT_TIMEOUT_TICKS` 语义已变，现在只有 5 秒这一个入口）没收到推帧：发射中就 `DPH_ExtStopTx()`，否则 `DOPPLER_SetExtControl(false)` + 双响。
- 重连后 App 会先发一次 0x0768=0 清残留（`clearStaleExt()`）。

## 七、本轮（2026-10-27）改了什么

### 固件 10 处

1. `doppler.c` 校准 ppm 用 int64 —— 原 int32 乘法在 2147 秒以上溢出，存进 flash 的 ±20000 ppm 是乱值。
2. `DPH_EditClock` 先判 `edit_len == 10` 再读缓冲 —— 原来读残留数字，日期静默错。
3. `DPH_EditClock` 按月校验天数（2 月按闰年）—— 原来 02/31 被日期表顺延成 3 月 3 日。
4. `DPH_BaseDays` 兜底 —— 空 flash 读回全 1，年份算成 127（2050 年）；现在不在 2015–2064 就按 2000-01-01。
5. 新增 `DPH_Freq10Ok()`，`DPH_Tune` / `DPH_RxShow` / `DPH_TxApply` / `DPH_ExtTxApply` 四个入口统一 29–1300 MHz 校验。
6. 新增 `DPH_TxStore()` / `DPH_TxCfgs()`，四处写发射频点（`DPH_TxApply`、`DPH_ExtTxApply`、`DPH_SetTone`、`DPH_LoadEntry`、ExtPush）全走隔离规则。
7. `DPH_LoadEntry` 改读临时结构，校验通过才覆盖 `cur`；失败时 `sel` 回退 —— 原来失败会把当前条目清成全 0，屏幕显示 `0.00000`。
8. `$S` 在接管期间显示手机推来的星名 —— `ext_name` 之前解析完从没被读。
9. 删掉 15 秒看门狗死代码 —— 5 秒那段每拍先清状态，1500 tick 的条件恒假。
10. `uart.c` 0x0601/0x0602 加帧长校验 + 寄存器地址限制 0x00–0x7F。

### App 6 处

1. 电台页「算过境→写表」改为先写样点、最后写表头 —— 原来从表头一次写整表，中途断线留半截表。
2. USB 权限 PendingIntent 改 `FLAG_MUTABLE` —— `IMMUTABLE` 在 Android 12+ 拿不到 `EXTRA_PERMISSION_GRANTED`，首次连接必报「权限被拒绝」。
3. `releaseControl()` join 400 → 3200 ms —— 交还帧排队发不出去，电台冻在最后频点。
4. `fwBitsLine()` 先验回包长度 —— 短帧越界，异常被吞成空串。
5. `pushExt()` 的 `dist` 钳到 0–65535 —— 负数按 u16 读成 65000+ km。
6. `Recorder`：线程没真退出就不清引用，`start()` 前等旧线程 —— 原来下次录音抢不到麦克风。

## 八、已知问题 / 技术债

**还没改的**

- `MainScreen.kt` 里 3 秒轮询调 `tryReconnect()` 在主线程，坏线时会周期性卡 UI。
- `MainScreen.kt` 每 10 拍在 Main 协程里跑 55 次 SGP4 propagate，应该挪到 `Dispatchers.Default`。
- IO 线程里直接写 Compose 状态（`liveInfo` / `linkLost` / `liveTune` / `page` / `prog`）。
- `uart.c` 回包的 CRC 字段填的是 `Obfuscation[...] ^ 0xFF`，不是真 CRC。App 不校验回包 CRC，所以不影响功能，但字段名是骗人的。
- `DPH_PhaseGet()` 的注释说返回位图，实际返回枚举（`DPH_OFF/READY/RUN/DONE/EMPTY/EXT`）。真正的位图在 `DOPPLER_ExtState()`。App 只把它当数字打印，未按位解析。
- `doppler.c` 3400 行，画页 / 按键状态机 / ExtPush 三块仍是补丁摞补丁，要大改需要单独一轮。

**踩过的坑（别再踩）**

- 手台 USB CDC 在发射瞬间可能掉线（电源跌落），桥接和 App 都要能自愈。App 侧判死阈值已放宽到 12 帧。
- 编译固件不设 `TMP` 会报 `Cannot create temporary file in C:\Users\...\Temp\: Permission denied`。
- `.gfw.py` 的 shebang 在第 2 行（首行是 `import io`），只能 `python .gfw.py` 调用。
- 手台屏幕布局由 `doppler_layout.h` 的表驱动，改字符位置改这个文件，别去动 `DPH_Expand` 的逻辑。
