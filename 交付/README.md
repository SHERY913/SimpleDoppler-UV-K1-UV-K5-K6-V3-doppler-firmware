# 交付物指纹

APK 和 bin 都是**可再生产物**，不是源码真相。要看现在整体是什么样、下一步做什么，读
`文档/项目交接-37.md`（唯一交接文件）。

**md5 不能当源码指纹**：信息页把 `__DATE__`/`__TIME__` 编进了镜像，
同一份源码每重编译一次 bin 的字节就不同。同理，APK 的字节也会因构建缓存、
签名时间戳而变 —— 下表 md5 只说明"这一份构建产物"，不是"这套源码"。
要认源码，读固件自己的 `0x0772`（版本串 + ppm + proto + phase），或看文件头注释。

## 命名规则

**交付根目录只放不带日期的正式名**：`f4hwn.sstv.doppler.bin` / `F4HWN-Doppler.apk`。
这两个文件永远指向"当前该刷/该装的那一份"，名字不随构建变。

旧版本进 `历史-YYYYMMDD/`，文件名带 `-日期-HHMM-<md5 前 8 位>`，只用于回滚与对照。
**不要当现状用。**（2026-11-07 整理时历史目录已清空，只剩当前这一份。）

## 外部 flash：过境表只是租客，不是房东

那颗 PY25Q16 有 2 MB，里面住着**1 个主系统 + 4 个多系统**（`0x020000..0x0C0000`，
每个 128 KiB）、5 个配置 bank、multiboot 状态标记、48 个 overlay app 槽、
原厂的 A-law 语音包，以及白头佬汉化包的 40 个 app + 字库。

三片实测镜像摆在一起，这批"租客"的位置才看清楚（图见 `文档/外部flash地图对照.png`）：

| 区段 | 原厂（`全满.bin`） | 白头佬汉化包 |
| --- | --- | --- |
| `0x020000..0x0C0000` | 5 个固件槽全满 | 5 个固件槽全满 |
| `0x0C0000..0x100000` | bank1..4 留空 | 同 |
| `0x102000..0x151A5C` | **语音包前 316 KiB** | 40 个 FAP1 应用（结束于 `0x151A5C`，槽 0..39） |
| `0x151A5C..0x162000` | 语音包 | 汉化应用尾 + app 槽 40..47 的声明区（空的） |
| **`0x162000..0x172000`** | **语音包中段 64 KiB**（熵 7.89，无文件头） | **空：0 / 65,536 个非 FF 字节** |
| `0x172000..0x180000` | 语音包 | **空：0 / 57,344 个非 FF 字节** |
| `0x180000..0x1D6300` | 空 | 大字体 16×16 + 小字体 8×8 + 拼音检索表 |
| `0x1D7000..0x1DE000` | 空 | 空 |
| `0x1DE000..0x200000` | Sonic 4K 互操作保留区 | 同 |

**表区落在 `0x162000..0x172000`，64 KiB、16 个扇区。** 选它是因为按汉化包算，
这是 `0x102000..0x180000` 那 384 KiB 里唯一一段没人要的空地：

- 下沿 `0x162000` 正好是 48 个 app 槽声明区的末尾（`0x102000 + 48 × 8 KiB`），
  不多不少——再多 4 KiB 就把第 48 槽吃掉，编译期就 `_Static_assert` 不过。
- 上沿 `0x172000` 到汉化字库 `0x180000` 留 **57,344 B** 缓冲（汉化镜像实测 0 个非 FF
  字节），字库以后要扩也撞不到。
- 容量分两层，**不再有一个"最坏情况"反推出来的固定趟数**：
  1. **条目区**（结构性）：条目从 `+16` 起、样点从 `+0x1000` 起，中间 4,080 B。
     `DPH_PASS_MAX = 102`，`16 + 102×40 = 4,096 = DPH_SAMPLE_OFF`，正好填满。
  2. **字节数**（按真实表算）：每趟 40 B 条目 + 点数×6 B 样点。10 s 栅格一趟
     946 B、5 s 一趟 1,846 B（1,500 s 满长）——差一倍。PC/App 构表时用
     `table_used()/fit_keep()` 算实际占用，装不下就让操作员去掉最后几趟；
     固件按实际 `count` 与每条样点范围独立校验。
  实测（ISS，20 天窗口）：10 s 档 102 趟只占 39,256 B（60%），5 s 档 95 趟
  占 65,310 B（99.7%）—— 同一片 64 KiB，趟数按密度浮动，不再被 30 砍一半。

**代价必须说清**：原厂镜像里这 64 KiB 是 A-law 语音包的中段（整段
`0x102000..0x196510`）。所以第一次在有语音的机器上写表，归属闸门会判它
「不是我们的数据」并**拒绝擦除** —— 这是设计。放行的唯一正路是 `0x0776`
一次性解锁：PC 工具写表按钮左边勾「允许清空被占的表区」，或
`clear_table.py COM7 --yes`（两者都会先发 `0x0776`，令牌 `DPU1` 小端 = `0x31555044`，
借 64 次擦除额度，额度掉电清零）。`verify_table_fit.py` 里这条写成
「已知取舍」的断言，不是漏检。语音包本身：

- 原始连续 `0x102000..0x196510` = **607,504 B ≈ 75.9 s @8 kHz**（紧接 `FMP3` 标记，
  起点不是以前记的 `0x11C000`——那是 13 个 app 盖住头部之后看到的假起点）。
- 本机 20:25 的转储里那块地是一张真表（`DPT1`，8 条 ISS，`step=1000ms`，整表 41.0 KiB，
  样点末端 `0x16C3E6`）——即旧表实际啃掉 41 KiB，不是 64 KiB；`0x16D000..0x16F000` 与
  `0x172000..0x174000` 是被擦空的。

原来表区声明在 `0x162000`、长 **496 KiB**（`DPH_REGION_SIZE 0x7C000`），一路压到 `0x1FF000`，
而且擦除范围是从"表区大小"推导的，还带 `max(sectors, 8)`——所以那不是"写坏"而是"**擦坏**"，
扇区擦除不可恢复。现在三端统一收成 64 KiB（16 扇区），`erase_plan` 永远只擦
`0x162000..0x171FFF`，**写之前逐个扇区认主**：全 FF → 放行；自己的 `DPT1` → 放行；
别人的东西 → 立刻返回 `DPH_TBL_OCCUPIED`，一个字节都不动
（除非本次已用 `0x0776` 借过额度）。

四道防线，前两条是编译期的：

1. 固件 `doppler.c` 的 `_Static_assert`：`DPH_BASE_ADDR >= APP_SLOT_BASE(APP_SLOT_COUNT)`
   （不得压进 app 槽）、表区末尾 `<= DPH_CN_ASSET_BASE`（不得撞汉化字库）
   且 `<= MB_SONIC_RESERVE_BASE`（不得撞 Sonic 保留区）、容量不等式、三条扇区对齐、
   `DPH_SAMPLE_OFF` 必须落在表头之后 —— **槽数、字库、容量任何一个变了，是编译不过，不是悄悄踩**。
2. `mb_flash.h` 一条：配置 bank 不得长到盖住 multiboot 状态标记（**5 个系统已是满配**）。
3. PC 端写表流程在 `validate_table` 之后、对时之前插入「归属探测」：512 B 一帧读满
   整个表区，逐扇区判 BLANK / OURS / FOREIGN，非空即中止并给人话理由
   （「表区被人占着，已中止」）；勾了「允许清空被占的表区」才发 `0x0776` 借额度。
   App 端 `tableRegionOccupied()` 做同一件事，读表头 16 B + 其余扇区各探两处 128 B。
4. `verify_layout.py` 三端比数字（表区起始 / 容量=擦除上限 / 102 条上限 /
   样点区起点 / 采样下限 5 s / 单趟时长 1500 s / 本地日偏移 15 天 / 表区末尾），
   `verify_table_fit.py` 离线验精度、容量、闸门与真镜像归属。
   **它现在也测「放行」**：表区 16 个扇区逐个过一遍 `guard()`，必须全过。
   以前只测拦截不测放行，于是 `FLASH_VOICE_PACK` 盖住表区、写表按钮全线静默失效，
   九层回归照样全绿。

**校准记录仍在 `0x1FF000`（保留区内），没有搬** —— 搬它会让已校准的电台丢值。

## 装机顺序

1. 刷 `f4hwn.sstv.doppler.bin`（用官方升级工具或本目录的 PC 工具，**擦写期间不能断电**）。
2. 装 `F4HWN-Doppler.apk`（Android 8+；13+ 首次启动会要通知权限）。
3. App 里：设置 → 连接（USB 或网络桥 7878）→ 设台站经纬度 → 卫星页选星 → 「手机接管」。

安卓真机装包的完整坑（亮屏解锁、通知栏收、vivo 确认页、`am force-stop com.vivo.easyshare`）
见 `文档/真机安装-安卓.md`。

## 已知未验（照实说）

- **固件 17 条修复里只有 E1~E4 上过真机**，E6~E9 与 D5 至今没点过。
- 固件编译绿 + 42 条仿真断言 + 15 条阳性对照 **都没有上过真手台**。
- 写表全流程（整表写入 + 整表回读比对）没在真机上跑完整过 —— 会擦手台 flash 同区域，要人守着。
- 写表后**当场重载**与**掉电重启后**表还在不在：这一轮给重载补了信道保护（页面没开着时
  只刷新"有没有表"，不装条目），所以「写完表屏幕没变」不再一定是 bug，得先确认当时在不在多普勒页上。
- 校准 ppm 能存住了（CRC 的 14→12 字节），但"存进去 → 断电 → 还在"要真机走一遍。
- 罗盘手举实测没做（气泡抖动、EMA 0.35、2° 判据都只有操作员能判断）。
- 过境中真实录音质量，需要真实过境 + 人耳判断。
- TLE 有两个源已经陈旧（脚本会告警），需定期 `refresh_tle.py`。
