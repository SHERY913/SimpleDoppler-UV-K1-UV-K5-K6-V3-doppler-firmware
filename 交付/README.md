## APK 不能按字节复现，别拿 md5 判"同代"

10-27 16:42 那份是 `62525358258067c5bb816ef9ad6425a1` / 15,783,147 B，被 17:0x 这次重建
取代（只改了"断链 15 s"这句文案和三处注释）。两包大小差 20 万字节，但 zip 条目级比对
结果是：**140 个条目一个不多一个不少，assets 逐字节相同，只有 3 个 `classes*.dex`
内容不同，而未压缩总量只差 1104 字节** —— 差别是 D8 把那个 9.1 MB 的 dex 从 `classes4`
挪到了 `classes5`（分包编号换了位置），压缩后大小因此抖动。

结论：判"交付包等于源码同代"要用**条目 + CRC**，md5 只能用来确认"是不是同一个文件"。
固件的 `.bin` 没这个问题，所以它是逐字节比对的（见下）。

## 19:42 链路自愈（App 0.2，bin 未变，仍是 4e3996e）

交接文档待办 1 的两件事落地，根因是**它们长在一个全工程没有调用点的页面里**
（`RadioPage()`，曾 `MainScreen.kt:1736`）：掉线自动重连循环、USB 插入自动连、

同轮还修了三处同源问题：`describe()` 用 `lastMode` 决定整段文案（网络桥失败一次后

`default-workspace/_tmp_verify/fake_radio.py`（按 `radio_proto.py` 的帧规则回包）：

第 3 次，上次尝试在 几秒前」（「断开」灰掉、连接按钮恢复）→ 桥重新起来 12~16 s 内

这轮真机测试逼出两个新问题，都已修（`安卓App` HEAD `45d37be`）：

1. **空闲探针会插进写表流程**。探针每 ~9 s 发一条 `0x076A`，而写表 35 秒里有几百条
   ask；探针那 9 字节回包落在两条 ask 中间时，会被下一条 ask 的 1 ms `drain()` 漏掉、
   再被当成 128 B 写块的回包读走 —— 正是"写到一半随机失败"的样子。修法：
   `RadioLink.lastAskAt` 记每条命令收发的结束时刻，`probeAlive()` 在"3 秒内还有人说话"
   时直接返回 true 不动手；`MainScreen` 的探针分支再加 `!TableWriter.busy`。
2. **历史文案和实时状态同屏打架**。`fwInfoLine()` 原来把接管/PTT/发射一起报，
   这句话现在是"带时间戳的历史"，于是出现过「固件应答 … 未接管（43 秒前）」紧挨着
   实时那行「固件 接管」。修法：`fwInfoLine()` 只报"这一版固件长什么样"
   （proto / 表已加载 / phase），动态状态只由 `stateLine()` 说。

**注意交付包大小**：增量构建出来的 dex 分包会抖（同一份源码 15,803,287 ↔ 16,027,751），
所以交付包一律从 `gradle clean assembleDebug` 取，别拿手边那次增量产物覆盖。

## 21:3x 那一轮：抄回来的两条

这轮只做用户点名的"值得抄的都抄了"，两边各一条，都是**协议级或链路上**的东西：

| 抄自 | 抄了什么 | 落在哪 | 证据级别 |
|---|---|---|---|
| Look4Sat `RadioTrackingService.kt:244/214-216/218` | 手调检测：读回频率与自己刚写的比，偏差即视为人在拧，按读回值重设基准 | 固件新命令 `0x0770`→`0x0771`（`uart.c`）+ `RadioLink.readVfo10()` + 控制循环里的 `trim10` | 编译通过；老固件上验证过"不支持时静默跳过" |
| 星来 `doppler.c:556-601` | 断帧时用两帧斜率外推顶上（闸门更严：≤2 s、跨度 [100,5000] ms、|Δ|>100 kHz 判换星） | `doppler.c` `DOPPLER_Tick10ms()`，节流 100 ms | 编译通过 |

**为什么手调检测要改固件**：App 只有"写"，没有"读"就没有判断依据。这里没有走
"往 `0x076B` 里加字段"的路——那条回包的 `expect=7` 写在老 App 里，加长会让老 App 判
"回包长度不合理"，而版本号又只在同一条回包里，对不上时没有退路。单开一条命令是唯一
能兼容三代的形状。

**没验到的**：这两条都要新固件才生效（`0x0770` 只有这版有），而新固件还没刷进电台。
老固件上 `readVfo10()` 拿不到回包→返回 null→静默跳过，控制循环行为与 0.3 一致
（真机跑过 20 s 接管，没有误报"检测到手动调频"）。

固件这两处的"该看什么"：刷完新 bin 后接管，拧一下旋钮，App 应弹
「检测到手动调频 +N Hz · 已按读回值重设基准」；然后手机端锁屏 2 s 再解锁，
频率不该在断帧期间掉回旧值（外推在顶）。
