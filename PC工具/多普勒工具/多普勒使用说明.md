# 卫星多普勒跟踪（SSTV 版固件）使用说明

一句话：电脑算好卫星过境时"频率该怎么变"，把一张表塞进对讲机；对讲机按 F+0 打开跟踪页，按 M 开始，它自己跟着卫星跑频率，声音从喇叭/耳机插孔出来，手机录音。

---

## 0. 先搞清楚为什么需要这个

卫星飞过来时，你和它之间的相对速度从 +7 km/s 变到 −7 km/s（ISS 级别），
145.800 MHz 上的接收频率会从 **+3.6 kHz 一路滑到 −3.6 kHz**，一共 7 kHz 跨度。

FM 解调本身不在乎这点偏移，但：

- 信号滑到中频滤波器边缘 → 声音失真、噪声变大；
- 滑出静噪门限 → 声音直接被掐断（这就是"录到一半没声了"的主因）。

所以真正要做的不是"改音调"，是**把这个 7 kHz 的滑动抵消掉，让信号始终停在中频正中间**。
本固件每 10 ms 检查一次该补多少，直接改收发芯片（BK4819）的频率字，全程不碰静噪、
不碰音频通路 —— 所以**跟踪过程中没有咔声、没有断音**。

## 1. 刷固件

### 1.1 已经编好的 bin（直接用这个）

`f4hwn.sstv.fusion.bin` —— **94,904 字节**，md5 `4216a05fa37935f8d3d2cb3d8b7c3daf`（上限 120,832，余 25,928）。

> **这一版把表格格式换成了 v4（条目 40 字节 + 每点 6 字节），刷完必须重新点一次「写入电台」**，
> 旧表会被固件判为版本不符，屏幕显示 `NO PASS TABLE`。

- **这一版是 Fusion 底座 + 多普勒页，主动裁掉了一批跟收图无关的功能**（省出 26 KB 余量）。
  多普勒页里另外有：时钟 / 定时开始 / 晶振校准 / 发射（上行补偿 + 亚音 + 6 键换功率）。

  **保留了**：多系统、CHIRP 写频（USB/UART）、宽频接收、基础扫描、手电筒、
  键盘锁、双守、各类亚音编解码、开机自检、电池管理、`BK4819` 寄存器实时读写（0x0601/0x0602）。

  **这一版没有的**（实测省下的字节）：
  频谱扫描 8,788 / FM 收音机 5,508 / 收发日志界面 4,284 / 快速扫描 2,148 /
  扫描进度条 2,004 / 扫描信号格 672 / 扫描亚音 504 / VOX 声控 868 / 信号条 580 /
  K5Viewer 2,000+。
  > 这些功能在**别的系统槽**里刷官方 Fusion 就能用 —— 内部 Flash 有 5 个槽，
  > 按住 MENU 开机可以切换，不用为了频谱在这台上将就。
- **用官方 ARM GCC 13.3.0 + 官方链接脚本 `Core/py32f071xb.ld` + 官方 nano newlib 编的**。
- 起始地址 `0x08002800`、栈顶 `0x20004000`，与官方 Fusion bin 布局一致，
  **用你平时刷 Fusion 的那套工具（k5tool / UVTools / 官方升级工具）直接刷**。
- **多系统**：`MULTIBOOT` + `HOT_CFG` + `OVERLAY` 全开（Fusion 本来就是开的）。
  按住 **MENU** 开机 → `F4HWN MULTIBOOT` 选择器；不按就正常开机。菜单里 `CFG M` 也是它。
- 万一刷进去不开机：断电，**按住 PTT 再开机**进原厂 bootloader，刷回官方 Fusion 即可
  （bootloader 在内部 Flash 最前 10 KB，刷固件不会碰到）。

> 说明：之前给过的几个包（现在改名为 `f4hwn.sstv.trim*.bin`）是**裁剪版**——砍了 60 多个功能宏，
> 体积只有 73~91 KB。既然你反馈 USB 连不上，而裁剪版和官方 Fusion 的唯一区别就是"砍掉的那些功能"，
> 所以这一版把砍掉的全还回去了，用官方 Fusion 的原始宏表重编。**如果这版还连不上，那就不是裁剪的问题。**

> 注意：`MULTIBOOT_OVERLAY` 必须开着，否则多系统里"刷回固件"那段代码（`MB_RamReflash`，888 字节）
> 会落到 `.data` 里，把 RAM 前 0x280 的保留区顶爆，链接脚本直接抛
> `RAM before the overlay exceeds the fixed 0x280 anchor`。

## 2. 把过境表写进对讲机

在对讲机屏幕根部没有时钟，所以它不自己算过境，只负责"照着表跑"。表由电脑生成。

### 2.1 准备

```bash
pip install sgp4 pyserial
```

TLE（卫星轨道根数）每天在变，**一定要用当天的**，去 celestrak 或 space-track 下载：

- ISS：<https://celestrak.org/NORAD/elements/gp.php?CATNR=25544&FORMAT=tle>
- 存成 `iss.txt`（两行 `1 ...` / `2 ...` 就行，前面带卫星名也可以）

### 2.2 上传

```bash
python doppler_upload.py --port COM5 --lat 31.23 --lon 121.47 --tle iss.txt --days 7
```

| 参数 | 含义 |
| --- | --- |
| `--port` | 串口，Windows 是 `COM5` 这种 |
| `--lat/--lon/--alt` | 你的经纬度（东经、北纬为正），`--alt` 是海拔米 |
| `--freq` | 中心频率 MHz，SSTV 默认 `145.800` |
| `--days` | 往下算几天（最多存 32 个过境） |
| `--min-el` | 最低仰角，默认 10°，低于这个角度基本收不到 |
| `--step` | 采样间隔秒，默认 2 s（越小越平滑，表越大） |
| `--tz` | 时区，默认 `8`（北京时间）。机器上显示的是**本地时间** |

先看看算出来对不对，不上传：

```bash
python doppler_upload.py --lat 31.23 --lon 121.47 --tle iss.txt --dry --save table.bin
```

会打印每个过境的 AOS/LOS（**本地时间**，手机对一下就行）和最大仰角，并生成 `table.bin`。
`D0`/`D1`/`D2` 表示这是今天/明天/后天的过境 —— 只算两天的话，同一个钟点会出现两次，
看 D 标记区分。

清空表：

```bash
python doppler_upload.py --port COM5 --clear
```

### 2.3 表格存在哪

对讲机外置 2 MB flash 的尾部 `0x162000` 起 64 KB，和固件槽、APP 槽完全不冲突。
（多系统固件槽占 `0x020000`~`0x0C0000`，覆盖式 APP 槽占 `0x102000`~`0x162000`，表正好接在后面。）
表头 16 B，最多 32 条过境（每条 28 B），样点从 `0x162800` 开始，每条过境约 300–640 个
`int16`（2 s 一点），32 条也就二十几 KB。

---

### 2.4 表格式 v5（2026-10 起）

表头 16 字节：`"DPT1" ver count hdr_size data_off reserved`。

每条 40 字节：`name[16] freq10 data_off up10 aos_min dur_s pts step_ms ctcss10 flags max_el`。
`up10` 是**上行频率**（10 Hz 单位，0 = 纯接收）、`ctcss10` 是上行亚音（0.1 Hz，670 = 67.0 Hz）。
工具会自动从 `sat_freq.py` 的 `UP` 表里带出来。

样点从 `data_off` 起，每点 **6 字节** `<hBHb>`：
`int16 多普勒偏移Hz + uint8 仰角 + uint16 斜距km + int8 径向速度(0.1km/s，负=接近)`。

- 条目上限 **256 条**，表区 0x162000–0x1FF000（约 630 KB），
  1 秒采样时一条 10 分钟过境约 3.6 KB，够放 170 多条。
- 写入时会**先按时间排序**再写，所以机器里翻 ▲▼ 就是时间顺序。
- **工具连上电台会自动对时**（新命令 `0x0766`），不用再手按六位数字。
- **旧表不兼容**（v1/v2/v3 全部拒收，屏幕显示 `NO PASS TABLE`），刷完新固件必须重写一次。

## 3. 机器上怎么操作

| 按键 | 作用 |
| --- | --- |
| **F + 0** | 打开多普勒页（原来这俩键是开 FM 收音机，本版已换掉） |
| ▲ / ▼ | 就绪页选择第几个过境 |
| M（短按） | 立即开始跟踪 |
| **M（长按）** | **按当前这条过境的 AOS 定时开始**（提前 60 秒自动打开静噪、预置频率，到点自动进入跟踪） |
| **9** | 设置时钟（输入 `HHMMSS` 六位数字，MENU 确认） |
| **8** | 校准晶振（见 3.1） |
| **6** | 切换发射功率：5W → 2.5W → 1W → 500mW → 250mW → 125mW → 20mW |
| PTT | 发射（只有表里带上行频率的卫星才有反应） |
| EXIT | 跟踪中 = 停止并还原频率；子页面 = 返回；就绪页 = 退出多普勒 |

### 3.1 时钟与晶振校准（为什么必须做）

芯片**没有 RTC**，时钟是用主晶振数出来的。这颗晶振出厂有 ±1.5% 左右的偏差，
换算到 145.8 MHz 就是 **±2000 Hz** 上下 —— 定时 30 分钟会偏 27 秒，
频率直接滑到滤波器边上。校准一次之后残差约 0.1%，30 分钟只差 2 秒 / 100 Hz。

**设时钟**：插上 USB、用配套工具写入一次表，**自动对时**（`0x0766` 命令）。
不想连电脑也可以手按：按 `9` → 输入六位 `HHMMSS`（例 `224107` = 22:41:07）→ MENU 确认。
时钟只存在内存里，关机后归零，所以每次开机想用「定时开始」都要重新设一次。

**校准**（一次就够，掉电不丢）：

1. 按 `8` 进校准页
2. 在整分钟（比如 22:00:00）按 **M** 开始内部计数
3. 等 10~30 分钟（越久越准）
4. 到点看手机/电波钟，**直接打六位真实时间**（如 `223000`），MENU 确认
5. 屏幕 `CAL 1.0062` 就是校准后系数，写在外置 flash 的 0x171000 独立扇区

### 3.2 定时开始怎么用

1. 先按 `9` 把时钟设准（否则倒计时无意义）
2. ▲▼ 选中要等的那条过境
3. **长按 M** —— 屏幕 `04:12` 那个位置变成到 AOS 的倒计时
4. 可以放下机器去干别的，**但要留在这一页**（背光亮着，退出本页会取消定时）
5. AOS 前 60 秒三声提示、前 10 秒再三声，然后自动开始跟踪

### 3.3 发射

表里带**上行频率**的卫星（ISS、AO-91、SO-50、FO-29、RS-44、AO-95、AO-85、AO-7、
AO-73、JO-97、XW-3、PO-101）才能发；表里 up=0 的星按 PTT 不会有反应。

- 接收时每 100 ms 修正一次**下行**
- 发射时每秒修正一次**上行**，方向和下行相反
  （`上行频偏 = −下行频偏 × 上行频率 ÷ 下行频率`），一次乘法就够，V/U 和 U/V 都对
- 发射时改得快会被对方听到「咔」，所以故意放慢到 1 秒一次
- 亚音（CTCSS）从表里读，直接写进发射参数；表里没写亚音就不发亚音
- **按 PTT 后屏幕会切到主界面**（这是原厂发射流程，会显示信道和功率），
  松开 PTT 约半秒后**自动回到多普勒页**，追踪不中断
- 想改发射功率：**直接按 6**，循环 5W → 2.5W → 1W → 500m → 250m → 125m → 20m；
  追踪页左下角一直显示当前功率
- 发射被原厂拒绝（比如电量低、忙锁）时，半秒后也会自动回到追踪页

三个页面（实际排版可在 `layout_editor.html` 里自己拖，导出 `doppler_layout.h` 后重编）：

**就绪页**

```
ISS (ZARYA)              1/17
      145.8000
EL 42   04:12   AOS 10:20     ← 中间是到 AOS 的倒计时
DUR 10:20    SW 6.5K
M  START                EXIT
                          22:41:07   ← 右下角时钟（没设就是 --:--:--）
```

**跟踪页**

```
      145.7976
                        -04:12   ← 剩余时间
 EL 42   -87dB   -2360
[██████████░░░░░░] 60%
5W                      22:41:07   ← 左下发射功率，右下时钟
```

**完成页**：`PASS COMPLETE` / `MAX EL` / `DUR` / `FREQ RESTORED`。

**设时钟页**（按 9）：`SET CLOCK` / 大字当前时间 / 一行 `------` 显示输入的数字 / `TYPE HHMMSS`。
**校准页**（按 8）：`CALIBRATE` / `ELAPSED 12:34` 已计时间 / `REAL ------` 输入的真实时间 / `CAL 1.0062` 当前系数 / `M START 8 END`。

进入时它会自动：静噪全开（SQL=0）、喇叭打开、背光常亮；退出或结束时全部还原
（包括发射频率和亚音）。

## 4. 录音

对讲机 3.5 mm 耳机口 → 手机录音（或录音笔）。手机端用 SSTV 解码 App
（Robot36 / SSTV Encoder / Black Cat 之类）直接录下来解码，或先存成 wav 事后解。

因为跟踪期间静噪是开着的，弱信号也不会被掐断，只有真的没信号才会有噪声。
AOS 前后各留 30 秒余量开始录，PD120 一张图 2 分钟，别急着停。

## 5. 出问题怎么办

| 现象 | 检查 |
| --- | --- |
| `NO DATA / LOAD TABLE VIA USB` | 表没写进去：重跑上传，加 `--verify` |
| 上传报 `erase FAILED` | 串口波特率/端口不对；确认刷的是 SSTV 版（带了 0x076x 命令） |
| AOS 时间和实际差很多 | TLE 太旧，换当天的；或 `--tz` 不是 8 |
| 跟踪了但没声音 | 静噪全开了还是没声，说明真没信号：换更高仰角的过境 |
| 声音有节奏性的"咔" | 补偿量跳变太大：把 `--step` 调小到 1 s 重传 |
| 偏移一直是 0 | 表里样点全 0：上传时用了错的 TLE 或频点参数 |
| SIG 一直是 `.....` + `-155 dBm` | 正常，说明当前频点没信号；有信号时格数会跳上去 |

2. **实机行为**。编译/链接/向量表/字符串我都验了，但"插上耳机有没有声音、频率跳得准不准"只能你上机看。
   F+0 进去先看就绪页时间对不对，按 M 之后拿另一台机器或 SDR 听 145.800 有没有在动。
3. **`ENABLE_UART_RW_BK_REGS`** 我在 `CMakePresets.json` 的 default 层改成了 true（radio 寄存器读写命令），
   这是上一版就改的，SSTV preset 继承它。

## 8. 这一轮代码审查修掉的问题（都在 `doppler.c`）

写完之后逐行复核，发现并改掉 5 个真问题，其中第 1 条会直接废掉整个功能：

1. **每 100 ms 关一次音频**。原来照抄频谱扫描的写法，换频前后把 `BK4819_REG_30` 写 0 再复原。
   那个寄存器 bit 9 是 **AF DAC 使能**，写 0 等于关掉喇叭输出几微秒 —— 扫频只看 RSSI 无所谓，
   可我们唯一要的就是音频，每 100 ms 掐一次会变成"哒哒哒"。现在只写频率字 `REG_38/39`，不碰 REG_30。
2. **信号强度格数是反的**。`BK4819_GetRSSI_dBm()` 返回 `-160…+95`，我原来先取绝对值再比阈值：
   满格信号（+95，即 RSSI 饱和）会被算成 2 格，空频道（-155）反而 5 格。改成直接对带符号的 dBm 比较。
3. **退出时静噪阈值取错频段**。还原顺序原来是"先配静噪、再改回频率"，而阈值表是按当前频率选
   频段（VHF/UHF 两张表）的 —— 你在 430 MHz 用，退出后会拿到 145 MHz 的阈值。现在先还原频率再配静噪。
4. **喇叭状态没还原**。进入时强制 `gEnableSpeaker = true`，退出没恢复，耳机模式下会被强行开外放。
5. **多普勒页的多过境分不清日期**。原来只显示 `HH:MM`，两天预报里同一个钟点会出现两次，
   选错了就是照着另一条曲线跑（频率反着走）。表里 `flags` 低 4 位现在存"第几天"，界面显示 `D0/D1`，
   时间也改成**本地时间**（脚本 `--tz`，默认 +8），不用再自己拿 UTC 换算。

`printf` 格式全部走工程自带的最小实现检查。
